# Agent 会话与引导设计

日期：2026-10-28。状态：会话与引导已实现，验证结果见文末。

目标：让用户知道 AI 能做什么、如何描述任务，并能围绕独立主题持续沟通。沿用现有左侧 AI 助手面板、画布输入入口和执行链路。

验收设计时应能回答四个问题：如何开始一个任务；如何续聊或切换主题；模型收到哪些上下文；执行范围与实际能力如何保证一致。

## 1. 设计依据与当前实现

截图可以确认 pen.dev 提供会话下拉、新建入口、设计示例，以及生成代码和添加上下文文件的说明。截图没有展示它的系统提示词、会话存储、上下文策略或任务并发机制，这些不能从界面推断。

本方案区分三种内容：面向用户的任务示例、面向用户的能力说明，以及面向模型的执行提示。前两种帮助用户发起任务，第三种保障任务执行质量。

## 2. 面板结构

推荐保持现有侧栏结构，不另建一个聊天工作台。界面继续称「AI 助手」，主题单位称「会话」；「新建会话」不会创建另一种 Agent 配置。

```text
AI 助手                                      关闭
[ 客户管理页面优化  ▾ ]                 [ ＋ 新建 ]
────────────────────────────────────────────────
空会话：简短引导 + 4 条任务示例 + 能力帮助
已有会话：用户请求 + 助手回复 + 执行与结果
────────────────────────────────────────────────
必要时：项目中有其他会话正在执行 → 查看任务
当前范围：客户管理 / 已选 Table
[ 附件 ] [ 描述需求或修改建议……                 ]
                                  [ 模型 ] [发送]
```

标题、会话栏与输入区不随消息滚动。中间空状态和消息历史共用一个 `Scrollbar`。下拉列表、长输入和展开详情也必须复用共享滚动组件，保持有界高度与 `min-height: 0`，避免嵌套原生滚动。

建议以现有面板宽度为基准验证，360–420px 作为主要设计范围；较窄时示例换行、会话标题截断并提供完整文本提示，不增加横向滚动。沿用 Studio 的字体、Antd token、明暗主题和 UI 语言包。

### 空状态文案

主文案：「描述你想创建或改进的页面」。

副文案：「可以描述需求，也可以添加需求文档或参考图。」

当前有页面时，展示这些示例中的 4 条，优先与上下文有关的内容：

| 场景 | 短标签 | 点击后填入的完整任务 |
| --- | --- | --- |
| 新建页面 | 创建客户管理页 | 新建一个客户管理页面，包含姓名、手机号和状态筛选，客户列表，以及新增和详情抽屉。使用项目现有组件。 |
| 页面优化 | 优化页面布局 | 优化当前页面的间距、对齐和信息层级，保留现有字段、数据绑定与业务交互。 |
| 完善交互 | 补齐筛选与分页 | 检查当前页面，补齐查询、重置和分页联动，查询条件变化时回到第一页。 |
| 表单编辑 | 添加表单校验 | 检查当前表单的字段和校验规则，补充明确需要的必填和格式校验，保留现有提交逻辑。 |
| 讨论方案 | 先分析再设计 | 先分析当前页面的信息结构，列出布局和交互改进建议，暂不修改页面。 |
| 参考设计 | 根据参考图设计 | 根据我添加的参考图设计当前页面，优先复用项目现有组件；先指出需要补充的信息。 |

行为规则：

- 示例只填入输入框，不自动执行；用户可以编辑后发送。已有草稿时换行追加，不丢弃原草稿与附件。
- 未开启页面生成时隐藏「新建页面」相关示例。没有当前页面时，只展示真实支持的入口，并解释需要先打开页面的操作。
- 未配置 AI 服务、无编辑权限和能力关闭分别显示对应状态，不展示一个点下去必然失败的主操作。
- 示例使用确定的、按场景维护的文案，不在每次打开面板时请求模型随机生成。

能力帮助以两段简短说明呈现，默认控制信息密度，展开后再看格式和限制：

**围绕当前设计工作**：「创建页面、优化布局、完善表单与交互，也可以先讨论方案。」按实际可用能力裁剪。

**添加上下文**：「通过 + 添加需求文档或参考图。支持 TXT、MD、PDF、PNG、JPG、WebP，最多 5 个，总计 10 MB。」PDF 和图片是否能被理解仍取决于服务模型，读取失败必须明确反馈。

不照搬截图里的 React、Tailwind、Next.js 或 HTML 导出介绍：目前内置 Agent 的工具链没有这些能力。拖拽和粘贴文件也不能仅凭现有附件选择器宣称支持；若实现相应交互，应验证后再增加提示。

第一条消息发出后移除欢迎内容，优先展示对话。使用中的能力帮助保留为输入区附近的低频入口。

## 3. 会话行为

首版采用「项目内共享、按分支隔离的主题会话」。项目成员沿用现有权限读取已发送内容；当前选中的会话、未发送草稿和滚动位置属于个人界面状态，不随其他成员切换。主分支的 `branchId = null` 也应作为明确的分支身份处理。

| 动作 | 规则 |
| --- | --- |
| 新建 | 进入本地空会话，默认名「新会话」；首次发送成功时创建服务端实体，避免产生大量空记录 |
| 命名 | 首条请求生成简短标题，首版用文本规则即可，不额外调用模型；允许手动重命名 |
| 切换 | 恢复该会话消息、草稿和滚动位置；不切换页面、不恢复旧设计、不停止其他会话里的任务 |
| 列表 | 当前项目、当前分支，按最近发起消息时间倒序；显示标题、最近消息摘要、时间与运行状态，流式增量不导致列表不断重排 |
| 归档 | 隐藏已完成主题，可从已归档列表恢复；运行中或需要核对保存结果的会话禁止归档；不提供首版永久删除 |
| 重开项目 | 恢复当前用户在该分支最后查看的会话；无可访问记录时进入空状态。已发送消息由服务端恢复 |
| 草稿 | 按用户、项目、分支、会话隔离，切换时保留；首版不承诺未发送附件跨设备或重启恢复 |
| 他人任务 | 显示作者；停止和任务操作沿用现有权限，不能因会话共享获得额外操作权 |

**会话和编辑范围是两个概念。** 同一会话可以讨论多个页面；每条请求发送时显示并绑定当前页面或画布，执行过程中保持该次绑定。查看历史不会把旧的编辑器 `sessionId` 当作有效执行身份。

从 A 页面切到 B 页面后继续发送，会在输入区明确显示「当前范围：B」。历史里 A 的 node UUID、选区和工具结果只能作为背景，必须在当前范围重新读取才能用于执行。「刚才那个表格」无法唯一定位时先澄清。切换分支则切换会话列表，禁止自动带入其他分支的对话。

项目内有运行任务或未确认的保存结果时，仍可新建空会话、浏览历史和编辑草稿，但不能发送其他任务。底部显示「『客户管理页面优化』正在执行」和「查看任务」入口；停止操作只出现在对应运行任务中。若任务已停止但仍需核对保存结果，提示会继续指向该会话，发送与归档都须等待核对完成。项目级执行状态由现有执行所有者维护，不能只看当前会话的可见消息判断是否忙碌。

撤销仍受当前编辑器会话与可用变更记录限制。跨会话也不能撤销一个会覆盖后续编辑的历史变更；禁用时说明原因，不承诺所有历史都可撤销。


### 画布底部输入与侧栏面板

底部输入是当前会话的紧凑入口，不强制创建新会话。它与侧栏共用同一项目执行器及当前会话，不各自维护聊天历史。

| 场景 | 行为 |
| --- | --- |
| 第一次进入 | 显示「新会话」，首次发送时原子创建主题和请求 |
| 收起面板 | 保留当前会话、文本、附件、模型和运行状态 |
| 点击底部会话名称 | 展开当前会话，不发送、不新建 |
| 点击底部下拉箭头 | 在输入框上方打开与侧栏相同的会话列表 |
| 点击「新建」 | 主动开始新主题，保留其他会话的草稿；空草稿不产生数据库记录 |
| 从底部发送 | 立即固定会话 ID、文本、附件、模型和编辑范围，直接提交一次，再展开面板；展开事件不携带延迟执行的请求 |
| 发送期间切换主题 | 返回的任务更新发送时的主题；只清理该主题已提交且未继续修改的草稿 |
| 切换页面 | 保留主题，范围标签显示当前页面／画布；每次请求重新绑定范围 |
| 切换分支 | 恢复该分支的个人会话选择和当前运行期间保留的草稿，不带入其他分支的历史 |
| 切到运行任务之外的会话 | 可以写草稿和浏览历史，发送暂不可用；通过「查看运行中的会话」回到任务，待核对的任务仍保留查看入口 |
| 附件在切换后才读完 | 仍写入原会话，保留读文件期间更新的文本，不影响新会话的附件或读取状态 |

### 会话列表

两个入口复用 `AiThreadPicker`。列表包含名称搜索、「未归档／已归档」切换、最近请求摘要、日期与运行／失败状态。未发送的本地草稿以文本或附件名作为摘要，帮助区分多个新主题。

每页 30 个主题；服务端按最近消息时间与 ID 排序。分页游标固定当页边界时间和 ID，某会话因续聊移动到顶部时不会改变下一页边界。搜索、归档和分页均在服务端执行，旧查询的延迟响应不能覆盖新查询。

每条已发送会话通过更多菜单重命名、归档或恢复。运行中或需要核对保存结果的会话禁止归档；项目查看者可读历史，写操作沿用项目编辑权限。列表由共享 `Scrollbar` 限高滚动，筛选与翻页操作位于滚动区外。

## 4. 真正的续聊上下文

模型按显式 `threadId` 选择历史。两个会话即使操作同一页面也不能混入彼此的需求。

每次请求的上下文装配顺序：

1. 当前用户明确请求及本次附件。
2. 当前会话已确认的目标、约束、用户纠正、待确认问题和已完成结果。
3. 当前会话最近的用户／助手消息；完整工具调用与结果保持成对，不能混入其他会话。
4. 当前实时页面／画布、选区、组件契约和编辑范围。
5. 当前任务需要的设计或交互规则。

以上是装配内容，指令层级仍由系统约束、用户要求与资料来源决定。历史回复、摘要、附件和工具输出不是新的高优先级命令；实时模型是当前设计事实的依据。用户最新纠正覆盖旧需求，但不能改写已经发生的执行记录。

长会话采用 12,000 字符的保守摘录预算，最多读取本会话先前 100 次请求；最近 6 次保留较长摘录，更早内容使用较短摘录。每条保留来源 run ID、用户要求、助手回复和撤销事实，并明确标记是否省略了更早内容。助手建议不会自动变成已确认决策；被省略的信息是必要条件时应澄清。这里不承诺无限记忆，也没有将全文重复发送给模型。

历史附件保留可追溯引用；本次没有添加新附件时，加载同一会话最近一次提供的附件组。本次提供新附件时使用本次附件，在当前上下文中不能声称看过未加载的其他附件。历史保存的 UUID 需要实时确认，历史截图不能当作当前视觉证据。

## 5. Agent 执行提示完善

提示按会话、讨论、编辑、新建页规则与输出阶段组合，直接使用注册工具的真实 schema，不另建组件契约或泛化插件框架。

| 层 | 内容 | 维护方式 |
| --- | --- | --- |
| 基础行为 | 助手角色、用户语言、真实性、资料与指令边界、简短沟通 | 所有任务共用 |
| 会话上下文 | 最新要求、历史事实、已确认约束、附件引用、待解决问题 | 服务端按会话装配，作为带来源的上下文数据 |
| 意图与权限 | 讨论、修改、新建页的可用工具与范围 | 工作流和服务端强制校验，提示词说明其语义 |
| 编辑规则 | 组件契约、状态与事件、初始业务状态、节点身份、选择揭示、撤销与保存 | 复用当前已验证规则 |
| 任务指导 | 布局优化、表单、列表、新建页等当前相关内容 | 只加载任务需要的规则；不复制整套 MCP 文档 |
| 结果表达 | 变更、已验证证据、待确认事项与真实限制 | 继续区分执行阶段与最终回复阶段 |

### 需要补齐的规则

**讨论意图**：用户说「先分析」「给方案」「暂不修改」时，进入只读讨论路径，不创建页面、不修改节点、不生成保存或撤销记录。意图分为 discuss/edit/page，讨论路径在服务端限制为 `read`、`queryElements`、`getEditorContext` 等只读能力；不能只靠一条「不要修改」提示。讨论结束后用户明确要求执行，再按当次实时范围发起修改请求。高歧义请求优先讨论，不自动创建页面。

**设计质量**：先识别用户目标、页面类型、信息优先级和关键操作；在组件契约正确的基础上处理对齐、间距、密度、主次动作、可读性、空状态和反馈。修改已有页面时保留现有业务字段与交互，避免无关重做。后台原型遵守现有模板、AppShell 和注册组件规则，不能用提示丰富为由添加装饰性标题或介绍。

**语言与命名**：中文业务页面和目录名称遵守用户要求；内部树节点使用 English PascalCase。注册 props、slots、事件签名及组件帮助保留其英文契约，UI 语言切换不改变保存内容。新建意图携带用户可见 Page 名和路由，业务目录名称与内部节点名分别遵循各自语言规则。

**能力如实展示**：布局修改、表单交互、页面生成必须与真实工具及权限一致。目前工作流有模型结构检查与保存，没有内置视觉／交互验收工具；不能宣称已在 Preview 中验证，也不能通过扩写提示词获得导出代码、发布或外部 API 连接能力。

**最终回复**：报告实际完成的结果；只有讨论时给出方案和必要问题；修改后说明真实验证与未验证部分。示例：「已补齐状态筛选与分页联动，并保存。模型结构检查通过；视觉布局与交互尚未验证。」不得输出虚构的检查项、保存结果或推理过程。

## 6. 实现结构

### 数据与接口

- 增加 `ai_thread`：`id`、`projectId`、`branchId`、`title`、`createdBy`、`createdAt`、`lastMessageAt`、`archivedAt`。
- `ai_run` 增加非空 `threadId`，每个 run 只属于一个 thread；消息、附件、工具和变更仍归 run，避免重复存储。
- 现有 `ai_conversation` 的项目级 seq／锁语义与主题会话分开看待；保留项目级事件序列和执行互斥，不把 seq 重置成每会话一套。
- 列表、历史分页、发送、重命名、归档和恢复按项目与 thread 校验权限；发送还要校验分支。运行快照、停止、附件读取也验证 run 的归属。幂等请求重放必须匹配原 thread，不把别的会话请求返回到当前会话。
- 新会话首发时，在同一事务内创建 thread 和 run。首版不做跨项目会话、多个 Agent 人格或多人同时修改设计。
- 数据库迁移将已有历史按项目和分支收拢为默认历史会话，保留请求、消息、附件与执行记录，不猜测原本不存在的主题边界。

### 客户端与工作流

- 继续由 Top Frame 和 `LocalEditSession` 持有执行权。增加项目级 thread 列表、当前 thread、按 thread 的消息快照与草稿；左侧面板和画布输入同步同一当前会话。
- 扩展 `AiSessionView`、snapshot/action bridge，传递会话切换、分页、草稿和状态。不能只改 `CopilotChatDialog`。
- 项目事件游标继续接收所有会话事件，再路由到对应 thread 的视图缓存；不可先过滤非当前会话事件再推进连续游标。
- 切换时用请求所属 thread 和请求代次处理返回，避免慢历史响应覆盖当前会话。后台运行事件更新对应会话状态，不向当前消息列表插入另一会话的内容。
- 服务器按 `threadId` 构造上下文，取代同页最近 3 次请求；客户端筛选不能成为上下文隔离措施。
- discuss 使用只读执行路径与讨论结果，不进入变更、结构验收和保存收尾；edit/page 继续沿用已有验证和保存链路。
