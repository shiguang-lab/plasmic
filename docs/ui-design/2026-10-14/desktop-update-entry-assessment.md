# 桌面客户端更新入口与提示评估

日期：2026 年 10 月 14 日。状态：Dashboard 已确认；CMS 已接入同一左侧更新控件并更新本地 App，等待效果反馈；Studio 已拆为左侧工具栏下方独立入口并更新本地 App，等待效果反馈；其余页面待逐页实现。

桌面更新是应用级能力，应在管理页面和带工具栏的预览页面提供可发现的入口，并在纯业务预览中保持画面干净。后台检查和下载不依赖页面。Dashboard、CMS 和 Studio 已使用明确的挂载点；Studio 位于左侧工具栏下方，普通预览等页面尚未覆盖。后续修复需要同时处理入口、状态提示、打断策略和重启前保存保护。

本评估以当前仓库源码为依据。页面布局与更新流程已做静态核对；各操作系统、实际安装包、窗口切换及全屏行为仍需在修复阶段实机验收。路由定义中的旧入口只作为覆盖检查项，不代表它们当前均有独立页面。

## 当前实现

### 更新流程和全局入口

- 支持自动更新的正式安装包启动时检查更新，之后每 10 分钟检查一次；下载中、已下载和安装中不会按该定时条件再次检查。
- 发现更新后由 `UpdateManager` 自动开始下载。底层 updater 的 `autoDownload = false` 是为了由 manager 控制下载，不表示产品关闭了自动下载。
- 下载完成后主窗口收到打开更新对话框的事件；用户点击安装才执行重启安装。没有退出时自动安装。
- macOS 的应用菜单提供「Plasmic → 检查更新……」；其他平台的菜单提供「Updates → 检查更新……」。该入口不依赖 Dashboard 或编辑器布局。
- 自动更新受安装形式限制：manager 仅在 `app.isPackaged` 且 Linux 满足 AppImage 条件时启用。开发环境的禁用状态不能当成入口故障。

依据：[更新管理器](../../../desktop/src/update-manager.cjs)、[更新初始化与 IPC](../../../desktop/src/updates.cjs)、[原生菜单和窗口创建](../../../desktop/src/main.cjs)。

### 页面内控件和对话框

`update-ui.js` 优先寻找应用提供的 `data-desktop-update-slot="header"`，Dashboard 与 CMS 共用该挂载点和顶栏样式；Studio 的 `EditorToolRail` 在工具栏外下方提供同一显式挂载点，使用紧凑图标和上方气泡，旧 footer 规则保留。找不到时移除控件。控件只在 available、downloading、downloaded、installing 阶段显示；idle、checking、current、disabled 均隐藏。主动检查通过原生菜单进行。

Dashboard 的 `DefaultLayout` 与 CMS 的 `CmsTopBarChrome` 已在品牌旁提供明确挂载点。普通预览使用 `PreviewTopBar`，在右侧操作胶囊外侧前方提供明确挂载点。

更新对话框与页面状态控件相互独立。主窗口即使没有状态控件，仍可通过原生菜单打开对话框，也仍可能在下载完成时自动弹出对话框。因此「页面没有按钮」不等于「没有检查、没有下载、没有任何提示」。

依据：[页面控件](../../../desktop/src/update-ui.js)、[对话框触发](../../../desktop/src/update-dialog.cjs)、[对话框界面](../../../desktop/src/update-dialog.js)、[Dashboard 布局](../../../platform/wab/src/wab/client/components/dashboard/DefaultLayout.tsx)、[CMS 顶栏](../../../platform/wab/src/wab/client/components/cms/CmsTopBar.tsx)、[预览布局](../../../platform/wab/src/wab/client/components/live/Preview.tsx)。

## 各页面的具体位置和视觉层级

以下是本轮建议采用的布局。方括号表示可见控件，省略号只代表既有内容。新增控件都属于桌面应用，不出现在普通浏览器版 Studio。示意是布局顺序，不表示已经实现。

### Dashboard 和组织管理

已确认采用左侧位置。更新控件位于 Plasmic 品牌胶囊外侧右边，与品牌间隔 12px、垂直居中。它与品牌同属左侧应用区域，右侧项目导航、新建组织和用户头像保持业务操作分组。

```text
[Plasmic 品牌胶囊] 12px [应用更新] …… [项目／个人项目／组织] [新建组织] [头像]
```

没有更新时，控件隐藏，品牌后不留下额外空隙。发现更新后显示 32×32px 下载图标，下载时可显示百分比，下载完成后显示蓝色下载图标。高度保持 32px，宽度上限 112px；窗口宽度不超过 1200px 时收为图标，百分比与版本进入气泡和详情。

气泡位于图标下方，间隔 8px。按气泡实际宽度居中，靠近视口边缘时向内收；小箭头始终指向图标。悬停和键盘聚焦均展示已本地化的真实更新状态说明，窗口尺寸变化时重新定位。点击就绪图标打开统一更新详情，不直接重启。

### CMS 全部子页

CMS 沿用已确认的 Dashboard 左侧位置，使用同一个应用顶栏更新挂载契约。品牌和更新控件属于同一应用身份区域，数据库名称位于其后。内容、修订、模型、设置和加载状态都使用 `CmsTopBarChrome`，不分别新增更新逻辑。

```text
应用顶栏：[Plasmic 品牌胶囊] 12px [应用更新] | [数据库名称，可编辑] …… [内容／模型／设置]
内容详情：                  [条目名称] …… [保存／发布等内容操作]
```

数据库名称以紧凑文字显示，和品牌区域用细分隔线分开；宽度最多 280px，长名称省略并在悬停时显示完整名称，保留直接编辑。名称组件显式撑满该容器，使编辑输入框使用同一宽度，避免内容自适应与百分比宽度导致收缩。编辑焦点边框和光圈使用主题 colorPrimary 与 colorPrimaryBg，和当前紫色主题一致。内容／模型／设置放在同一顶栏右侧，用中性色分段导航表示当前页面；下方不重复显示导航。加载态和内容、模型、设置子页使用相同结构。

无更新时控件和间距隐藏；更新可用、下载中、下载完成和安装中才显示。尺寸、下载图标、下方气泡、箭头与视口边界处理均复用 Dashboard。Windows 保留当前窗口按钮预留区域，更新按钮为 no-drag，不加入 Content／Schema／Settings 导航或内容保存区。

CMS 设置沿用 Dashboard 的标题层级、间距和主题样式，不使用卡片外框。配置采用三个平面分组，以间距和细分隔线区分，内部使用单个共享 Scrollbar，顶栏保持固定。内容依次为数据库信息、API 访问凭据、语言区域。私密令牌默认隐藏，查看和复制在凭据旁；整页“设置”标题右侧放复制 CMS 结构和保存按钮。保存通过同一个表单实例提交语言区域配置，保留空值与重复校验；复制说明位于按钮提示中。数据库结构复制沿用现有接口，说明不复制内容条目。

CMS 模型列表和内容条目列表侧栏共用 48px 标题区、内边距和分隔线；模型结构页与内容页的模型侧栏使用同一结构。筛选和内容搜索均使用 Ant Design Input.Search，新增按钮使用相同尺寸的标准 Button，加载态保持同样布局。模型列表保持独立共享 Scrollbar，筛选框固定在列表之外。模型结构与条目编辑内容靠左，保留 24px 内边距及可读宽度上限。相关布局测试和构建、打包、签名检查通过，运行构建哈希与产物一致；本地 App 中两页实际位置已核对，内容页两个侧栏的标题分隔线和搜索框对齐；模型页搜索背景没有叠层，筛选和 Escape 清空正常，未修改业务数据。侧栏一致性调整通过 8 项相关测试、构建、打包和签名校验，运行构建哈希与产物一致。

本阶段只接入更新状态和详情入口，CMS 业务数据及保存流程保持现有行为。跨页面安装前保存保护仍属于 U04 后续问题，不能把本阶段完成理解为该风险已经解决。

### Studio 编辑器

更新入口位于左侧竖向工具栏胶囊外下方，间隔 12px，与工具栏水平居中。工具栏宽 48px、按钮为 36×36px，仅显示图标，名称通过现有 hover Tooltip 与可访问标签提供。分隔线宽 20px，上下间距 6px，外框使用主题标准圆角。正常编辑和加载态共用 `EditorToolRail` 的明确挂载点。

```text
[左侧设计工具栏胶囊]
          12px
      [应用更新]
```

没有更新时控件隐藏且不增加间距。有更新后显示 32px 紧凑图标；下载进度、版本和状态通过悬停、键盘聚焦及详情查看，不横向扩展。气泡在图标上方留 8px，按实际宽度向视口内收，箭头指向图标；气泡不创建滚动区域。点击打开统一更新详情，安装仍在详情中确认。

挂载点与工具栏胶囊为兄弟节点，右上角操作胶囊不放更新入口。画布与业务 iframe 不参与更新展示；普通预览使用自己的外层工具栏，仍待实现。

9 项 Studio 布局测试、2 项更新状态与挂载测试及原生跨框架回归检查通过；Studio 构建、桌面打包和签名校验通过。本地 App 已核对左侧独立图标和上方本地化气泡，临时状态仅用于视觉验收，点击不触发安装，刷新恢复真实状态。

### 普通预览

预览以业务画面为主，更新必须处在外层工具栏。右侧明确采用以下顺序：

```text
[变体 More，有变体才显示] [代码操作，按权限显示]   [应用更新] [返回编辑器]
```

应用更新放在 `PreviewTopBar.rightGroup` 中右侧操作胶囊外侧前方，与操作胶囊间隔 12px。无更新时隐藏；有更新后使用 32px 图标形态：准备时下载图标、下载时进度环、就绪时蓝色下载图标。这里不展开「下载 42%」或「更新就绪」文本，以保留设备、尺寸与返回操作的空间。

已有 More 只承担变体控制，不改其职责和显示条件。应用更新不依赖是否有变体，也不依赖是否有代码操作权限。工具栏在响应式布局中换行时，更新始终和「返回编辑器」处于同一右侧操作组；不放进尺寸菜单，不浮在预览画面的右下角。

### 账户设置

账户设置的详细管理卡片仍是后续待评估项，不代表需要常驻页面状态图标。当前账户设置使用独立 `SettingsContainer`，不能假定它继承 Dashboard 顶栏。直接在正文添加「桌面应用」卡片，位置为账户和偏好设置之后、API Tokens 之前：

```text
账户
偏好设置：外观、语言
桌面应用
  Plasmic 桌面客户端
  当前版本 x.y.z                 [检查更新]
  更新状态／进度／新版本信息
API Tokens
Trusted Hosts
```

卡片是版本和更新的详细管理位置，使用有文字的次要按钮，不再额外新增该页面的浮动更新图标。下载期间按钮改为「查看下载」，就绪后改为「查看更新」；点击仍先进入统一详情，卡片上不直接提供裸露的重启按钮。浏览器环境不渲染该桌面卡片。组织设置、账单等使用 Dashboard shell 的页面则继续继承头像左侧位置，不各自增加卡片。

### 项目组件文档

在 `DocsPortalHeader` 的 `rightButtons` 中放置，沿用普通预览的紧凑形态：

```text
[Project token，按模式显示]   [应用更新] [Back to Studio]
```

更新在 Project token 之后、Back to Studio 之前，与返回操作相邻但保持 8px 间距。现有 Loader／Codegen 选择器不重排，组件文档演示区域不显示更新。Project token 不显示时，更新仍保留在返回按钮前。

### 明确不新增页面控件的场景

纯业务全屏预览、缩略预览、业务 iframe、外部浏览器和发布站点不放更新控件。登录与认证、加载和错误页、内部工具及辅助窗口本轮也不新增页面控件，使用前文定义的原生入口或主窗口承载方式。它们不属于「以后随便塞进更多」的待定项。

`/copilot` 当前是跳转入口，不设计独立更新位置；跳转到项目后采用 Studio 位置。任何新的独立工作页面，需先判断是否已有应用操作区，再选相同控件的固定位置，不能用通用 DOM 搜索自动附着。

## 统一交互建议

### 主动检查入口

原生菜单继续作为应用级入口。主要工作页面只在有更新时使用前述独立状态控件，下载完成后点击统一打开更新详情。没有更新时不显示检查图标；主动检查使用原生菜单，不在每个页面增加独立检查逻辑。

账户设置中的「桌面应用」卡片适合展示版本信息，但不应成为唯一入口，因为编辑器与 CMS 用户不应被要求先退出当前工作。

### 后台检查和自动下载

保留现有自动检查、自动下载行为。无需为各页面分别增加「自动下载」开关或启动按钮。下载状态应由应用共享，页面切换只改变展示位置，不启动第二次下载，也不重置进度。

| 状态                   | 建议页面表现                                                               | 点击行为                               |
| ---------------------- | -------------------------------------------------------------------------- | -------------------------------------- |
| 未检查、无更新         | 页面控件隐藏且不占据空间                                                   | 原生菜单可主动检查                     |
| 正在检查               | 页面控件隐藏；原生菜单主动检查时在对话框显示状态                           | 避免重复请求                           |
| 发现更新、准备下载     | 短暂的低干扰准备状态                                                       | 查看更新详情                           |
| 正在下载               | 工作页顶栏或编辑器工具栏显示小图标与进度；窄空间显示图标，悬停或聚焦看进度 | 查看详情，后台下载继续                 |
| 下载完成               | 显示蓝色下载图标，悬停显示版本与就绪说明；关闭详情后仍保留                 | 用户主动打开，选择稍后或重启安装       |
| 安装准备中             | 明确显示正在保存并准备重启                                                 | 防止重复安装；保存失败时恢复可操作状态 |
| 检查、下载或安装失败   | 主动操作必须说明失败并允许重试；后台失败保持低干扰                         | 查看原因并重试，不能显示为已是最新版   |
| 当前安装形式不支持更新 | 在版本详情或对话框说明实际状态                                             | 不显示可执行的下载、安装操作           |

下载完成默认采用可延后的轻提示。用户主动点击更新控件、设置卡片或原生菜单时才使用更新对话框。CMS 正在输入、预览演示、认证和辅助模态窗口打开期间，不自动弹出安装对话框；返回正常工作界面后提示一次，状态标记持续保留。

### 布局和工程约束

- 为 Dashboard、CMS、编辑器与普通预览声明明确的更新展示位置，由各自 shell 提供；不要继续靠寻找任意 `aside > footer` 推断位置。
- 同一可见应用视图只显示一份状态控件；预览业务内容、组件文档演示 iframe 和画布不展示更新 UI。
- 控件不覆盖 macOS 窗口按钮、Windows 标题栏按钮、预览尺寸操作、CMS 保存或发布操作；可点击区域应排除拖拽行为。
- 使用既有共享 UI 语言包、主题、菜单和控件规范。状态应可通过键盘访问，下载进度有可读标签。
- 新增或调整对话框滚动区域必须由共享 `Scrollbar` 管理，验证有界高度和 flex 尺寸。
- 辅助窗口不复制更新服务或暴露新的通用更新桥接；保持现有来源与主窗口检查边界。
