全页面 UI 与交互改造计划

范围：45 张页面与关键状态设计稿。登录、注册、重置密码沿用现有界面和流程。45 张图是状态覆盖清单，不对应 45 个新路由，也不应分别实现 45 套页面。

目标：以暗黑主题和连续无限画布为核心，统一项目入口、资源插入、对象编辑、AI 修改、预览评审和交付体验。实施先完成 Ant Design 6 + antd-style 的设计基础，再统一应用与编辑器布局，之后接入无限画布交互及其余功能。

页面范围实施顺序统一规则整体验收实施边界

当前实施优先级 · 先统一编辑器公共布局

首先完成所有编辑状态共用的顶部、左侧工具轨道、左侧内容面板和右侧检查器，再继续模板与素材功能细化。

  1. 顶部：统一左右浮动操作组、项目与保存状态、当前页面入口及预览/交付入口，保持实际菜单、权限和 Desktop 拖动区域。
  2. 侧边：统一工具图标与名称、选中/悬停状态、页面/图层导航，以及左右面板的位置、标题、滚动和收起行为。
  3. 公共布局验收：深浅主题、总览、聚焦、专注及小窗口下结构一致；面板切换不改画板位置，浮动操作区域外可操作画布。
  4. 随后完成第 12「插入页面模板」和第 13「项目素材」的搜索、预览、上传、拖拽和管理细节，验证真实插入、保存与撤销。
  5. 再细化右侧设计/交互/数据、业务弹层和组件变体，保留真实 Props、Slots 与事件契约。
验收顺序：公共框架显示 → 面板切换与画布空间 → 模板/素材功能 → 右侧编辑细节 → 其余页面。

实施顺序与每阶段交付

0 · 建立当前行为基线

目的：确定需要保留的真实功能与当前改动范围。

  • 记录项目打开、编辑、保存、预览、分享、设置的实际入口和权限。设置页补充 API Tokens、可信宿主等图中遗漏的已有能力。
  • 当前工作区已有工作台和全局主题改动；先审阅这些改动，再决定继续调整的范围，避免覆盖已有工作。
  • 记录登录、注册和密码重置的现状，后续用相同条件验证没有受到外壳样式影响。
  • 确认模板配置、AI 服务、代码导出、部署和评论在目标部署中的可用性，并列出图中新增能力。
交付：实际页面/能力映射与行为基线；每个设计入口都能归为复用、UI 重组或新增能力。

1 · Ant Design 6 + antd-style 与设计基础

目的：所有页面从同一套样式和控件出发。

  • Studio 应用直接升级 Ant Design 6 与相应图标版本，引入 antd-style，修正实际受影响的组件 API 和内部样式。使用 ThemeProvider、createStyles、useTheme 统一主题和样式来源。
  • 建立作用于产品外壳的颜色、字体、间距、圆角、边框、图标和浮层层级规则，支持深色、浅色与跟随系统。
  • 收敛当前新增 styles/theme.scss 中全局 body/header/aside 和类名模糊匹配的样式。新主题限定在需要改造的应用及 Studio 外壳，不影响认证页和业务画布。
  • 统一按钮、输入、搜索、标签、弹窗、状态提示及菜单；工作台和编辑器分别复用各自的外壳组件。
  • 界面标签进入现有共享语言包。手写封装和样式优先承载改造，不逐页修改 Plasmic 生成文件。
验收：深浅主题下公共控件一致；登录/注册/密码重置与业务页面外观保持原状；语言切换不改变组件契约。

2 · 统一应用布局与编辑器布局

目的：先让所有页面和编辑器共享稳定布局，再改变画布行为。

  • 使用 Ant Design 6 的 Layout、Flex、Grid 与统一 antd-style 样式建立工作台、设置、团队、CMS 和文档的公共应用外壳：导航、顶栏、内容容器和页面操作区。
  • 建立编辑器外壳：项目栏、工具轨道、左右面板与底部控件的统一位置、尺寸、层级及收起行为；此阶段保留现有画布渲染和导航逻辑。
  • 通过共享布局插槽承载既有业务内容，不按截图各自复制导航、顶栏和弹窗，也不为每个页面新增独立 Layout。
  • 先验证窄窗口、滚动、浮层定位、键盘焦点和 iframe 边界；认证页面保持现有布局。
验收：应用页面共享一个布局体系；编辑器面板位置与折叠行为一致；已有画布编辑可继续运行。布局通过后进入无限画布改造。

3 · 打通真实多页面画布

目的：先证明设计图中的核心交互可以在现有模型上可靠运行。

  • 用一个项目的四个真实页面验证混合 Arena 多画板布局；每个画板明确对应页面、视口与当前编辑上下文，编辑不能创建另一份页面内容。
  • 接通选区、图层、属性、撤销、保存与预览。验证在总览编辑某页面后，该页面原有入口和预览能看到同一份修改。
  • 验证画板拖动、布局持久化、负坐标、向画布边缘连续平移，以及重开后的恢复。现有 Arena 尺寸根据右下边界计算，需测试和补齐自由延伸的边界。
  • 总览与聚焦共用多画板渲染；聚焦使用视口缩放和平移。现有 FocusModeLayout 只渲染单画板，不能直接作为新聚焦方案。
  • 定义返回总览和重新打开项目的视口恢复；缩放根据可用视野计算，图中的 25% / 54% 是示例，不应硬编码为所有页面的固定值。
验收：四页可选择、编辑、移动、撤销、保存和重开；总览→聚焦→返回后画板位置保持一致；相邻画板仍可见。此阶段未通过，不进入全量编辑器重排。

4 · 完成编辑器交互与状态

目的：形成可以持续工作的无限画布编辑器。

  • 画布铺满编辑器，项目栏、操作栏、工具轨道、左右面板及底部工具覆盖在画布之上。展开/收起面板不重排画板，适合全部时考虑面板遮挡。
  • 统一左侧页面/图层、组件/模板/素材与组件变体的切换；资源插入使用实际可编辑目标和合法位置。
  • 右侧按设计/交互/数据重组既有编辑能力。先修正注册契约，再调整展示；没有重复的属性映射层。
  • 实现总览、聚焦、专注以及面板恢复。专注保留当前视口；返回总览恢复总览视口，二者是不同操作。
  • 完成空画布、只读、版本历史、保存失败、业务弹层临时展开，以及键盘、拖拽和跨 iframe 的命中行为。
验收：所有编辑器状态共享顶部入口与工具位置；真实修改进入现有保存/撤销；只读不产生修改；弹层临时展示不改变预览初始状态。

5 · 工作台、模板与创建流程

目的：从找到项目到进入新画布形成连贯路径。

  • 统一工作台、项目网格/列表、工作空间导航、搜索、筛选与菜单。缩略图使用保存内容的预览或缓存，避免首页运行全部业务页面。
  • 模板中心明确页面、区块和弹层；展示实际组件库及使用权限，插入后绑定消费项目的数据和事件。
  • 复用一个新建弹窗实现三种起点；名称、工作空间和创建按钮位置固定。空态与工作台的创建入口调用同一流程。
  • 创建成功直接进入项目总览；未有页面时进入空画布。创建失败保留输入，提供重试。
验收：空白和模板均能创建并进入真实画布；原有项目可正常打开；搜索、权限、删除/复制等既有操作保持有效。

6 · AI 修改与生成入口

目的：把 AI 接入现有编辑过程，而不是另建一套页面结果。

  • 底部输入明确当前画布、页面或选区范围。左侧任务面板与同一执行任务同步，不为每个入口建立独立会话状态。
  • 运行、完成、失败、取消来自实际任务反馈。重试保留输入；停止后明确已完成部分，不承诺任意长任务整体回滚。
  • 复用现有 MCP/Agent 桥接和原子编辑操作。自然语言执行服务若尚未具备，需要单独完成后才启用图中的执行入口。
  • AI 连接配置遵循现有 Desktop/服务端的存储与安全边界；前端不新增明文密钥存储。工作台的描述需求与编辑器局部修改共享执行能力。
验收：增加负责人列后，图层、实际 Props、预览与保存结果一致；完成摘要、失败重试、停止和撤销均来自真实执行。

7 · 预览评审与分享交付

目的：编辑结果能可靠预览、评审和交付。

  • 统一预览工具栏、设备切换与返回编辑；业务页面运行自己的路由、表单、分页、Tabs 和 Drawer。
  • 评论定位真实页面与节点，明确权限和版本；页面切换及节点不存在时给出定位反馈。
  • 分享预览/导出代码/发布应用使用同一外壳。各标签继续调用实际现有流程，复杂设置采用二级区域，不能因简化图稿而丢掉配置。
  • 先核对固定版本分享、访客评论、工程代码交付等能力。只把真实可用的功能作为可操作入口；发布使用现有环境与权限校验。
验收：编辑→预览→评论→返回编辑的上下文一致；权限真实生效；导出产物通过其必要构建检查；发布状态对应真实部署结果。

8 · 设置、团队、内容库与文档

目的：其余页面统一显示与导航，并保留各自业务能力。

  • 设置收敛外观、语言、账户、AI 与工作空间入口。支持实际保存语义，不把所有设置都伪装成自动保存。
  • 成员、角色、账单与分析使用现有权限、方案和数据。部署未开放的页面不展示可执行假入口。
  • CMS 统一模型导航、条目列表、字段编辑、草稿/发布、修订和结构设置；优先复用已有组件与接口。
  • 开发者文档展示真实组件 Props、Slots、事件、代码来源及集成方式，保留已有 API Tokens 和可信宿主等入口。
验收：修改设置后重开可读回；成员权限生效；内容草稿、发布与修订可完成；文档契约与实际组件一致。

9 · 全流程一致性与发布检查

目的：验证完整体验，而不只验证截图相似。

  • 执行下面的端到端主流程和主题/语言/权限矩阵；每个页面补齐加载、空态、错误和不可操作状态。
  • 以实际项目测量打开、平移、缩放、选区和内存。先测试四个真实页面，再扩大到十个及更多，按结果实施可见区域加载或远处画板简化。
  • 检查 1440、1600、1920 桌面宽度及较小窗口。小窗口允许面板收起，避免同时展示所有面板导致页面不可操作。
  • Web 与 Electron Desktop 分别验证；Desktop 使用本地构建产物并按现有来源校验打包，不能以 Web 开发环境通过替代桌面验证。
交付：可运行版本、状态覆盖清单、真实检查结果与一致性截图。后续图集由同一组件/实际运行截图更新。

所有页面共用的交互约束

  • 顶部预览与分享位置固定；分享始终进入同一交付流程，场景差异只改变可用操作与权限。
  • 主题、语言、按钮、弹窗、通知与图标共用来源；业务页面自身主题与编辑器主题分离。
  • 左侧面板切换内容，右侧按选区更新。属性、Slot、事件和数据写入现有 Studio 模型，显示层不产生平行数据模型。
  • 当前选区、活动画板、面板状态和视口必须共享上下文；跨页面导航不默认丢弃或重置视口。
  • 只读、保存状态、AI 状态与发布状态分别由实际权限和执行结果决定，不互相替代。
  • 临时展开业务弹层、切换非活动 Tabs 等编辑展示状态不能泄漏到业务初始属性、预览或导出。

完整主流程验收

  1. 通过现有登录进入工作台，找到并打开已有项目。
  2. 创建空白或模板项目，在总览查看四个不同页面，并移动画板。
  3. 聚焦客群列表，选中表格，修改 Props、绑定数据与事件，验证撤销。
  4. 临时展开新建抽屉进行编辑；预览初始状态仍按真实业务配置运行。
  5. 执行 AI 增加负责人列，核对完成、失败、停止与撤销反馈。
  6. 切换总览、专注、面板恢复与浅色主题；检查位置、选区和页面内容。
  7. 运行桌面/手机预览，完成筛选、分页、创建和页面跳转；评论可定位。
  8. 分享后按真实权限访问；完成所选代码交付/发布路径的必要验证。
  9. 保存并关闭项目，再打开，核对设计、画板布局及应恢复的偏好。
  10. 验证账户/团队设置、内容条目编辑与修订，以及真实组件文档。

实施边界与关键判断

第一交付目标：Ant Design 6 + antd-style、统一布局、暗黑外壳 + 四页真实无限画布 + 总览/聚焦/专注 + 属性修改/保存/预览。完成阶段 0–4 后即形成可评审的核心产品版本，之后按阶段补齐入口、AI、交付和周边页面。
