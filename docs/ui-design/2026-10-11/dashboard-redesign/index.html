Dashboard：与编辑器一致的项目工作台

2026-10-11 · 推荐「项目工作台」，同时提供「空间浏览」 · 查看可交互方案 · 设计检查结果

本次交付是 UI 设计与本地交互样稿。依据当前仓库、当天已部署 Dashboard 的可见入口，以及上一轮功能审计；没有提交项目创建、邀请或权限变更。两个项目名称沿用已有设计审计，不代表重新查询后的项目更新时间。业务表单最终必须使用当前权限、配置和服务返回值。

设计判断

这里应是一款面向创作者的生产力产品。用户的首要任务是找到已有作品、开始新项目、进入所属工作区；团队管理和数据连接依然重要，但不应抢占首页的视觉中心。界面的专业感来自清晰的层级与可预测的操作，不需要统计大屏、彩色指标卡或业务管理表格。

沿用当前编辑器的实际 P 标志、浮动品牌胶囊与右侧操作胶囊、12px 面板圆角、紫色主行动与选中状态，以及深色背景／面板／分隔线的层次。Dashboard 的导航与内容重新组织，但不另造品牌或一套窗口框架。品牌图形直接取自 DefaultLayout 的现有路径。

「项目工作台」将永久展开的文字侧栏收为 62px 导航轨，左侧“空间”入口展开组织与工作区树。中间按实际工作区组织项目，右侧显示选中项目的摘要、打开与复制；其余操作收进菜单；点击封面查看详情，点击名称或“打开编辑器”继续编辑。不会为查看信息而加载编辑器，也不会增加一套业务数据。

「空间浏览」取消初始详情栏，以工作区集合为主体；查看某个项目时才展开详情。两种方案共享品牌和资源层级，区别是持续上下文操作与内容优先浏览。创建变为右侧抽屉，保留背景中的工作区上下文，继续使用原名称、目标工作区和空白／模板流程。

参考 Figma 文件浏览器的内容浏览与上下文组织，以及 pen.dev紧凑、克制的工具外观。实际查看本机 Figma 文件浏览器和 pen.dev 编辑器；后者的编辑器结构不是其 Dashboard 功能证据。借鉴布局语言，不照搬通知、收藏、回收站、社区或 AI 会话。

布局收紧

导航轨与内容面板按内容决定高度，取消 435／700／800px 的固定最小高度和导航底部的填充间隙。右侧不再纵向铺开六个操作，以摘要和两项行动为主；完整六项项目操作仍可从更多菜单进入。左右顶部胶囊等高，距离窗口边缘均为 16px。空间导航集中到左侧，不在品牌旁重复设置切换器。

信息架构与交互

  1. 浮动顶部只保留当前编辑器的品牌与窗口按钮，移除重复且含糊的“项目空间”下拉；文档与账户胶囊右对齐，并与品牌胶囊等高。应用导航变成紧凑轨道；所有项目、个人空间、组织与工作区仍可直接访问，左侧“空间”入口提供完整名称与层级。
  2. 项目集合按现有 Workspace 分组，不引入文件夹或新的持久化层级。个人试验场单独呈现空态，创建入口直接指定该空间。
  3. 项目封面选中后展示右侧详情：名称、组织、工作区、修改时间与打开、复制及更多操作菜单。名称点击仍可直接打开；列表的名称用于选择，右侧明确提供打开编辑器按钮。收起详情后浏览区占满剩余宽度。
  4. 创建使用右侧抽屉；保留名称、目标工作区、空白／模板和原校验，工作区内创建保持目标上下文。模板必须来自真实工作区或配置，不因 Admin Templates 的项目名而将其当作模板。
  5. 组织页继续按工作区承载项目及 CMS；工作区保留项目／数据源标签、分享、重命名、移动、删除；账户保留全部现有设置分组。
  6. 窄窗口将详情移至项目集合下方，导航轨改成横向；创建抽屉自适应为窄屏浮层。五种分享角色、复制名称与目的地、项目操作均保留。

能落地的增加项与边界

项目数据及成本本次呈现
选中项目详情直接读取当前项目与工作区列表已有 name、updatedAt、workspace／team 数据。前端选中状态不写入 Studio 模型；操作仍按原权限门控。工作台初始选中一个项目以展示交互，点击另一封面同步详情。空间浏览默认不展开详情。
空间分组与导航轨对现有项目按 workspaceId 分组，沿用既有团队与工作区集合。没有新增文件夹层级。组织／工作区完整名称在空间弹层展示；导航轨提供项目、个人与组织入口，以及“空间”导航弹层。
名称封面使用现有 name 前端排版；当前 ApiProject 无缩略图字段。不展示虚构画布截图、页面数量、在线成员或发布状态。
视图偏好可按设备保存网格／列表与详情栏展开状态，现有业务模型无需变更。样稿记忆页面、浏览视图与详情选择。
创建抽屉改变 NewProjectModal 的呈现容器，复用表单、作用域和 API，不增加新的创建类型。空白／模板共用一个抽屉流程。

不加入未经验证的最近访问、收藏、通知、实时在线状态、统一资产中心或发布成功标签。“最近修改”使用 updatedAt，不解释成“最近打开”。Admin Templates 是已有项目名，其名称本身不能证明它已被设置为模板。
