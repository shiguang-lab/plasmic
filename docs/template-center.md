# 模板中心

模板中心是顶部导航的独立入口 `/template-center`，与项目、个人试验区和组织空间平级。模板直接按页面/区块、适用端、场景分类和已发布内容使用的组件库筛选，没有集合层级。

## 维护与参考

- 系统管理员（身份服务的 `system-admin`）创建模板、编辑信息和画布、发布、下架、删除未发布模板。
- 新建模板直接打开画布，自动提供一个 `/` 参考页面；移动端初始画板为 390×844。区块模板也通过这个页面展示其内容。
- 画布左上角返回模板中心，发布按钮先保存当前画布，再发布模板。模板中心的发布操作发布已经保存到服务端的主分支内容。
- 登录用户只看到最新已发布信息和交互预览。未发布修改不会改变对外的标题、说明、分类或预览。
- 下架同时隐藏目录条目并禁用参考预览；再次发布复用预览地址。已打开的预览在重新加载时读取新版本。
- 模板用于参考，本流程没有安装、引入依赖、复制到业务项目或修改项目创建入口的操作。

## 数据和权限

`design_template` 记录每个模板的草稿元数据及最新发布元数据。其 `projectId` 指向内部编辑画布，`project.isTemplate` 区分模板画布和业务项目。模板画布不属于工作区，并被业务项目列表查询排除。

现有 Studio 模型、撤销、保存和组件注册机制承担画布编辑。模板草稿在通用项目权限检查和批量资源权限检查中均要求系统管理员；分享权限、公开默认权限、项目令牌不会向普通用户开放草稿。界面权限与服务端限制一致。

`/api/v1/template-center` 提供列表和创建；`/:templateId` 提供元数据更新和删除；`/:templateId/publish`、`/:templateId/unpublish` 负责发布和下架。列表只向管理员返回 `draft`；普通用户返回已发布记录。所有维护接口都校验系统管理员身份。

## 发布与运行

发布先保存一个内部模型版本，使使用独立数据库连接的代码生成 worker 能读取它。随后在事务中生成固定版本的 `preview_publication` 和更新模板发布信息；失败时上一份发布信息和预览不变。发布、更新元数据、下架和删除按模板串行处理，发布前校验准备阶段的版本及元数据未被并发更新覆盖。

发布复用现有预览服务，需要配置 `PREVIEW_ORIGIN`，并运行对应代码生成 worker 和预览服务。模板需要至少一个固定路由的参考页面。实际组件库依赖随发布记录，不由展示标签替代。

部署前执行标准数据库迁移，包含 `AddTemplateCenter1794873600000`。迁移增加 `project.isTemplate`（现有项目默认 false）及 `design_template` 表。
