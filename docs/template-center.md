# 模板中心

模板中心是顶部导航的独立入口 `/template-center`，与项目、个人试验区和组织空间平级。模板直接按页面/区块、适用端、场景分类和已发布内容使用的组件库筛选，没有集合层级。

## 维护与参考

- 系统管理员（身份服务的 `system-admin`）创建模板、编辑信息和画布、发布、下架、删除未发布模板。
- 新建模板直接打开画布，自动提供一个 `/` 参考页面；移动端初始画板为 390×844。区块模板也通过这个页面展示其内容。
- 画布左上角返回模板中心，发布按钮先保存当前画布，再发布模板。模板中心的发布操作发布已经保存到服务端的主分支内容。
- 编辑模板信息后点击「保存」，名称、类型、设备、分类、描述和封面立即更新。未发布的模板在首次发布画布后进入普通用户的目录。
- 点击已发布模板卡片，在只读 Studio 中打开最新发布版本。通过页面目录可以直接打开没有业务入口的页面，点击「预览」从当前选中的页面开始。画布和预览在同一会话内使用同一份发布模型。
- 发布会话对管理员也锁定模型和版本。Studio 隐藏编辑、版本及评论入口，MCP 可读取设计和浏览画布，写入设计、保存、撤销及评论操作会被拒绝。
- Desktop MCP 的 `open_template({templateId})` 打开同一只读画布，并返回实际打开的模板 ID、名称和发布版本。跨画布导航前会保存当前可编辑设计。
- 在每个示例页面的「页面设置 → 描述」中，用一两句话写明使用者要完成的任务、主要区域如何配合，以及与相近页面最容易区分的操作或数据范围。以画布实际呈现为准。保存并发布后，AI 从各页描述选择参考。
- 管理员通过卡片菜单的「编辑画布」打开草稿。下架后，普通用户的目录隐藏该模板，只读 Studio 入口与参考预览地址停止提供该模板。已打开的模板在重新加载时读取当前发布状态。
- 模板用于参考，本流程没有安装、引入依赖、复制到业务项目或修改项目创建入口的操作。

模板目录以卡片网格展示，封面框统一为 4:3。图片完整居中，比例不同时用原图的模糊背景填充边缘。支持类型、场景、适用端和组件库筛选。管理操作位于卡片的更多菜单。空目录与筛选无结果分别提供创建入口和清除筛选入口。

模板封面通过信息编辑弹窗上传，可替换或移除，支持 PNG、JPG、WebP，最大 5 MB，建议比例 4:3。图片复用现有图片上传服务，地址随模板信息保存在 `thumbnailUrl` 中。没有封面时显示统一占位。

## 数据和权限

`design_template.metadata` 保存当前模板信息，`design_template.published` 记录画布的发布版本、时间、预览地址和组件库。其 `projectId` 指向内部编辑画布，`project.isTemplate` 区分模板画布和业务项目。模板画布不属于工作区，并被业务项目列表查询排除。

现有 Studio 模型、撤销、保存和组件注册机制承担画布编辑。模板草稿在通用项目权限检查和批量资源权限检查中均要求系统管理员；分享权限、公开默认权限、项目令牌不会向普通用户开放草稿。界面权限与服务端限制一致。

`/api/v1/template-center` 提供列表和创建，`/:templateId/studio` 向登录用户返回当前模板名称和已发布的画布版本，`/:templateId` 提供元数据更新和删除，`/:templateId/publish`、`/:templateId/unpublish` 负责发布和下架。普通用户的列表包含已发布模板的最新信息。所有维护接口都校验系统管理员身份。

## 发布与运行

发布先保存一个内部模型版本，使使用独立数据库连接的代码生成 worker 能读取它。随后在事务中生成固定版本的 `preview_publication` 并更新画布发布记录。发布失败时继续提供上一次成功发布的画布。最终发布前检查画布发布状态和包版本，模板信息可以独立保存。

发布复用现有预览服务，需要配置 `PREVIEW_ORIGIN`，并运行对应代码生成 worker 和预览服务。模板需要至少一个固定路由的参考页面。实际组件库依赖随发布记录，不由展示标签替代。

部署前执行标准数据库迁移，包含 `AddTemplateCenter1794873600000` 和 `SeparateTemplateMetadata1794960000000`。已有模板以最新保存的信息为准，并沿用已发布的画布版本。
