# 组件库模型资源化与加载验收

状态：源码完成，尚未部署生产或替换已安装 App。生产热修复状态和配套发布要求见 [运行说明](unpublished-revisions-hotfix.md)。

## 接口职责

- 首次打开项目 GET：`/api/v1/projects/:projectId?includeStartup=true`（另传 `branchName`）同时返回 `startup` 上下文、项目正文和依赖资源清单。专用 bootstrap 接口已删除。
- 普通项目/包 GET：当前修订和权限、准确依赖版本、模型资源 ID；不附带组件库模型正文，不重复查询启动上下文。
- 模型资源 GET `/api/v1/dependency-models/:resourceId`：按权限返回完整不可变 JSON。
- 客户端：Root 使用本次响应中的启动上下文，同时初始化编辑器并通过 SharedApi 并行获取缺失模型，不重复请求项目。Desktop 在协议处理器中按资源 ID 查本地，命中不访问服务端。

项目自身页面模型仍完整返回，没有实施页面按需加载或组件库分包注册。模型请求单位是一份依赖包模型，不是一个组件；848 个图标属于一份图标库模型。JS、图片、字体仍由各自资源路径加载。

所有库存扫描上传、`modelDigests` 参数、只读 POST 协商、按客户端缓存裁剪和空缓存特殊分支均已移除。资源响应中的校验和只用于下载完整性校验，不上传回服务器参与缓存判断。

## 请求数量

下表仅统计到服务端的启动、项目模型和依赖模型请求，不包含 JS、图片、字体、登录等其它请求。客户端调用本地资源协议处理器命中时不计网络请求。

| 缓存状态 | 原 0.5.27 | 当前方案 |
| --- | ---: | ---: |
| 全部命中 | 2 | 1 |
| 缺 1 份模型 | 2 | 2 |
| 缺 N 份模型 | 2 | 1＋N |

原链是启动信息 → 项目模型。当前链是项目正文/启动上下文/资源清单 → 并发 GET 缺失资源。全部命中时只剩一次项目请求；缺失资源仍依赖清单到达。服务端并发发起启动上下文与项目读取，复用项目及权限查询。不存在的分支返回 400，避免 Desktop 将它误判为项目删除。启动上下文随项目正文同时到达，原先可在上下文先到后提前进行的界面初始化现在会等待该响应；因此少一次请求不等于首帧或完整画布必然更快。

## 资源和权限契约

`dependency_model_resource` 按发布实体 ID 和模型内容唯一，保存不可变 JSON 文本。相同内容复用资源 ID；模型迁移改变内容时生成新资源 ID，旧资源字节不覆写。资源权限按所属包的当前 viewer 权限检查；包/发布实体硬删除时资源级联删除。资源创建不写业务页面模型。

普通读取事务先完成，随后生成并提交资源，再输出引用，避免客户端在创建事务提交前 GET 到 404。Desktop 主进程校验保存路由后，将完整打开响应在内存中暂存最多 30 秒，仅相同项目/分支的可信主帧可消费一次，账号变化即清除。客户端保留原包版本与模型加载顺序，源码/Props/Slots 一致性由真实发布端到端验证。账号、Studio 来源和实际 renderer 构建隔离本地资源缓存；跨项目共享同一范围内的资源，退出清理可重新下载的资源文件。

## 对照方法

在 NAS 一次性 PostgreSQL 容器中还原当前生产数据的完整逻辑副本，执行新迁移。使用副本里当前用户的普通权限和两个现有项目。没有对生产执行新迁移或改项目；测试后删除数据库容器和卷。

基线直接使用 0.5.27 的启动处理器、项目处理器、原协商函数及 Desktop 缓存实现。当前链使用实际 GET 路由读取事务/资源映射流程、资源 GET 和当前磁盘缓存。两边均包含 JSON、磁盘缓存、校验和和完整响应还原。

预热模块/JIT/数据库并生成资源后，每场景交替执行 7 轮。冷缓存指客户端模型目录为空，不是服务进程或数据库冷启动；部分缺失指删除最大一份模型文件，其余保留。对照实验为每个项目分开缓存目录以控制条件，实际产品缓存不按项目隔离。每轮校验修订 ID 和全部依赖模型内容摘要与基线一致；副本的项目/修订数量前后均为 89 / 3442。

以下耗时是同机模拟传输、服务端处理、JSON、缓存 IO、校验和与用于体积统计的 gzip 总处理耗时，未包含实际 HTTP/TLS、公网 RTT、浏览器或画布渲染。`serverWorkMs` 是并发请求处理时间之和，不是关键路径耗时。7 个样本的 p95 仅为观察值，不是生产 SLO。

### 客服平台 · GP评论查询

| 状态 | 原链 | 当前链 | 原/新网络请求数 | 新模型资源 GET 数 |
| --- | ---: | ---: | ---: | ---: |
| 空缓存 | 563.7 | 505.3 | 2 / 6 | 5 |
| 全部命中 | 517.2 | 306.1 | 2 / 1 | 0 |
| 缺一个模型 | 571.5 | 400.0 | 2 / 2 | 1 |

两组隔离样本的总处理耗时下降；热缓存由两次网络请求减少为一次，缺失模型依旧按引用并发获取。这个对照同时包含模型资源化与首次打开合并，不能把全部耗时改善归因于减少一个接口，也不能据此承诺完整 App 首帧或可编辑时间。

首次生成资源和预热缓存另记：Admin Templates 约 565 ms、创建 4 份资源；客服项目约 610 ms、仅新建 1 份资源，其余 4 份在服务端复用。计时包含首次缓存 IO/JIT，不能全部归因于入库，也不能用预热后的冷缓存数字代表首次部署后的首次访问。

`entryMs` 记录项目响应解析完成的时刻：原链在此之前还获取启动信息并补齐本地依赖，当前链此时已得到启动上下文和依赖引用，随后再补齐资源；它不是两版的首帧或可编辑时间。
原始样本、准备阶段、体积和分位数见 [JSON 记录](model-resource-loading.json)。完整正式 App 的首帧/可编辑耗时 A/B 尚未执行，不以此隔离测试代替 UI 性能验收。

## 验证

- Desktop Node：512 项通过；覆盖模型资源持久缓存、跨项目复用、160 个无关缓存不上传、GET/HEAD 并发去重、损坏后按资源重取、版本变化、账号隔离和原 API 透传。
- WAB：12 文件、90 项通过；覆盖资源不可变性与权限、事务提交先于引用和 304 响应、提交失败不发送成功响应、原读写路由、六类模型读取入口的 GET 资源加载、单次打开与并行初始化、分支选择及权限失败、来源检查。
- 实际沙箱 Electron：gzip、单次打开项目 GET、精确资源 GET、本地命中零网络验证、原历史列表与写入 POST 保留；并发 403 的 gzip 错误响应及 HEAD 语义通过。
- 临时 PostgreSQL 真实 npm tarball 发布端到端通过：两个并发首次读取复用同一已提交资源，两版本代码/Props/Slots 与模型一致，首次与新版本各下载一份模型，重开和切回旧版本无重复模型下载。模型主体不再出现在包响应中。
- TypeScript 检查通过；新增逻辑相关 ESLint 无错误。`app-ctx.ts` 仅重命名类型，其既有正则转义 lint 错误与两条警告和 HEAD 一致；其它既有大文件保留 11 条警告。
