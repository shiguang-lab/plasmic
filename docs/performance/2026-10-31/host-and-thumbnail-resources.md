# Web Host 强缓存与非图标预览图外置

状态：Studio 0.5.31、Desktop 0.5.30 已发布，Server/Web 已部署；Antd6 3.11.0、Overseas 1.13.0 已发布并通过画布、自动升级和热缓存验收。部分 CDN 图片旧缓存头待清理，见 [生产验收](release-0.5.31-acceptance.md)。本地验证记录见 [JSON](host-and-thumbnail-resources.json)。

## Web Host

生产构建将渲染后的内置 Host HTML 按完整 SHA-256 输出为 `static/host.<hash>.html`。NAS 启动配置先替换 Studio/Canvas 域名，再重算 Host 哈希并同步更新脚本中的引用，文件名中的哈希对应最终实际文件字节；Host 模板、语言内容、Studio URL 或引用的脚本构建变化都会更新文件身份。Web 只在使用本部署的内置默认 Host 时选择这个文件，Nginx 返回一年 `public, max-age=31536000, immutable`。同一 StudioCtx 中的多个画板复用这份不可变 HTML 的读取 Promise，失败后允许重取。

普通入口 HTML 和未带哈希的 Host 仍可更新。App 使用原来的安装包本地 Host；开发环境、自定义默认 Host、项目/分支自定义 Host 的选择不变。Host 信任检查使用配置中的 URL，避免构建文件名变化造成重复信任提示。哈希文件和其他不可变静态文件应一起部署，并保留仍在使用的旧构建文件；不能把所有 HTML 都永久缓存。

实际浏览器缓存验收同时导航 Host iframe、并发读取 Host HTML，再销毁页面并重建。第二次 Host 请求数为 **0**，没有条件 GET 或 HEAD。普通入口仍是 `no-cache`。这验证缓存链路，没有重新测量线上业务画布的完整耗时，也不承诺固定毫秒数收益。

## 非图标预览资源

Antd6 和 Overseas 的构建使用现有 SVG 生成器输出 `skinny/thumbnails.plasmic.json` 和轻量的 `./thumbnails` 入口。注册入口引用清单，不打入绘图生成器；本地 npm 注册仍能独立展示预览，不需要构建时访问对象存储。公共画布包通过专用 `./native` 入口引用原生 Antd 和语言包，构建图中不再引入组件注册元数据或预览清单；完整组件注册与原有加载时机保持一致。`Table.ExpandColumn` 的专用 SVG 也进入清单，图形内容保留。

平台组件库发布时：

1. 通过现有 SVG 上传服务生成内容寻址的绝对 `/assets/<md5>.svg` URL，不使用 Canvas 域上的相对资源地址。百分号编码的 data URL 在上传前解码为真实图片字节，再进行文件类型检测。
2. 对公开 URL 做 HEAD，确认成功和 SVG 类型。单次检查限时 15 秒，连接失败或 5xx 最多尝试 3 次。上传、持续访问失败或类型检查失败会中止发布，不保存含悬空预览链接的新版本。
3. 编译注册代码时把专用 JSON 模块替换为 URL 清单；导出用的不可变模块快照也保存这份替换后的内容。Canvas、服务端注册代码及库模型指向同批内容。
4. 显式发布入口将库模型的 SVG 预览引用外置，再按现有事务和版本规则发布。普通项目读取、依赖资源读取和模型迁移不执行上传或公开 URL 检查。

不改 `thumbnailUrl` 字段、Props、Slots、默认值、事件或自动升级决策。已有版本和业务项目不批量改写；新库版本通过现有平台库升级机制生效。带显式外部 URL 的预览继续保留。图标默认继续渲染已注册 SVG 组件，不新增图标缩略图请求。

卡片沿用现有懒加载及图片失败回退，关闭组件目录时不预取整套图片。Nginx 对内容寻址的 `/assets/` 成功响应返回一年 immutable 缓存；Web 和 App 都通过浏览器网络缓存复用已看过的图片。这些公开图片不占组件库代码/模型缓存层的 256 MiB 预算。浏览器清理缓存、淘汰资源或缓存超期后可重新请求，不能将 HTTP 缓存描述成无限期离线保留。

当前两份清单共 **123** 张 SVG；`thumbnailUrl` 值合计由 **182,183 B** 的 data URL 替换为 **10,086 B** 的生产绝对 URL，约减少 **94.5%**。这是清单字段体积，不是完整项目响应、gzip 流量或首帧耗时；共享预览可能被多个注册项引用。

## 验证

- Antd6、Overseas 包构建及原有包测试通过；图标直接预览、显式图片优先、普通组件失败占位和替换图片后的恢复通过。
- WAB 相关测试 10 文件、38 项通过；部署域名替换与哈希/旧文件保留的 Python 测试 2 项通过。相关测试覆盖 Host 路由边界、哈希路径真实启动/挂载、内容哈希、组件库上传/公开读失败、不可变快照、前后版本独立、失败时不保存/发布、发布版本策略和 Loader 打包。
- 真实 Antd6/Overseas 包的未外置/外置注册元数据结构一致，比较时仅排除 `thumbnailUrl`，函数保留存在性占位并处理递归元数据。浏览器注册代码不再携带预览 SVG；服务端保留正常业务依赖自身的 SVG，不按字符串前缀删除业务资源。
- 公共画布包 5 项回归通过：两种 JSX 构建、Host/Canvas 两种运行时的主题样式和账号切换，以及公共包不包含注册元数据/预览正文。
- 沙箱 Chromium + 当前 Nginx 配置：16 张预览全部解码；重建页面后 Host 和预览图网络请求均为 **0**，App 原有协议转发路径下的已查看图片也为 **0**；换一份内容哈希后只下载新图一次，切回旧图没有网络请求。已核对截图外观。
- 本地编译验收用内存对象存储替身，不向生产 S3 或数据库写入。公开读取失败由单元测试覆盖；Nginx 真实 HTTP 缓存、图片读取和 HEAD 响应另行验证。本次不是线上验收或完整业务启动性能 A/B。

## 生效顺序

部署更新后的 Server 和 Web（包含新的 Nginx 配置及 Web 容器的 `STUDIO_ORIGIN`、`CANVAS_ORIGIN`），再通过现有组件库发布命令发布新的 Antd6、Overseas 版本。不要覆盖历史版本制品。当前 App 的图片预览通道已支持绝对 URL，无需为这两项重新发布安装包；资源首次查看仍需下载。后续预览图更新随组件库版本发布，不依赖 App 发版。
