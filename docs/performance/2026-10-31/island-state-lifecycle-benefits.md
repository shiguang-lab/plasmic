# 灵动岛优化收益对照

同一台 macOS、Electron 44.5.1，使用相同的固定预览页面、真实灵动岛窗口/渲染/IPC，以及模拟账户接口。修改前为 `390772252`，修改后为当前源码；每组独立启动 3 次，顺序 AB、BA、AB。以下为中位数，原始结果与源码摘要见 [JSON](island-state-lifecycle-benefits.json)。不是线上业务项目或低端机数据。

## 结果

| 状态/指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 收起待机，约 3 秒的状态 IPC | 6 条，JSON 等效 2.09 MiB | 0 |
| 展开静态预览，约 3 秒的状态 IPC | 12 条，JSON 等效 4.28 MiB | 0 |
| 退出后连续 3 次导航，专用账户摘要调用 | 12 次 | 0 |
| 退出后的灵动岛浮窗渲染进程 | 保留，RSS 约 147 MiB | 已释放 |
| 退出并导航期间，应用各进程 RSS 合计 | 590.7 MiB | 439.2 MiB |
| 收起待机 CPU | 3.79% | 2.13% |
| 退出并导航期间 CPU | 5.11% | 0.71% |
| 重新开启浮窗完成 | 20ms | 163ms |
| 重新开启至预览图片显示 | 536ms | 682ms |

可确认的收益是去掉重复状态传输、退出后释放一个浮窗渲染进程，以及停止专用摘要调用。代价是重新开启浮窗及显示图片约增加 **0.14～0.15 秒**。

展开静态预览的 CPU 中位数为 15.74% → 14.26%，但修改前范围 11.68～16.48%、修改后 13.98～14.63%，存在重叠；3 个短样本不足以证明该状态有稳定 CPU 改善。启用时没有降低截图频率和动态任务反馈，因此不把这次改动说成全面降 CPU。

## 测量边界

- 每个状态观察约 3 秒；退出阶段在同一观察窗口中执行 3 次导航，故不是纯空闲 CPU。每阶段在开始和结束取累计 CPU 秒数，并每 500ms 采样进程 RSS。
- CPU 为应用存活进程累计 CPU 时间之差除以墙钟时间，100% 表示占满一个核，不是全机总算力的百分比。
- RSS 合计来自 `app.getAppMetrics().memory.workingSetSize`，可能重复计入共享页；**不能把减少的 151.5 MiB 直接等同于操作系统释放的独占物理内存**。进程退出已确认，但业务项目中的数值需另测。
- IPC 字节为测量窗口结束后计算的 JSON 等效正文，不是底层 IPC 线上字节；计数期间只保留消息对象引用，避免额外序列化影响 CPU 采样。初次同步/初次图片发送在预热阶段，不在静止窗口中。
- 大部分重复消息体来自整份状态中携带的语言包，不是这张测试图片本身。图片和账户数据固定；真实大图、网络等待、复杂组件与编辑器会改变绝对数值。
- 专用请求由 native 导航事件触发，模拟接口立即返回；真实接口的进行中去重可能减少修改前的调用数，不能推导每次真实导航固定产生 4 次请求。
- 内存前组退出阶段范围约 556.7～592.9 MiB，后组约 438.4～439.3 MiB；使用中位数避免仅选择一次结果。没有录制低端机温控、Swap 或长期 GC。

## 复现

精确脚本见 [benchmark](scripts/island-benefit-benchmark.cjs)。在临时目录中放置脚本，建立 `before/src`（基线源码）、`after/src`（当前源码）、`ui-locales`（语言包及 locale-resolution.cjs），并为两个实现和临时目录链接相同的 Desktop node_modules。使用同一个 Electron，依次传入模式 `before` / `after` 和结果 JSON 路径。每次使用新临时用户目录；脚本退出时清理配置，不连接线上或修改用户安装的 App。

本次只增加收益测量与记录，没有继续修改业务实现。
