状态：保留两项，撤回三项；另修复验收发现的环境索引清理竞态。源码、单测、类型检查和生产构建已验证，未提交、发布或替换已安装 App。工作区原有其他修改保留。

原始数据：[five-optimizations-validation.json](five-optimizations-validation.json)。环境为 M4 / 24GB、macOS arm64、Electron 44.5.1。不同实验的计时范围不同，不能相加为 App 打开收益。

## 保留项的实现与边界

### 项目 GET

`PkgVersion` 已有字符串正文时，先计算原始字节摘要并查找已生成的不可变资源；命中后直接复用身份，避免再次解析和序列化大型模型。未命中时仍按原方式生成规范正文，并查找规范摘要，保留已有资源 ID 和响应。测试覆盖空白、Unicode 转义、数字格式、首次资源生成、迁移后正文变化及元信息保留。

权限去重键将省略的 `includeDeleted` 归一为 `false`。检查仍在同一 DbMgr 内去重；不同项目、权限级别、`includeDeleted=true` 和不同调用者保持隔离。项目请求、组件库版本检测、自动升级和客户端缓存协议不变。

测量运行正式 0.5.31 服务端路由和当前前后资源处理源码，使用一次性数据库副本、项目实际所有者和无系统管理员角色的正常 actor。权限键默认值在诊断中通过等价运行时包装归一，源码另有隔离单测。26 次交错请求去掉前两次预热，每侧 12 次；计时包含路由响应 JSON 编码，不含公网 HTTP 鉴权、网络、客户端解析和渲染。

修改前后范围分别为 221.53–393.91 / 184.94–278.81ms。所有正式比较样本的响应正文、5 个依赖和修订 158 一致；副本项目数和修订数不变。临时数据库、导出文件和 NAS 诊断目录已删除，线上服务和数据未修改。

### 静态排队骨架屏

`CanvasFrame` 仅在 `ready-to-load`、`loading` 或组件注册表更新时开启 Skeleton 动画；排队状态保持静态。保留原加载数量、优先级、iframe 身份、加载遮罩和编辑状态。

性能 fixture 使用项目实际 Ant Design Skeleton 和生产构建，12 个预览全部可见，每侧 5 个 2 秒窗口。动态范围 475.25–555.92ms，静态范围 0.23–0.54ms；样式重算也停止。另有 1 个动画预览的正向控制，任务时长 182.17ms，只有一个样本，不据此推断普遍比例。

这是多画板排队期间的持续开销改善，不是首屏耗时缩短 510ms。实际验收项目的初始总览只有一个画板，本次没有证明它因骨架屏修改而整体打开更快。

## 撤回项的测量范围

后台暂停实验使用真实 StudioCtx 队列、jsdom、固定 300ms 手势和三次 40ms 同步初始化；每侧 7 次。定时回调延迟反映调度阻塞，不能称为真实鼠标输入延迟。实验完整加载了三个请求，但只是把工作推迟，因此没有保留。

MobX 实验中，两侧均包含相同的环境索引修复和静态骨架屏。丢弃侧通过浏览器构建替换插件将显式开发版导入指向同一 ESM 实例，服务端入口保持原样；源码映射确认开发版模块消失。离线实际项目/Plume 数据在每侧 4 个新 Electron 进程中交错运行，均通过编辑、撤销、重做且没有控制台错误。计时使用 100ms 就绪轮询，范围 2070.40–2157.00 / 2156.02–2188.85ms；粒度与样本量不支持固定毫秒收益或普遍回退结论。该替换插件已撤销。

画板保留实验在独立进程中创建六个仅存在内存的画板，均展示实际项目同一页面，依次访问后再返回两轮。每个设置一个进程、12 次返回；每次返回包含固定 100ms 稳定等待。6/3/2 的 RSS 求和采样分别为 1186/1288/1274MiB，不能当作独占物理内存，也不能凭单次采样认定泄漏或内存回收规律。降低保留数没有稳定内存收益，返回耗时明显增加，iframe 内运行状态也会重建。

## 验收发现并修复的环境索引竞态

本轮开始时的基线也会在编辑后出现 `Couldn't find envs`，随后可能出现 `instanceKeyStack` 错误。单点对照确认，MobX 的 `onBecomeUnobserved` 可能早于 React 提交完成；此时删除 ID，会让仍引用旧 ID 的 fiber 读取失败。这与本轮 MobX 包精简无关。

当前通过 `FinalizationRegistry` 在环境对象被回收后移除弱索引；保留按 frame 记录、frame uid 隔离和 `frame.dispose()` 的确定清理。清理登记只保留字符串/数值身份，不强持有 frame 或环境；删除完整键时继续核对当前 ID。生产环境不强制 GC。

正常重命名、撤销、重做恢复原值；20 轮重命名/撤销、每五轮诊断 GC，均没有画布错误。第 10/15/20 轮环境 ID 数量均为 694，完整键均为 131，未随该操作持续增长；这不是全项目零泄漏证明。单测验证旧 fiber 的环境在失去观察后仍可读，两个画板隔离，frame 销毁清理旧、新 ID。
