## 已验证的优化方向

1. **App 继续定位项目启动 GET 和编辑器前置启动链。** 暖开库资源已经零网络请求。补充 Web 样本的项目 GET 为 632/674 ms，服务端 dependencies 计时分别为 153/175 ms（新进程样本 216 ms）；修订、权限、owner 分别约 14–39 ms，部分并行。现有 Server-Timing 没覆盖全部启动上下文、事务提交、资源引用生成和传输，不能将剩余接口耗时直接归于依赖模型。下一次代码优化应先补齐这段计时，再针对实际热点改动；不再增加启动请求或上传缓存摘要。
2. **Web 可优先实施带构建标识的 Host HTML 强缓存。** 当前入口 HTML、Host iframe 导航和后续 Host HTML XHR 都是 `no-cache`。补充两轮暖样本中，入口约 216–221 ms，Host 导航约 219–221 ms，后续 Host HTML XHR 约 213–220 ms。导航 transferSize 为 300 B、同时有已缓存正文，说明仍发生条件校验；`fromCache: true` 不等于零网络。应构建不可变、带内容/构建标识的 Host 文件并强缓存，同时复用同一版本的文档读取。普通入口 HTML 保持可更新。节省量需实施后 A/B，不能简单相加承诺；App 对应文件已在本地，不预期同等收益。
3. **普通缩略图外置降为后续冷加载优化。** 本轮暖开库模型已不下载，解包只有几十毫秒；没有证据证明缩略图外置能明显缩短当前 2–3 秒的暖开。图标保持已实施的 SVG 预览。页面按需加载和组件库分包注册仍不在本轮范围。

这些是当前版本测量，不与 0.5.26/修订 146 的旧基线直接计算提升比例。
