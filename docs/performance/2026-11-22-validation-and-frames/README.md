# 模型校验和画板释放实验

2026-11-22，在同一台 macOS arm64 主机上比较基线 `ae1dc31dc` 和修复版 `be3264a33`。计时覆盖内存模型的完整不变量校验。项目读取、初始化和数据库写入均在计时区间之外。每项运行 9 次，前两次预热，以下取后 7 次的中位数。

| 场景 | 基线 | 修复版 |
| --- | ---: | ---: |
| 仓库内桌面入门项目，28 个组件，原始模型 | 173.3 ms | 7.7 ms |
| 合成项目，24 个组件、1,560 个模板节点、300 个 Token、300 个图片资产，原始模型 | 66.2 ms | 10.0 ms |
| 同一合成项目，观察模型并在每轮校验前改名 | 34.1 ms | 32.9 ms |

三组数据的完整校验均通过。观察模型已有查询缓存，本次小幅耗时变化接近单机重复测量的波动。构造非法图片引用的回归测试仍得到原有的保存错误。

## Chromium 内存

依次在 8 个同源 iframe 中挂载 React 按钮、记录模型编辑和选区，再卸载 React、取消节点注册、销毁画板状态并移除 iframe。撤销历史在整个实验中保持存活。通过 Chromium DevTools Protocol 触发三次垃圾回收，检查各文档的弱引用。基线残留 8 个文档，修复版残留 0 个。重建已逐出的画板时，撤销选区重新绑定到新文档，重做恢复编辑后的值。

实验覆盖真实 Chromium 文档、React Fiber、画板运行时和撤销记录。Electron 整个进程的常驻内存及长时间人工编辑未纳入测量。

## 复跑

在此实验分支的 `platform/wab` 中运行以下命令。性能用例也可以复制到基线的相同路径运行，保留同一测试负载。

```sh
node_modules/.bin/vitest run --project studio validation-performance.test.ts --disableConsoleIntercept
node_modules/.bin/vitest run frame-memory.browser.test.tsx
```

功能回归覆盖模型编辑后的索引失效、无效引用、项目合并、代码生成、选区恢复、文本编辑、变体、撤销重做和 PostgreSQL 增量保存。23 个相关测试文件共 219 项通过，合并套件原有 2 项跳过。WAB 完整类型检查通过。
