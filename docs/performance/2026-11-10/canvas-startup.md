# 项目画布启动：调度与永久等待诊断

结论：本轮修复了两个可复现的队列永久等待缺陷，并让活动画板的首次求值按前台任务执行。普通打开的对照受同机并行工作影响，不能承诺固定提速比例。完整脱敏数据见 [canvas-startup.json](canvas-startup.json)。改动在源码中，未替换正常安装版或发布服务。

## 加载慢的具体位置

从 Dashboard 打开包含 10,746 个模型对象、两个初始画板的冻结业务项目。使用生产构建和既有原生加载链路，项目、依赖及组件库均从私有离线夹具读取。以下为基线八个暖打开样本的相邻阶段中位数，阶段中位数之和不必等于总时长中位数。

| 阶段 | 耗时 ms | 含义 |
| --- | ---: | --- |
| 点击 → Studio 模块开始导入 | 543 | 外层入口、启动上下文、Host 文档和桥接 |
| Studio 模块导入 | 106 | 必需模块的加载和执行 |
| 初始化和路由 → 首画板开始加载 | 469 | 项目交接、模型解包、Studio 初始化、组件同步及路由等待 |
| 首画板加载 → ViewCtx 创建 | 190 | Host 文档、运行时和组件库准备 |
| ViewCtx 创建 → 首屏揭示 | 296 | 求值调度、真实渲染、收尾和就绪通知 |

这些阶段包含排队和跨 frame 调用，不能当成各模块的纯 CPU 成本。当前已经存在项目启动合并请求、依赖预取、目标画板优先和后台画板串行加载；本轮沿用这些所有权边界。运行时源码缓存命中也仍需在各 Document 中执行注册。

## 为什么会一直加载

1. `requestIdleCallbackAsync()` 原来用 detached async callback 执行任务，外层 Promise 只有 `resolve`。异步抛错变成未处理 rejection，外层永不结束；同步抛错同样不会结束等待。画板串行加载队列与求值队列都使用它，后续任务和就绪等待因此无法完成。
2. `ViewCtx.syncInternal()` 的 post-eval 阶段同样使用只会 resolve 的 Promise 包裹异步任务。收尾失败后，运行中的求值任务不释放，首渲染标记也不能完成。

现在空闲任务的同步、异步失败均返回原调用方；post-eval 保留原来的任务边界并直接等待收尾。求值队列捕获有效模型生命周期内的失败，通过已有 canvas error 状态和 TopFrame 错误界面报告，队列正常释放；工具就绪等待及时拒绝。取消或旧模型生命周期的晚到失败不污染当前项目。原始错误及堆栈写入已有 Desktop 错误日志。

回归用例覆盖真实空闲调度器中的后台加载失败、求值收尾失败、队列排空、工具错误和首渲染标记。修复前的空闲调度测试产生未处理 rejection 并超时；修复后通过。没有用缩短超时或无限重试掩盖错误。

## 调度优化及实测边界

活动目标的首次求值不再依赖浏览器空闲时机。它继续使用现有求值队列、渲染可见性和模型事务；后续编辑、后台画板仍使用原有调度。

在真实业务画板的实际求值器和队列中，仅重置临时首渲染就绪标记，并把空闲回调延后 1000ms，验证前台任务是否被空闲调度阻塞：

| 条件 | 首次求值完成 ms | 模型变化 |
| --- | ---: | --- |
| 修复前 | 1212.5 | 无 |
| 修复后 | 142.9 | 无 |

这是受控调度验证，保留了实际求值、DOM 和 post-eval；并非实际冷打开，也不代表每次进入项目都能节省一秒。

普通打开按 A/B/B/A 顺序运行，每个进程六次打开，排除前两次预热；共 24 次打开、16 个计时样本。所有组都保留：

| 组 | 首屏揭示中位数 ms | 全部初始画板渲染中位数 ms |
| --- | ---: | ---: |
| A1 | 1553 | 2239 |
| B1 | 1738 | 2513 |
| B2 | 1489 | 2138 |
| A2 | 1651 | 2371 |

合并中位数为首屏 1604 → 1524ms、全部画板 2314 → 2200ms，但组间波动明显，且同机其他聊天正在运行测试及其他应用负载，**不以合并差值宣称稳定提速**。各进程记录的同一条 Babel 大文件代码生成提示单列在 JSON 中；没有将它当成业务异常或删除样本。受控验证解决的是忙碌时的首求值等待，错误回归解决的是失败后的永久等待。

## 服务端边界

正常 Desktop 日志有列表 GET `/projects?query="all"` 的 502/504，以及部分状态为 0 的请求失败。它们证明曾有网关或请求可用性问题，但没有与同一画布启动卡住样本关联的网络记录，不能直接认定就是本次画布问题的服务端根因。离线测量不包含线上 IAM、API、WebSocket 或业务后端，客户端修复也不代表这些服务问题已解决。

- 最终核心回归 20 项、相关就绪/视口/初始化/销毁回归 35 项通过；WAB `tsc --noEmit`、改动文件 ESLint 和生产 Studio 诊断构建通过。
- 独立 Electron GP 项目完成画板渲染、页面和节点重命名、真实样式/位置编辑、撤销重做、完整保存及重开一致性；Preview 表格渲染并正常返回，模型未变化。全部请求使用离线后端，没有线上项目写入。

私有源快照、构建、完整计时、功能报告及测试日志在 `/tmp/plasmic-canvas-startup-20261110/`；项目正文、账号资料和 profile 不入仓库。构建冻结相同源码，仅替换本轮三个运行时文件，避免其他聊天的并行 UI 修改混入对照。计时后的最终源码仅追加错误日志和局部变量改名，并重新构建验证。
