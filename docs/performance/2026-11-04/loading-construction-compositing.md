# 构造阶段的主线程与流畅度对照

2026-11-04。保留线框、沿路径流动、渐变填充及等待流光。**动画自身的主线程工作显著减少，构造能在主线程阻塞时继续推进；GP 整体加载没有提速，合并对照约增加 54ms。** 本轮不能称为业务初始化长任务已经消除。完整脱敏数据见 [JSON](loading-construction-compositing.json)。

## 实现与取舍

运行时不再创建六条动态 SVG 描边，不再注册 requestAnimationFrame，也不再逐帧修改 SVG 遮罩、渐变 stop 或透明度属性。构造的彩色轨迹与填充由 Chromium 原生播放透明 WebP，SVG 只保留静态、随主题变化的线框，并对 SVG 根做原生透明度动画。等待流光沿用上轮已验证的独立 HTML 图层。

`desktop/scripts/generate-brand-loading.cjs` 从共享 branding 路径和渐变按原算法采样 193 帧，使用 Chromium 光栅化、无损编码，生成一次播放、3192ms 构造的资源。WebP 编码可合并相同帧；200px 资源对应默认约 100 CSS px 的 Logo，在 2× 屏幕下使用。更高缩放会重采样。

生成命令：`desktop/node_modules/.bin/electron desktop/scripts/generate-brand-loading.cjs`。当前资源 `brand-loading-construction.7a0ad6b7c6c3.webp`，550418 字节（约 538KiB），随客户端本地打包。没有引入视频运行时、Worker 框架或远程动画服务。

Chromium 会共享同一图片 URL 的动画进度，直接复用已播放的 WebP 会停在结尾。因此每次加载从同一带内容指纹的资源取得 Blob，并创建独立 Object URL；卸载或减少动态效果切换时中止请求、移除图片、释放 URL 并取消原生动画。加载失败时显示完整静态 Logo。减少动态效果设置下不请求动画资源。

Chromium 的 [合成架构说明](https://chromium.googlesource.com/chromium/src/+/lkgr/docs/how_cc_works.md)描述了独立的图像解码和动画阶段；本轮仍以实际画面捕获验证，未仅凭“原生动画”或图层原因认定其独立于主线程。

## 加载差异的补充归因

统一两轮、每侧 16 个暖样本后，顶层最大长任务中位数为 **323.0→347.5ms**。先前聊天及本文最初版本引用了首轮每侧 8 样本的 327.5→343.5ms，与首画布指标的合并口径不一致；本表已修正，原始 JSON 中的合并数值保持不变。

原对照各阶段时长中位数如下。嵌套阶段和各样本中位数不能直接相加归因总差值。

| 阶段 | A | B | 差值 |
| --- | ---: | ---: | ---: |
| Studio 模块导入 | 90.75ms | 91.35ms | +0.60ms |
| 项目 fixture 读取 | 33.20ms | 32.50ms | −0.70ms |
| 画板初始化 | 273.70ms | 282.05ms | +8.35ms |
| GP 首次渲染 | 358.75ms | 382.60ms | +23.85ms |

新增成本包括本地动画读取、Blob、原生图片解码与合成；独立文档的 TaskDuration 降低没有统计后台解码和 GPU 的全部工作。现有证据把差异主要定位到画板初始化及首次渲染阶段，没有证明 Studio 首次导入或接口变慢是主因。

为进一步排查，复制已测 B 诊断构建，仅将 BrandLoading 的 start 改为执行既有 stop/showStatic 后返回；修补入口模块、顶层 HTML 和两份内嵌 Studio HTML 的对应分支，保持其余 JS、资源、组件及全局减少动态效果偏好不变。该诊断副本位于 `/tmp/plasmic-opt-20261104/build-construction-static`，未修改源码、已安装 App 或发布产物。按 on/off/off/on 四个独立进程运行，仍为每进程六次打开、前两次预热。

| 同一 B 构建的开关对照，每侧 8 个暖样本 | 动画开启 | 加载 Logo 静态显示 |
| --- | ---: | ---: |
| 首画布中位数 | 1652.85ms | 1584.10ms |
| GP 首次渲染时长中位数 | 403.80ms | 357.05ms |

## 关闭动画与旧版的同轮直接对照

此前把旧版首画布 1560.25ms 与另一个轮次的新版静态 Logo 1584.10ms 相减，得到 +23.85ms。该数值只是跨轮次观测差，不能据此认定关闭动画后仍有稳定代码退化。两次静态 Logo 进程的中位数分别为 1696.05 / 1557.25ms，进程间漂移已明显大于 23.85ms。

为直接检查这一点，另按旧版/新版静态/新版静态/旧版串行运行四个进程，每进程六次打开、前两次预热。每侧八个暖样本，无 debugger、trace、构建、测试或采样并行。结果：

| 首画布加载中位数 | 原构造动画 | 新构建关闭加载动画 |
| --- | ---: | ---: |
| 进程 1 | 1644.45ms | 1561.70ms |
| 进程 2 | 1581.15ms | 1613.10ms |
| 暖样本合并中位数 | 1616.00ms | 1562.05ms |

同轮合并差值为 −53.95ms（约 −3.3%），方向与先前跨轮次 +23.85ms 相反；两个进程对之间同样有方向变化。这不支持“关闭动画后存在稳定的 +23.85ms 额外成本”，也不建立严格等价或稳定提速。现阶段更合理的解释是不同轮次与进程漂移影响了那次中位数差；未控制的系统负载、缓存和调度各占多少仍未确定。

此结果仅针对关闭动画后的诊断副本，不证明新版动画开启时没有额外成本。四个进程有效 renderer error 为零，既有缩略图 fixture 错误单列保留。原始文件为 `gp/list-open-old-static-{A,B}{1,2}.json`，日志位于 `/tmp/plasmic-construction-20261104/old-vs-static.log`。已安装客户端及其动画设置未修改。
