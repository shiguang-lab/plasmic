## 对照范围

macOS arm64、Electron 45.2.1；使用同一冻结源码、GP 单画板与复杂十画板的真实离线载荷和精确依赖。对应安装版为 0.6.6 / `cc50fd519d0df382f0657afbfe6b977528155898`。生产 StudioWindow、隔离 profile 和诊断 preload；不接触正常 App profile，不保存线上项目。

每个独立进程打开六次，前两次预热、后四次统计。三组正式实验共 **144 次打开、96 个计时样本**：动画 ABBA；导入/槽位候选按 L/M/R/R/M/L；Fiber 按 ABBA。构建、单元测试、trace、首次使用与正式计时分轮串行执行。正式轮无 debugger、trace、定时内存采样或强制 GC。所有有效轮 renderer error 为零，返回时的旧 Studio PID 释放断言通过。

初轮发生过 frame 销毁、超时和异常长的进程运行，整轮不纳入正式对照；原始结果保留。补测使用防休眠及前台窗口，并在首次失败时停止。未控制其它 App、系统文件缓存及热状态，样本也未随机化；不声明统计显著性、跨机器速度比例或线上 SLA。每个计时进程另有 7 次已有缩略图 fixture `undefined.map` 错误，两侧相同、单列保留，不作为缩略图功能验收通过。

“首画布揭示”是内部标记，不是屏幕合成完成或 OS 输入延迟。外部观察仍包含轮询延迟；离线回放不包含真实 API/IAM、Socket、草稿 IPC 和业务后端。

## 1. 轻量动画的实际收益

比较同一源码构建的旧动画与工作区已有轻量动画，保留真实动态效果，没有使用静态 Logo 替代候选。

| 指标，中位数 ms | 旧动画 | 轻量动画 |
| --- | ---: | ---: |
| GP 首画布揭示 | 3445 | 1637 |
| GP 全画板标记 | 3464 | 1656 |
| 十画板首画布揭示 | 3198 | 1490 |
| 十画板全部渲染 | 5601 | 3909 |

旧动画在每条轨迹上创建 56 个碎片，逐帧采样和改写 SVG 路径。现有修改使用六条固定路径的原生动画，有限时长 JS 更新完成后只保留 shimmer。两个版本均从同一冻结源码构建，旧版只还原 HTML、BrandLoading 及动画函数，未使用不同历史包拼接成绩。

实际 Chromium 探针读取构建产物中的 HTML Logo，并执行实际动画源码：3500ms 后构造结束、碎片移除；继续等待仍有 shimmer；全程 `getPointAtLength` 调用为零；清理后无运行中动画；切换到 reduced-motion 后保持静态完整 Logo。已查看长等待截图。最终探针 2.5 秒观察窗口的 Document TaskDuration 约 152ms，包含该文档的其它浏览器工作；不是 JS 循环独占成本、进程 CPU 百分比或内存收益，也没有以该单次结果做旧/新 CPU 对比。

## 2. Studio 首次导入

匹配 source map 的独立 trace 确认，AiMarkdown 静态依赖的 Refractor 全语言初始化仍位于 Studio 导入阶段。此次将原实现移入 `AiMarkdownContent.tsx`，保留 XMarkdown、Highlighter、公式、所有语言及原有组件契约；没有裁剪语言或更换解析器。

`AiMarkdown.tsx` 共用一个加载 Promise；首画布就绪后通过现有 idle 调度预载，Studio 销毁时取消尚未执行的 idle 请求。已预载时，新消息同步挂载；冷挂载复用现有 Loadable，以安全文本显示最新内容，并支持其原有失败/重试流程。冷挂载完成后保持同一组件分支，避免后续流式更新重新挂载并丢失复制、全屏等局部状态。预载失败不会强制刷新页面，真实展示可再次加载。

| 指标，中位数 ms | 轻量动画基线 L | 加导入优化 M |
| --- | ---: | ---: |
| GP Studio import | 201 | 91 |
| 十画板 Studio import | 196 | 95 |
| GP 首画布揭示 | 1764 | 1549 |
| 十画板首画布揭示 | 1518 | 1442 |
| GP 全画板标记 | 1784 | 1569 |
| 十画板全部渲染 | 4054 | 4123 |

模块段下降约 100–110ms 是直接对应的变化；整页数字还有运行间波动，不能把全部差额归因于模块执行。**十画板全部渲染没有提速，观察值增加约 69ms。** 预载移动了必要成本，并未消除它；此处保留首画布和首次消息体验的取舍，不宣传全部画板同时变快。

首次使用探针在完整画布就绪后展示实际消息，包含原生 UI 挂载及 16ms 观察：基线首次 Markdown 89.5ms、仅导入候选 81.2ms、最终资源 84.2ms；暖使用分别 32.2 / 30.5 / 30.5ms。每个版本一次独立探针，不能当作分位数。若在空闲预载完成之前请求消息，仍需承担冷加载并短暂显示安全文本；本次没有证明所有请求时机下都无等待。

首次使用功能覆盖表格、公式、原始 HTML/外部图片保持惰性、完整代码高亮、节点定位、复制、全屏、流式完成、主题、共享 Scrollbar、重开和代码片段。最终构建全部通过，没有把成本转成此前约 196ms 的同类首次使用结果。

## 3. GP 首次渲染

独立 profile 将剩余工作定位到槽位内容求值、CanvasObserver 和 React 提交后的 Val 树处理，而非基础 runtime 下载。先试验了消除槽位环境重复深合并：GP 首次 render 中位数 356.6→367.8ms、揭示 1549→1583ms，没有独立收益，因此实现、辅助函数及对应测试均从工作区撤回，不进入最终代码。

最终只保留一项局部改动：`mergeValsInSubtree` 对单个子 Fiber 复用已有 Val 数组。该数组在此路径只读，原 `flatMap` 只复制数组而不复制其中节点，因此可以省去每层单子节点的一次分配；多个子节点继续使用原路径，没有跨查询缓存或新增生命周期。

| 独立 GP ABBA，中位数 ms | 仅导入优化 | 加单子节点复用 |
| --- | ---: | ---: |
| 首次 render | 366.35 | 360.70 |
| 首画布揭示 | 1583.00 | 1564.05 |
| 全画板标记 | 1602.60 | 1583.25 |

**收益很小。** 首次 render 约少 5.7ms；两组独立进程、每侧八个暖样本，仍有明显环境波动，不能据此认定稳定的端到端百分比提升。保留理由是省去已确认不必要的分配、改动局部且功能一致，不宣称已解决 GP 剩余数百毫秒的渲染成本。
