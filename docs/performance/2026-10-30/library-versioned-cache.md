# 组件库独立发布与本地缓存

状态：源码及隔离验收通过；未发布生产服务、组件库或 App，未替换已安装 App。画布性能 A/B 和完整业务操作回归待配套环境验收。

## 当前实现

- 删除桌面本地构建的 `localCanvasLibraries` 覆盖。Antd6、Icons、Overseas、React UI 均按项目依赖中的包 ID 和精确版本加载；消费场景缺少依赖版本时报错，不请求 latest，不返回安装包代码。
- 库自身编辑/注册场景先通过 `/hostless-libraries/:name/release` 解析具体版本，再走相同制品加载路径。普通组件库发布继续使用已有 `publish-library.ts`，模型和代码在同一事务内保存；不要求重新构建 App。共享 React/Antd 和新增编辑器协议能力仍属于 App 更新范围。
- 修复 `getPkgVersionByProjectId` 的 latest 选择：使用现有版本解析器，避免无序数据库结果的最后一条被当成最新版。平台库自动升级的范围、大版本策略、已打开编辑器刷新提示、普通设计库接受更新和网站重发规则保持现状。

## 存储和网络契约

`desktop/src/library-cache.cjs` 只缓存版本化代码正文和依赖模型内容。目录按 Studio 来源、账号、实际 renderer 构建哈希隔离，代码键另包含库路径、包 ID 和精确版本。服务端返回独立浏览器源码 SHA-256，客户端核对包/版本及正文摘要；已有整份制品 digest 仍供发布器使用，不冒充浏览器源码摘要。

命中代码直接读磁盘，零网络校验；未命中通过现有认证下载。同一认证代次的并发 GET/HEAD 共用下载，错误、HTML、版本错配及不完整响应不入缓存。认证刷新后，新请求使用独立任务，不等待旧代次下载，也不会因旧任务失败而失败。缓存封装校验覆盖键、响应头和正文，临时文件原子替换；全局预算 256 MiB，优先淘汰未使用内容，活动读取/下载受保护。账号变化使未完成操作失效；退出清理全部组件库资源缓存，包括先前进程留下的账号/构建命名空间，不删除业务草稿。

模型使用**同一次项目/包请求内的内容协商**，不新建快照下载服务或保存整个业务项目：

1. 主进程使用项目/包 API 的只读 POST 入口，保留原 URL 查询参数和请求来源；`X-Plasmic-Model-Cache: 1` 只标识协议，JSON 正文的 `modelDigests` 提供全部已缓存摘要，不截断，也不占用 HTTP 请求头预算。库存受本地磁盘容量约束。
2. 服务端按原流程检查权限、取得修订并完成迁移/自动升级，然后计算各依赖模型 JSON 的 SHA-256。
3. 返回 `modelSnapshots` 清单、完整包元数据及缺失的模型正文；已知摘要省略模型正文。主进程从磁盘补齐后移除清单，交付编辑器原有完整响应契约。
4. 项目修订、权限、owner、版本选择结果始终取当前服务端响应。相同 semver 下迁移后内容变化会产生新摘要；跨项目可共享相同内容。
5. 损坏/淘汰发生在报告摘要之后时，再请求一次不带已知摘要的授权响应。失败不使用旧项目数据兜底。

项目/包请求明确绕过 HTTP 缓存，防止旧代理响应冻结修订或权限。磁盘缓存不可写时继续使用已授权的下载内容，后续可重试保存；缓存清理失败不会阻断退出登录。

该协议覆盖项目打开、增量更新、历史修订以及按包/项目取库版本；只读 POST 复用原读取处理器和权限检查，并经过现有 Origin 校验。常规 GET 仍获得完整模型。私有资源已授权下载后不再逐次资源鉴权，不能远程收回已下载文件；项目访问仍受服务端权限约束。

## 已执行验证

- Desktop：494 项 Node 测试通过，包括认证刷新期间的新旧并发请求、超过 64 份模型的重启/跨项目复用，以及原身份、草稿、资源路由回归。
- WAB：8 个相关 Vitest 文件 75 项通过，包括来源校验、160 份摘要完整协商及无效正文拒绝；类型检查通过；新增服务端文件及发布端到端脚本 ESLint 通过。
- 实际 Electron/Chromium：沙箱 renderer 经自定义 HTTPS 协议读取 gzip 网络响应，160 份缓存摘要以超过 8 KiB 的 POST 正文传递。更换页面文档和全部缓存实例后，代码只下载一次，项目修订继续更新，模型正文只传一次。
- 临时 PostgreSQL 的真实 npm tarball 发布 → 包/代码 HTTP 路由 → Desktop 磁盘缓存端到端通过。两个发布版本的代码、Props、Slots 一致，组件 UUID 保留；同版本重开和切回旧版本均零代码请求、零已缓存模型正文。单库示例的包响应从 13,378 B 降至 968 B；这是测试库的逻辑 JSON 大小，不是业务项目收益。
- 独立临时数据库的平台库自动升级端到端通过：删除参数检查、保留有效设置、开启后迁移、下一次加载自动升级及新库自动加入平台工作区。

命令、测试计数和线上只读制品核查保存在 [验证记录](library-versioned-cache.json)。所有测试数据库和临时用户目录均与生产隔离；不以隔离测试代替正式 App 画布验收。

## 线上核查与发布前提

只读核查时 `autoUpgradeHostless=true`，平台工作区已配置，四库目录均有 `hasCodeArtifacts=true`。现有最新版代码均可下载：Antd6 3.9.0、Overseas 1.12.0、Icons 0.2.0、React UI 0.2.0。

发布历史中 Antd6 有 16 个早期版本缺代码制品，Overseas 有 6 个。自动升级不会删除历史版本；这些缺口不等于当前项目仍使用低版本，也不阻止消费者按既有规则升级到有制品的最新版。明确请求缺失历史制品时仍失败，不能拿最新源码伪造历史实现。核查只证明下载可用性，不能证明每个历史模型与当时源码完全一致。

上线需一次部署配套服务端和更新 App；之后既有运行时能力内的组件库更新独立发布。当前本地已修改、尚未发布的组件库功能必须先形成对应远程制品，再切换真实项目验收，不能依赖本地 App 暗中覆盖。完成画布、属性面板、Preview、Form/Table/Tabs、主题与弹层回归及固定条件的重开 A/B 后，才报告真实业务项目耗时收益。
