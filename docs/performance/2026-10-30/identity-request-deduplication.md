# 主进程统一身份校验

日期：2026-10-30。状态：本地签名打包、安装及功能验收通过，已安装 0.5.26 本地构建，尚未发布生产版本。

## 加载契约

主进程为当前 Studio 来源和 Electron Session 创建唯一的 `DesktopIdentity`。灵动岛和本地草稿均调用它读取身份，不接收 renderer 自报身份作为授权依据。并发读取共用正在进行的校验；稍后打开草稿可复用同一会话下已通过服务端验证的身份。

身份仅在内存保存，最长 30 秒。每次读取先经过 IAM 会话恢复检查；主窗口新文档导航丢弃已完成的身份结果，但保留同一会话正在进行的校验；同文档内的画布路由变化复用验证结果。失败或未登录结果不缓存，允许重新请求。账号统计保留原有 30 秒轮询间隔，工作区切换仍单独刷新统计；项目权限、最新修订和 bootstrap 请求保持原有链路。

受信来源的 HttpOnly Cookie 变化、登录开始/结束、退出开始/结束、设备授权被撤销时，统一作废身份和进行中的旧任务。相关 Cookie 监听从灵动岛收敛到身份服务；迟到的旧身份不能重新填入缓存。Studio API 返回 401 时也会清除已完成的验证结果。登录/退出过程中禁止从缓存授权。

草稿句柄按身份代次授权。身份变化后，下一次访问必须重新验证当前用户；确认仍是同账号则继续当前草稿会话，避免 Cookie 轮换打断编辑。其他账号无法使用旧句柄。打开、列举及读取草稿的异步结果也检查代次，变化后不返回旧数据。没有身份变化时，已授权句柄的本地读写仍无需联网；导航重建文档继续清除旧句柄。

## 请求来源与实测

源码阶段记录见 [验证数据](identity-request-deduplication.json)，完整安装包和实际 App 的最终验收见 [本地验收结果](identity-local-acceptance.json)。同一「客服平台 · GP评论查询」修订 158，使用 Electron 44.5.1、固定安装包快照和隔离配置，分别验证首次进入及从 `about:blank` 重新进入。

修改前的四次 `/api/v1/auth/self` 均由主进程发起：三次来自灵动岛，一次来自草稿打开时的账号校验。灵动岛的导航监听反复调用 `invalidate(false)`，清掉未完成的 Promise，随后重复请求。当前项目的 Studio 启动身份信息由合并的 bootstrap 提供，不能将这四次都归因于 React 启动请求。

| 阶段 | 修改前 | 修改后 | 草稿打开 |
| --- | ---: | ---: | --- |
| 首次进入 | 4 | 1 | 复用主进程已验证身份，正常启用 |
| 重新进入 | 4 | 1 | 复用本轮已验证身份，正常启用 |

上表只统计 `/api/v1/auth/self`。模型 bootstrap 仍含身份和权限数据，不代表所有认证相关请求总共只有一次。超出有效期、会话或账号变化后需要重新校验，不保证任意项目、任意导航都固定一次。

对照的修改前使用固定安装包快照中的 `app.asar`；修改后保留同一包资源，在诊断进程中加载工作区六个相关主进程模块，模块路径和实际加载的 SHA-256 记录在 JSON 中，没有替换签名 App。诊断关闭自动保存并拦截项目写请求，运行时错误及项目写请求均为 0；两次草稿打开均成功，项目保留修订 158、修改计数 0、977 项注册及 848 个图标。隔离配置已删除。
