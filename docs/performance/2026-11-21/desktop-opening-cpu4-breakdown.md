# 普通项目打开时的 CPU 降速分段

同一份 33 页普通项目、9 张初始画板，Desktop 编辑器 WebContents CPU 降速 4 倍，项目接口固定加 1 秒。下文的“回包”沿用前次口径，指本机回放服务备好主响应。将请求时间与编辑器内的 `canvas-revealed` 对齐，可以复原前三次打开的首屏时序。[前次对照](desktop-opening-prefetch.md) · [分段数据、各画板时间和 trace 样本](desktop-opening-cpu4-breakdown.json)

## 回包到首张可见

原始三次分别为 3,019、3,336、3,471 ms。下表取中位数对应的第二次。区间连续、互斥，取整后合计 3,336 ms。

| 区间 | 墙钟耗时 | 观察 |
| --- | ---: | --- |
| 主响应就绪 → Host 开始导入 Studio | 421 ms | 顶层启动数据交接和 Host 启动均落在此区间。Host 文档从本地读取约 1 ms，依赖模型命中本地缓存。 |
| 导入 Studio 模块 | 396 ms | 补采的采样栈集中在打包器执行模块的调用链。 |
| 导入结束 → 项目和依赖模型解包完成 | 308 ms | 其中 270 ms 位于模型解包，剩下 38 ms 包含偏好和项目读取。 |
| 解包完成 → 开始同步代码组件 | 235 ms | 其中创建 Studio 上下文用 92 ms。 |
| 等待代码组件同步完成 | 467 ms | 补采时该窗口有大量 React 挂载、提交工作，不能将整段归给同步算法。 |
| 同步完成 → 首张开始初始化 | 355 ms | 约 196 ms 到初始路由就绪，再过约 159 ms 开始加载目标画板。 |
| 首张开始初始化 → 画板上下文建好 | 406 ms | 其中 Host 文档阶段 156 ms，组件包阶段 83 ms。 |
| 画板上下文建好 → 首次渲染完成 | 337 ms | 包括首次求值、渲染和后处理。 |
| 首次渲染完成 → 画布可见 | 411 ms | 已保存视口还在恢复。整段视口布局等待 169 ms、提交和等待生效 321 ms，其中部分与首次渲染重叠。 |

最后三行合计 1,154 ms。首开使用新用户目录，首次渲染完成后 72 ms 就显示。第二、三次复用保存的视口，这段分别为 411、418 ms。视口恢复含动画帧或定时器等待，父级 `initial-viewport` 也覆盖路由与首画板等待。[视口恢复逻辑](../../../platform/wab/src/wab/client/studio-ctx/StudioCtx.tsx) · [编辑器启动](../../../platform/wab/src/wab/client/components/studio/studio-initializer.tsx)

## 首张可见到其余八张就绪

原始三次分别为 4,880、4,576、4,571 ms。Desktop 原始打开日志在 Studio 就绪时结束。使用相同构建、模型、入口和降速设置，另外跑了三次，从 Studio 读取全部画板埋点。这三次分别为 5,972、5,601、5,597 ms。以下采用中位数所在的第二次，各行沿墙钟互斥，保留一位小数。

| 区间 | 8 张合计 | 占比 |
| --- | ---: | ---: |
| 首张可见 → 第二张开始初始化 | 1,009.7 ms | 18% |
| 后台画板依次初始化各自的 iframe | 2,455.6 ms | 44% |
| 各画板初始化结束 → 首次求值开始 | 约 518 ms | 9% |
| 各画板首次求值、渲染、后处理 | 1,210.6 ms | 22% |
| 一张渲染完成 → 下一张开始等间隙 | 约 407 ms | 7% |

8 张画板的单张初始化为 264–340 ms。2,456 ms 初始化里，组件包准备占 777 ms，Host 文档占 467 ms，画布运行时占 282 ms，Host 就绪占 156 ms，各阶段间的工作合计 773 ms。相邻画板的初始化按队列逐张执行。三轮中初始化合计均在 2.44–2.51 秒之间。[画板初始化队列](../../../platform/wab/src/wab/client/studio-ctx/StudioCtx.tsx) · [各 iframe 的运行时和组件包](../../../platform/wab/src/wab/client/components/canvas/canvas-ctx.ts) · [首次求值与后处理](../../../platform/wab/src/wab/client/studio-ctx/view-ctx.ts)

### 首张刚显示后的主线程工作

另外一次仅用于 CPU 归因，开启 Chromium trace 后，第二张等待 1,183 ms 才开始初始化。首张可见后第 578 ms，主线程开始执行 Markdown 高亮依赖所在的 JS 包，连续占用 584 ms，直到第二张开始前约 21 ms。CPU 采样在这段等待中有约 510 ms 落在 `refractor.register` 的调用栈内。代码会在首张就绪后通过空闲回调预加载 AI Markdown，后续画板也通过空闲回调取得初始化机会。还观测到了滚动条初始化和依赖模型处理。这轮 trace 的全段为 6.73 秒，单独用于识别执行内容。[预加载入口](../../../platform/wab/src/wab/client/components/studio/studio-initializer.tsx) · [高亮组件依赖](../../../platform/wab/src/wab/client/components/copilot/AiMarkdownContent.tsx)

## Agent 面板按需加载后的复测

两组都使用主数据接口提前的版本，普通项目 33 页、9 张初始画板，编辑器 CPU 降速 4 倍，主数据接口额外等待 1 秒。Agent 面板保持关闭。每个版本开 3 次，以下取同一进程内的第 2、3 次复开进行配对比较。旧版第一轮与单元测试短暂重叠，作为预热排除。

| 复开轮次 | 首张可见，原预载 → 按需加载 | 首张到全部就绪 | 点击到 9 张全部就绪 | Markdown 高亮包请求次数 |
| --- | ---: | ---: | ---: | ---: |
| 第 2 次 | 4,850 → 4,550 ms | 4,920 → 4,280 ms | 9,770 → 8,831 ms | 1 → 0 |
| 第 3 次 | 4,690 → 4,614 ms | 4,826 → 4,301 ms | 9,515 → 8,915 ms | 1 → 0 |

首张之后的等待分别减少约 640 和 525 ms。预载原本在首张就绪后触发，首张之前的差值含运行间波动。以上为本机离线回放。
