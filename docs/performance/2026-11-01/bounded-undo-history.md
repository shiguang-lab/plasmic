# 有限撤销历史：100 步阶段的 A/B 记录

日期：2026-11-01。本报告保留 100 步阶段的测量与验收记录，共最多 101 条内部记录。用户随后明确要求[固定最近 50 步](undo-history-50.md)，当前源码已调整；下文的 100 步数据不能当作 50 步策略的测量。[本阶段脱敏逐进程数据、功能结果、压力轮与源码哈希](bounded-undo-history.json)。

## 保存与恢复契约

- 会话撤销用于最近编辑；一次已有分组交互仍是一步，不拆分拖动，也不跨用户命令压缩。
- 超出窗口只移除 UndoLog 对旧记录的引用。未保存的 `_changeRecords`、当前交互缓冲和保存计数保持原样；保存失败或离线时不能丢弃这些内容来降低内存。
- 起点记录保留边界视图，但其 `changes/newInsts/removedInsts` 必须为空，否则仍会持有已经不能撤销的旧模型。用新的空变更对象替换，不能原地清空与保存缓冲共享的数组。
- 最旧保留状态之后不能继续 Ctrl+Z，这是本次明确授权的功能边界。更早状态只能从实际存在的已保存版本恢复，自动保存不是每步快照。
- 本项目的自动修订列表接口当前每次最多取 50 个，并按最近发布版本过滤；不能把它说成任意旧步骤都永久可恢复。源码另有旧修订清理工具，其部署执行情况未在本轮核实。没有修改这些服务端策略或请求职责。

## 功能验收

新增单测覆盖连续滚动、最旧状态、全部重做、撤销后新分支、纯选择不丢重做、交互分组、`noUndoRecord` 合并、待保存事件完整以及边界记录不持有旧变更。与既有冷恢复、样式、多画板、MCP、动画操作及模型测试合计 **11 文件、167 项通过**。

两侧均使用实际生产模式 Studio、独立 profile、离线 HTTP fixture。原版保留无限历史；候选为 100 步。两侧都保留之前的样式缓存修复，并使用相同的变体面板生命周期修复。

- 重复实例/clone key、Slot owner/Param、三层嵌套目标变体/pins/default Slot，分别先追加 120 次编辑触发滚动，再检查原有真实编辑的撤销重做；候选各检查点均为 101 条记录。
- 驱逐画板后冷恢复、UI/MCP 删除后的节点身份与选择恢复、双画板样式与实际 DOM computed color、位置和选择恢复均通过。
- 全量客户端保存、重新载入后的组件/Slot/变体/节点/位置读回相等。
- 保存 `SavedCheckpoint` 后再记录 125 次编辑；候选能完整撤销/重做最近 100 步，最旧状态为 `Later24`，不能再撤销。随后通过实际 `StudioCtx.revertTo` 请求和载入路径恢复 `SavedCheckpoint`，恢复后可继续编辑。
- 上述最终两轮均无 Studio 或浏览器 console 错误。离线服务模拟修订存取和恢复协议，没有验证真实数据库权限、事务、修订保留策略或线上网络。

版本恢复首次探针没有观察重新载入后尚未挂载的嵌套组件；已按真实修改调用方的契约显式观察，另检查 125 次编辑确实产生 125 条记录。后续两侧均复现了既有的旧 ViewCtx 销毁后面板创建变体控制器的错误；工厂现在拒绝为显式传入的已销毁 ViewCtx 创建控制器，两项回归测试通过。失败探针均未计入通过或性能样本。

## 正式 A/B

两侧各三个全新 Electron 进程，独立 profile，按无限/100 步/100 步/无限/无限/100 步交错串行。两侧都保留样式缓存修复，唯一性能变量是撤销步数。每进程执行 600 条命令，即 300 轮 121 节点子树添加/深删。全部保存前两侧均有 600 条待保存记录；保存后均为 0，活动子节点均为 120，组件缓存规则均为 121。

| 指标 | 无限历史中位数 | 最近 100 步中位数 |
| --- | ---: | ---: |
| 保存前 GC 后 JS 堆 | 371.91 MiB | 371.41 MiB |
| 保存后 GC 后 JS 堆 | 372.02 MiB | 141.10 MiB |
| 保存后堆范围 | 372.02–374.71 MiB | 141.02–141.21 MiB |
| 历史记录，含视图起点 | 601 | 101 |
| renderer 累计 TaskDuration | 11.76 s | 11.53 s |
| 撤销/重做至画板就绪的合并 p95 | 107.87 ms | 103.55 ms |

保存后减少 **230.92 MiB，约 62.07%**，达到此前至少 10 MiB 且超过 5% 的内存门槛。保存前两侧接近，证明没有依靠丢弃待保存事件取收益。CPU 约 1.94% 的差异处于本轮进程间波动范围，不能宣称明确 CPU 改善；没有看到明显回退。延迟含轮询、调度及诊断 IPC，亦不能将 4.32 ms 差异当成可靠的用户感知提升。

每侧 120 次延迟采样来自三个独立进程，不能当成 120 个独立样本；p95 使用最近秩法。正式计时未与构建、类型检查、其他测试或快照并行。沿用之前的 Mac16,1 / 24 GiB / arm64、Electron 44.5.1，使用完整生产模式 renderer 与匹配资源。

另外一个新进程执行 **1,800 条命令**，保存前待保存记录为 1,800、GC 后堆 925.71 MiB；保存完成后待保存记录为 0、历史仍为 101 条，堆为 **141.46 MiB**。随后逐位置执行最近 100 次撤销及 100 次重做，模型、最旧边界、最终记录数均正确，无 Studio 错误。这一固定大小场景的保存后占用与 600 条命令时接近；单轮压力检查不是独立的三进程 A/B，也不是所有项目的固定内存承诺。诊断释放历史后的数值不计入产品收益。

最终源码检查：11 文件 167 项 Vitest 通过，`pnpm --dir platform/wab typecheck` 通过，两个隔离生产构建成功，候选直接读取当前源码而不注入替换文件；五个 CJS 脚本 `node --check` 和相关文件 `git diff --check` 通过。生产变更只涉及 UndoLog 截断和已销毁 ViewCtx 的变体控制器入口；诊断脚本按新上限检查实际边界，没有关闭或跳过错误。

## 测量边界

正式 A/B 与功能轮、构建、类型检查、堆快照分开。JS 堆不是整个 App RSS 或 GPU 内存；100 步不是固定 MiB 上限，单个大操作仍可能占较多内存。未保存事件必须保留，保存失败/离线期间内存仍可能增长。首次画布加载、主进程 CPU、进程 RSS 收益未在本轮测得。

诊断入口和版本服务模拟仅存在于 `desktop/tests/performance/`。没有新增生产依赖或采样器，没有更改版本恢复接口、发布调试入口、账号隔离、组件库发布升级或资源缓存预算。
