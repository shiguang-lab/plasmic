# 撤销相关缓存：修复验收错误后的 A/B

日期：2026-11-01。性能对照使用相同的功能修复基线，唯一变量是已删除 VariantSetting 的样式缓存清理；没有启用快照共享、标量压缩或冷历史。缓存清理已按独立 CPU 门槛保留为正式源码实现，未提交或发布。本报告修正[上一轮候选验证](undo-candidates-validation.md)中的未定位功能失败。[脱敏逐进程数据、功能结果和源码哈希](undo-functional-qualified-ab.json)。

本文记录设上限前、两侧都保留完整 600 步的缓存 A/B。用户随后授权有限历史，当前源码已采用[最近 100 步策略及独立对照](bounded-undo-history.md)；不要将本文的无限历史内存值当作当前策略的值。

## 已确定的失败原因

| 原因 | 证据与处理 |
| --- | --- |
| 测试 Slot 缺少 base VariantSetting | 原脚本直接调用低层 `mkSlot`，没有执行真实创建路径的变体初始化。删除在模型修复阶段抛出 `Tpl should have base variant`，没有记录删除；随后 undo 撤销的是之前的变体设置创建。修正测试模型，并在执行前及删除恢复后检查 Site invariants。 |
| 测试 Accent 变体没有合法归属 | 原脚本将无 group、无 selectors 的变体直接加入 Component。模型预检报 `Expected style variant`；改用实际 TplMgr 创建变体组和变体。 |
| 等待条件不覆盖排队的编辑和其他 frame | `awaitStudioReady` 等待活动画板，不代表所有 frame 和排队的选择修改均完成。功能脚本先等待模型队列及渲染同步，再断言各画板实际样式。 |
| 原版冷恢复的变体栈初始化错误 | 新 ViewCtx 在首轮 val tree 建立前已有三层恢复栈，`buildViewCtxPinMaps` 却将它与仅一项的 `[null]` strictZip，触发断言和超时。首轮仅生成根层 pins，val tree 建立后生成完整栈。回归单测在原版失败、修复后通过。 |
| 原版冷恢复丢失默认 Slot 内容开关 | ViewStateSnapshot 没有保存开关；补充后，原生跟踪又确认 Spotlight 挂载时排队的旧 `false` 会覆盖已恢复的 `true`。快照保存、恢复此状态，并避免在开关已关闭时排队关闭。退出编辑上下文及 Preview 的既有关闭行为保留。 |
| 原版 MCP 删除后保留失效选择 | 实际 `COPILOT_TOOLS.deleteElement` 删除了节点，但属性面板 reaction 仍读取该节点，抛出 `tpl must have owning component`。在 MCP 修改事务结束前剪除失效的 ViewCtx 引用。原生检查包含节点身份及撤销后的选择恢复。 |

这些功能修复同时用于原版和缓存候选。不能把修复测试数据或消除既有错误算作缓存优化的性能收益。

## 正式性能对照

两侧各三个全新 Electron 进程、独立 profile，按原版/候选/候选/原版/原版/候选串行运行。预热后添加/深删 121 节点子树 300 轮，即 600 条命令。完成真实客户端保存流程，由离线 HTTP fixture 确认；保存后两侧均保留 601 条历史、120 个活动子节点、0 条待保存记录。测量期间没有并行构建、测试或堆快照。

| 指标 | 修复后的原版 | 加样式缓存清理 | 变化 |
| --- | ---: | ---: | ---: |
| 保存后 GC 堆中位数 | 390.88 MiB | 372.01 MiB | −18.87 MiB / −4.83% |
| 保存后堆进程间范围 | 390.84–390.94 MiB | 372.01–372.03 MiB | 三个独立样本/侧 |
| 相对预热基线的堆增长中位数 | 296.29 MiB | 280.80 MiB | −15.49 MiB |
| renderer 累计 TaskDuration 中位数 | 22.94 s | 11.55 s | −49.63% |
| TaskDuration 范围 | 22.67–23.07 s | 11.45–11.62 s | 三个独立样本/侧 |
| undo/redo 至画板就绪的合并 p95 | 196.01 ms | 101.91 ms | 未见回退 |
| 最终共享组件缓存的规则数 | 37,026 | 121 | 删除节点的规则不再累计 |
| 最终组件样式文本字符数 | 3,014,099 | 9,849 | 保留全部历史 |

每侧延迟包含 120 次操作，来自三个独立进程，不能当作 120 个独立样本。就绪延迟包含既有轮询、调度和诊断 IPC，不是纯撤销执行时间。TaskDuration 在命令执行前后读取，强制 GC 与快照不在该 CPU 区间内；编辑期间自然触发的 GC 属于实际成本。

预设内存门槛为至少 10 MiB 且超过总堆 5%，本轮没有达到百分比门槛；独立 CPU 门槛为至少 20% 且相关功能通过，本轮达到 CPU 收益门槛。

## 复现与边界

- 使用 `desktop/tests/performance/undo-build.config.ts` 显式加入功能与增长诊断入口，`PERF_BUILD_OUT` 必须指定私有目录。入口不在正式构建中注册。
- 功能轮：`PERF_UNDO=1 PERF_UNDO_FUNCTIONAL=1 PERF_UNDO_ROUNDS=0`。先执行完整模型预检，再检查重复实例/clone key、Slot owner/Param、嵌套上下文、变体与 pins、默认 Slot、冷恢复、UI/MCP 删除、双画板 CSS、画板位置和选择。
- 性能轮：`PERF_UNDO_RETAIN=1 PERF_RETAIN_OPERATIONS=600 PERF_RETAIN_CPU=1 PERF_RETAIN_LATENCY=1`，分别运行两个构建并设置唯一 `PERF_RUN_ID`。
- 全历史轮使用 `PERF_RETAIN_FULL_UNDO=1`，不计入上表；离线保存重开使用 `PERF_UNDO_REOPEN=1`，只在此诊断模式中将完整保存结果交给下一次启动读取。
- 私有项目响应、缓存正文、profile、快照和生成构建不提交。沿用匹配版本的隔离 renderer，不修改 manifest、资源完整性或发布调试配置。

GC 堆是 renderer 诊断 isolate 的 JS 堆，不是整个 App RSS，也不包含所有原生/GPU 内存。此前堆快照和 MemLab 已确认活动 Component 的规则数组保留已删除 VS；本轮用独立计时和 GC 后堆复测，不把快照成本混入性能轮。历史释放只用于诊断，上表保留全部历史。

本轮没有测出画布首次加载、主进程事件循环、整个 App CPU/RSS 的收益，这些收益未知。离线确认不代表真实后端保存、账号、发布或更新验收。没有更改缓存预算、依赖发布方式、账号隔离、请求职责、撤销深度或客户端摘要上传。
