# 语法高亮按需加载：实施、收益与保留边界

## 最终实现

仅保留 CodeDisplay/CodeSnippet 的按需加载。公开组件保留原 props，原高亮实现移入 CodeDisplayContent；复用现有 Loadable 提供局部加载、失败重试和卸载取消。加载期间通过共享 Scrollbar 显示转义后的原代码，模块返回时使用最新 props，后续更新不重新挂载高亮组件。主题、语言覆盖、代码内容、样式和滚动组件保持原实现。

AI Markdown 的按需加载及其配套历史滚动改动已撤回。Markdown、消息历史、流式内容和 Agent 输入框保持原实现。两个方向没有留下并行的旧实现或配置开关。

脱敏结果及最终源码摘要见 [JSON](lazy-renderers-validation.json)。

## 对照方法

Apple M4，Electron 44.5.1。从同一份当前 WAB 冻结源码分别构建基线、完整拆分、仅代码展示、仅 Markdown 四个版本；使用生产构建配置和匹配的既有 runtime 资源，额外诊断入口仅用于显式首次使用探针。这些是 diagnostic 制品，不是已发布 App 或 NAS 部署包。

使用既有真实 GP 模型和复杂十画板模型，HTTP/WebSocket 由隔离 fixture 接管，资源经过实际 Desktop 文件缓存及摘要校验。每个正式计时进程打开六次，前两次预热，后四次统计；每侧两个独立进程，按 A/B/B/A 串行运行。构建、计时、trace、首次使用、内存和功能轮分开。没有把同一进程中的四次打开当作四个独立进程样本。

以下 reveal/rendered 是内部标记，不是物理屏幕呈现或实际输入延迟。没有线上 IAM、NAS API、真实后端保存和原生草稿桥的耗时，不能外推为用户线上两秒 loading 的缩短比例。

## 保留版本的收益

表中各值为一个进程四次暖打开的中位数，单位毫秒；每格两个值对应两次独立进程。

| 指标 | 基线 | 仅代码展示按需加载 |
| --- | ---: | ---: |
| GP：Studio 模块导入 | 106.8 / 104.6 | 95.6 / 100.5 |
| 复杂模型：Studio 模块导入 | 105.4 / 103.5 | 98.1 / 96.9 |
| GP：点击至首画板 reveal | 1338.9 / 1333.6 | 1318.2 / 1305.3 |
| 复杂模型：点击至首画板 reveal | 1251.0 / 1198.9 | 1180.0 / 1207.1 |
| 复杂模型：十画板全部 rendered | 3460.2 / 3503.3 | 3486.5 / 3462.7 |

导入阶段缩短约 4–11ms。GP 的两轮首画板样本较快，但复杂模型的一轮更快、另一轮稍慢；不认定稳定的整体打开提速，不宣传 CPU 百分比或“秒开”。

独立 trace 与 source map 确认：基线启动加载的脚本包含 Refractor 和 prism-react-renderer 的语言初始化；最终版本仍加载原有 Markdown 所需的 Refractor，但没有在启动路径请求/执行包含 prism-react-renderer 默认语言注册的 chunk。保留依据是按使用需求减少确定的初始化工作，及功能验收通过。

首次代码展示有成本转移。复杂模型两组首次使用探针中，基线约 16.5 / 17.5ms，保留版本约 31.6 / 32.2ms。探针包含 React 提交及 16ms 轮询，不是纯脚本执行时间；本轮观察约多 15ms，不能保证所有代码长度、网络和设备的差值相同。实际高亮逻辑及全部语言没有删减。

## Markdown 拆分为何撤回

完整拆分的导入阶段曾从约 104–119ms 降至 20–22ms，但这些不是最终交付收益。

复杂模型连续六次重开、最后显示 Markdown 和代码后返回列表：完整拆分在三组有效内存比较中的两组，峰值工作集总和高约 960 / 1008MiB；三组回收后工作集分别高约 83 / 86 / 224MiB。再等待约六秒并做第二次诊断 GC 的一组，差值仍约 183MiB。仅拆 Markdown 的隔离轮也出现更高峰值及约 165MiB 的回收后工作集差值。

回收后 JS 堆接近，不能据此证明泄漏；分配、回收时机及已提交页的具体归因仍未确定。也不能因堆最终一致而忽略多轮出现的工作集压力。因此撤回 Markdown 拆分，保留原有消息渲染路径，没有添加产品强制 GC、隐藏编辑器预热或延迟必要业务工作。

## 保留版本的资源边界

工作集为 Electron 各进程 RSS/working set 总和，包含共享页重复计数，不是系统实际物理内存。每个内存进程自然打开六次，最后一次显示消息与代码，返回列表后才执行诊断 GC。

| 有效比较 | 基线 | 仅代码展示按需加载 |
| --- | ---: | ---: |
| 第一组：自然峰值工作集总和 MiB | 2426.9 | 2250.5 |
| 第一组：回收后工作集总和 MiB | 1575.5 | 1594.7 |
| 第一组：回收后 JS 堆 MiB | 260.7 | 259.7 |
| 第二组：自然峰值工作集总和 MiB | 2426.3 | 3414.2 |
| 第二组：回收后工作集总和 MiB | 1578.9 | 1478.7 |
| 第二组：回收后 JS 堆 MiB | 260.4 | 260.9 |
| 第二组：再等待并第二次 GC 后工作集总和 MiB | 1454.4 | 1352.0 |

没有观察到一致的退出后工作集增加或回收后 JS 堆增长。但第二组仍有更高的自然峰值，不能保证峰值不变，也不能宣称内存下降。保留版本的收益限定为代码展示未使用时减少初始化，不把上述数据验收为内存等价或内存优化。

一轮早期内存探针在共享 Scrollbar 默认空闲初始化完成前提前断言，未取得回收后快照，不计入有效比较。探针现等待滚动组件真实就绪；所有有效功能轮均使用这一条件。没有通过改动产品滚动实现或忽略错误来通过验收。

## 功能验收与源码检查

- 最终保留源码的九个相关测试文件共 **56 项通过**：原有 Markdown 安全、公式、节点引用、复制、高亮、全屏及流式内容；AI 输入、会话和过程展示；代码主题；Loadable 失败重试和卸载取消。新增受控挂起测试检查代码更新、关闭一个等待中的实例，以及加载完成后的组件状态保持。
- 最终保留构建在两个真实模型中完成首/中/末画板切换、重命名、DOM 样式和画板位置编辑、撤销/重做、完整客户端保存与文档重开。复杂样本另验证冷画板销毁后的选择和样式恢复；GP 验证真实 Preview 分页及返回编辑器。
- 原生 Electron 中直接挂载真实 AiMarkdown、CodeDisplay、CodeSnippet，验证表格、公式、不执行原始 HTML、不加载外部图片、节点定位、代码高亮、复制选区、全屏、流式更新、主题、共享 Scrollbar 和重开。复制命令在隔离 Document 中拦截，未写系统剪贴板；单元测试另核对传入复制函数的完整文本。
- 最终代码的完整 `tsc --noEmit --incremental false`、修改生产源码及相关测试的 ESLint、生产配置隔离构建通过。最终两份实现文件与被测 code-only 冻结源码逐字节一致，摘要记录于 JSON。

有效计时和功能轮的画布 renderer error 均为零。基线与候选仍有既有 Dashboard 缩略图 fixture 的 `undefined.map` 错误，未掩盖，也没有把缩略图功能宣称为通过。保存由离线 fixture 确认，不冒充线上数据库、认证、发布或自动升级验收。未修改已安装 App 或 NAS。
