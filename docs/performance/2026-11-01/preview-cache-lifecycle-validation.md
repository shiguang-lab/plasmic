# Preview 缓存与画布生命周期验证

2026-11-01。**保留画布事件解绑的生命周期修复；不采用本轮代码生成缓存所有权候选。** [脱敏测量数据](preview-cache-lifecycle-validation.json)。

## 成功条件与方法

- 先证明旧对象的强保留路径，再比较 GC 后 JS 堆及旧对象存活数；不能靠清空共享缓存、卸载活跃画布或缩短历史取收益。
- 恢复后仍有可用画布，Live/Docs 生成模块摘要一致；当前模型暖缓存和另一个上下文的缓存身份保持。两个活跃画布的事件、选择、销毁及撤销重建正常。
- 缓存候选需带来明确内存收益并释放目标旧模型，才进入生产；有功能测试通过仍不足以单独证明值得采用。

Apple M4 / arm64，Electron 44.5.1。使用现有 `studio-optimization-fixture.cjs` 和 CDP，新增仅隔离入口注册的 `preview-cache-entry.ts`。实际 Studio 创建一个 640×480 混合画布，引用有 120 个文本子节点的页面，通过真实客户端完整保存及 `revertTo` 路径反复替换模型，再执行真实 Live/Docs 代码生成。另一个代码生成上下文始终保留最初模型，检查其输出和暖缓存未受影响；它不代表第二个真实 Docs iframe。

所有 HTTP(S) 由独立进程内 fixture 应答，WebSocket 阻断，没有业务后端写入。沿用源码构建的 renderer 与本地资源，不伪造 manifest，不开放正式包调试入口。每次采样清理 console 并执行两次诊断 GC；报告使用 Studio CDP 会话 `Runtime.getHeapUsage.usedSize`。三组正式对照每侧均为全新进程，串行运行，无构建、测试或快照分析并发。快照另轮采集，快照轮不参与计时中位数。

首次带真实画布的基线在版本恢复时出现 `PropEditorRow → getComponentEvalContext → valState` 错误：React 尚未卸载的属性行读取了已销毁 ViewCtx。已增加该行的销毁检查，停止读取旧画布；后续所有对照均包含同一检查，该修复的收益不单独计量。没有向已销毁的求值器提供伪造数据。

## 保留链与正式改动

MemLab 与三快照确认两类强保留：

1. 全局代码生成函数 → mobx-utils DeepMap 的 `store: Map` → 旧 Site/Component/生成输出。最初的 WeakMap owner lookup 路径不能单独证明强引用；过滤 ephemeron pair 路径后，仍能找到普通 Map 强保留链。
2. Window/debug 根 → ViewEditor → `releaseFrameInteractions[]` → 解绑闭包/共享词法上下文 → 已销毁 ViewCtx → `_globalFrame` → 旧 Site。数组在每次画布加载时追加，原来只在整个 ViewEditor 卸载时清理。关闭画布并没有结束这些回调的所有权。

正式改动将画布 Document 的 `trackFrameInteractions` 注册及解绑交给对应 **CanvasCtx 的现有 disposals**。CanvasCtx 销毁时解绑；编辑器 clipper 的监听继续由编辑器管理。活跃画布不解绑，不改变业务模型、后台同步、MCP、保存或 50 步撤销策略。

没有增加生产诊断常驻逻辑、依赖或缓存配置。

## A/B 结果

12 次模型恢复，三进程/侧的中位数，单位 MiB：

| 方案 | 初始 JS 堆 | 第 6 次后 | 第 12 次后 | 被跟踪旧 ViewCtx / Document 存活数 |
| --- | ---: | ---: | ---: | ---: |
| 基线 | 84.97 | 132.70 | 176.06 | 11 / 11 |
| 仅画布生命周期修复（保留） | 84.98 | 112.74 | 125.72 | 2 / 2 |
| 生命周期修复 + 缓存候选（未采用） | 85.10 | 111.79 | 123.87 | 2 / 2 |

正式修复使末尾 JS 堆下降 **50.35 MiB / 28.60%**；相对初始值的堆增长约为 91.10 → 40.74 MiB。另做一进程/侧的 36 次扩展循环，末尾为 **340.33 → 172.67 MiB**，下降 **167.66 MiB / 49.26%**；被跟踪旧 ViewCtx/Document 为 **35 → 2**。36 次不是三进程中位数。

被跟踪对象排除第一个故意保护的 Site 对应轮次，因此 12 次对应 11 组、36 次对应 35 组。无快照快速循环仍暂存最近两个旧 ViewCtx/Document；6 次与 36 次末尾均为 2，没有在这段工作负载中线性累积。额外三快照轮的末尾，两者均降至 **0**、JS 堆为 116.22 MiB；快照改变等待/GC 时机，这个数字不混入正式 A/B。

缓存候选将六个 keepAlive computed 改成按上下文/模型归属、在模型替换及会话结束时释放的缓存，保留 structural equality 和当前模型暖命中。单独候选初测三进程末尾仅约少 1.85 MiB / 1.05%；在生命周期修复之上再加它，三进程只额外少 **1.84 MiB / 1.47%**。两种情况下 11 个被跟踪旧 Site 仍全部存活，因此候选和相关辅助改动、候选专用测试已撤回，没有进入正式源码。

代码生成时间为 Live+Docs 同步生成调用的墙钟时间：基线冷中位数 8.8 ms，正式修复 9.0 ms；暖中位数均为 0.8 ms。**未测得生成提速**。这不是 CPU time，也不是 Preview 暖重开或画布首帧耗时。

## 已执行验证

- 最终源码：9 文件、79 项 Vitest 通过，覆盖画布事件转发、拖动、内容编辑、加载状态、ViewCtx、Live/Docs 生成快照、Preview 同步和 PreviewFrame。生成快照包含 counter、全局变体、自定义函数、token、依赖项目样式等六种 fixture，并执行真实转译。
- `pnpm --dir platform/wab typecheck` 通过；根目录 ESLint 对三个改动生产文件检查通过；诊断 CJS 的 `node --check` 通过。候选阶段另有 60 项相关测试通过，不能因此宣称其实际收益或全部 UI 等价。
- `before`、`after`、`frame`、`combined` 四个隔离生产构建通过；最终生产实现对应 `frame`。
- 三组正式循环及 36 次扩展循环的模型恢复、当前画布、生成 JS/CSS 摘要、另一消费者输出身份、暖缓存身份检查均通过，Studio error 为 0。历史恢复后内部 undo 记录为 1，旧对象保留不靠更改撤销上限解释。
- 原生 Electron 双画布：两个 Document 均恰好转发一次；销毁 A 后旧文档不再转发，B 的转发和焦点正常；撤销创建新的 A 文档后仍恰好转发一次。之后公开重命名、撤销、重做和恢复均通过，错误为 0。基线行为控制也通过，说明事件行为断言与内存保留检测须分开；它不是会在旧版必然失败的泄漏断言。
- MemLab 完成原始缓存路径、缓存候选后的画布闭包路径、正式修复后的缓存路径分析。目标快照中的 6 个标记 Site 聚为一类保留链；正式修复后的代表 Site retained size 约 56,328 bytes。该大小不涵盖全部条件保留图，不能与整堆差值相加，也不把 MemLab 候选总数当成泄漏数。

## 未解决与测量边界

正式修复后 11/35 个被跟踪旧 Site 仍存活；快照中仍有全局代码生成缓存的普通 Map 保留链。这条路径已确认，但只改变六个代码生成缓存的候选没有释放整个旧模型图，也没有足够收益，本轮没有继续扩大清理其他全局 selector 的范围。不能据此宣称所有模型泄漏已经修复。

本轮没有完整实际 Docs 编辑 UI、草稿恢复链路、账号登录、库发布/自动升级/远端接口验收。缓存候选因此也不具备“全部功能已证明等价”的结论；它已因收益和旧模型回收条件失败而撤回。正式改动的运行时交互检查针对画布 Document 事件生命周期。

数字仅代表本机离线项目的 Studio JS 堆。未测原生/GPU 内存、整 App RSS、总 CPU time、系统输入延迟、完整打开项目或 Preview 重开时间，这些收益均未知。反复恢复版本比日常少量操作更集中，不把 36 次结果外推成固定日常内存节省。

原始模型、profile、四套构建、快照和被撤回候选 patch 留在本机权限为 700 的临时诊断目录；仓库仅保存工具和脱敏数据。诊断入口不加入发布构建。
