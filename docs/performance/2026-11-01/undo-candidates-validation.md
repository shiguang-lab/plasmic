# 撤销候选方案：分项验证与处置

日期：2026-11-01。延续[操作量增长诊断](undo-history-growth.md)，记录最初四个独立候选轮次的数据。[后续完整验收及重新 A/B](undo-functional-qualified-ab.md)已定位并修复下述失败，将样式缓存清理转为正式实现；快照共享、标量压缩和冷历史仍未启用。[本候选轮次脱敏样本及源码哈希](undo-candidates-validation.json)。

## 验收门槛

- 保留每个用户撤销停点、历史深度及模型/选择/变体语义；不能通过清空共享缓存或减少历史取得收益。
- 内存门槛：相同场景的 GC 后 JS 堆稳定下降至少 10 MiB，且下降超过最终总堆的 5%。以每侧三个新进程为正式 A/B，比较中位数及范围。
- 发现 CSS 累积的 CPU 成本后，在采集正式 CPU 数据前增加独立门槛：renderer 的累计 `TaskDuration` 稳定下降至少 20%，交互就绪延迟不明显回退。墙钟耗时单独变化不作为 CPU 验收。
- 收益和功能必须同时具备证据。单测或简单场景通过，不能替代重复实例、Slot、嵌套上下文、删除恢复和多画板检查。未完成或失败的关键验收不计为通过。

所有测量为隔离 Electron 44.5.1、生产模式 Studio、离线 fixture、独立 profile；使用 Mac16,1 / arm64 / 24 GiB。没有使用正常 App 凭据、真实项目写入或正式包外部调试入口。数字是共享 isolate 的 GC 后 JS 堆或诊断 target 的性能指标，不是整个 App RSS、GPU 内存或操作系统 CPU 利用率。

## 1. 已删除 VariantSetting 的样式缓存保留

### 确认的根与所属范围

100 条子树添加/深删命令后，完整客户端保存流程完成，堆仍从约 147.6 MiB 维持在约 147.7 MiB；诊断移除历史后仍约 134.5 MiB，基线约 97.9 MiB。保存响应由离线 HTTP fixture 确认，实际执行客户端打包、校验、修订及待保存缓冲更新，不等于服务端保存验收。

MemLab 2.0.6 分析 baseline / target / history-released 三快照，找到：

```text
StudioCtx → styleMgr → componentToVsRules WeakMap
  → 活跃 Component 对应的规则数组 → entry.vs → 已删除 VariantSetting
```

该规则数组的 retained size 约 36 MB。它按 Component 归属，并非每个画板独占；同一组件的多画板共享它。WeakMap 的 key 是仍活跃的 Component，因此不能据“用了 WeakMap”认为已删除 value 必然回收，也不能清空整个共享缓存。

源码有两处遗漏：摘要过滤依赖删除后已经不存在的所属组件，导致移除节点的 VS 没进入样式清理；StyleMgr 的删除规则路径也提前跳过脱离树的节点。原型用 VS 对应的缓存所属组件清除确切规则，并保留删除通知。只改了这两处生命周期路径，没有改 UndoLog 的深度或模型事件。

### 保留完整历史的 A/B

每进程预热后执行 300 轮 121 节点子树添加/深删，即 600 条模型命令、601 条含初始视图的历史。两侧最终仍是 120 个活跃子节点。内存轮、CPU 轮各自每侧三个新进程，交错串行，不与构建/类型检查并行。

下表统一取带 CPU 指标的六个新进程，避免将不同轮次混为一轮：

| 指标 | 原版中位数 | 缓存原型中位数 | 结果 |
| --- | ---: | ---: | --- |
| 保存后、保留全部历史的 GC 后堆 | 394.06 MiB | 375.29 MiB | 少 18.76 MiB / 4.76%，未达 5% 内存门槛 |
| 600 条命令的累计 TaskDuration | 22.96 s | 12.07 s | 下降 47.43%，达到独立 CPU 门槛 |
| 每侧 120 次 undo/redo 至当前画板就绪的合并 p95 | 193.45 ms | 103.33 ms | 未见该场景延迟回退 |
| 最终样式缓存规则数 | 37,026 | 121 | 已删除规则不再累计 |
| 最终组件样式文本字符数 | 3,014,099 | 9,849 | 模型和全部历史保持不变 |

每侧独立进程数只有 3，不能把 120 次操作当作 120 个独立样本。就绪计时包含调度、IPC 和既有 50/100ms 轮询，不是纯撤销执行时间、触摸响应或首次加载耗时。TaskDuration 不是操作系统 CPU 百分比，亦未据此宣称整个 App CPU 下降 47%。

一次性清除诊断历史后，原型和原版堆差距显著扩大，但该对照不代表保留全部历史的产品收益，不能拿它替代上表 18.76 MiB 的结果。

### 初次功能检查及后续修正

- 相关 5 文件、38 项单测通过，包含两个 Document 的删除/撤销/重做、另一组件样式保留、变体规则删除恢复；原型类型检查最终通过。
- 一个新 Electron 进程遍历全部 600 次 undo，再执行全部 600 次 redo，各位置子节点数和最终历史状态正确，无 Studio 错误。
- 扩展场景中，两侧重复实例身份、Slot owner/Param、嵌套上下文/目标变体/pins/default Slot 的断言通过。
- 原始低层 TplQuery 删除场景在两侧都触发动画 observer 的 `tpl must have owning component`。这些整轮测试记为失败，不能因部分断言通过而改为通过。
- 双画板早期检查只等待当前画板就绪，立即读取了另一画板的旧样式。后续数据记录了双方均可见、原型第二画板随后激活时正确恢复颜色；这不足以将整个扩展场景算作通过。
- ViewOps 的“Deleted model not restored”已确定源于测试 Slot 缺少 base VariantSetting：删除在模型修复时失败，随后 undo 撤销了前一项变更。另一个非法 Accent 变体也已通过模型预检发现并修正。

当时因关键验收不完整撤回原型。后续另行修复了原版冷恢复的 pin 栈初始化、Slot 开关恢复与 MCP 删除后的失效选择；在相同修复基线上，两侧复杂场景、完整 600 次撤销/600 次重做及保存重开全部通过。正式收益使用[重新测量的数据](undo-functional-qualified-ab.md)，不将本表实验数字冒充功能通过后的统计。

## 2. 未变化的变体栈快照共享

在原始生产逻辑上独立构建原型，仅在相同 frame/Tpl 实例及私有 targets/pins 相等时复用历史栈帧；恢复活跃编辑栈仍 clone，选择和上下文保存方式不变。没有使用忽略实例身份的普通 equals 直接判断共享。

每侧三个新 Electron 进程，5,000 次独立属性修改：

| 指标 | 原版 | 共享原型 |
| --- | ---: | ---: |
| 最终 GC 后堆中位数 | 107.72 MiB | 103.38 MiB |
| 相对各自基线的增长中位数 | 14.48 MiB | 10.16 MiB |
| 包含初始视图的历史记录数 | 5,001 | 5,001 |
| 不同变体帧快照对象数 | 5,001 | 1 |

实际减少约 4.34 MiB / 4.03%。5 项只读快照/实例身份单测通过，六个进程末端 undo/redo 抽查均通过。没有将这些检查扩大为所有冷恢复和全部历史位置通过。

**未达收益门槛，不转正。** 该原型一直只通过私有构建 loader 注入，未修改生产撤销源文件；这项对象数下降不能当作大内存收益。

## 3. 同一次交互内压缩重复标量差分

独立原型只压缩已有一个撤销边界内、相同实例/字段/路径的连续标量链；不跨用户命令合并。对象引用、数组结构变更、未知路径及不连续值保留原事件；只改历史副本，保存缓冲仍保留原始变更。没有全局修改 mergeRecordedChanges 或协作协议。

使用已有 startUnlogged/stopUnlogged 契约，每 50 次 margin-left 更新是一组；5,000 次更新对应原有 100 个手势步骤。完整 renderer 执行模型和样式更新，但没有模拟真实鼠标轨迹。两侧均为原始生产逻辑加各自唯一候选，未叠加上一项共享或缓存原型。每侧三个新进程。

| 指标 | 原版 | 压缩原型 |
| --- | ---: | ---: |
| 最终 GC 后堆中位数 | 114.37 MiB | 111.90 MiB |
| 相对各自基线的增长中位数 | 19.48 MiB | 17.01 MiB |
| 最终总堆进程间范围 | 114.24–114.42 MiB | 110.86–111.96 MiB |
| 历史记录数，含初始视图 | 101 | 101 |
| 历史中的内部 ModelChange 数 | 10,000 | 200 |

实际总堆减少约 2.48 MiB / 2.17%，未达收益门槛。6 项边界单测通过；六个进程末端 undo/redo 抽查均通过，包括恢复到上一手势的边距值。没有据此宣称所有历史位置、协作冲突、复杂对象或冷恢复通过。

此表为诊断移除待保存引用后的值；清理前的中位数约为原版 114.37 MiB、原型 112.90 MiB。压缩没有删除待保存事件，因此缓冲尚未释放时收益更小。该清理仍不等于真实保存；没有将这组数据扩大为完整在线/离线保存链路的收益。

**收益不足，不转正。** 内部事件数量减少 98% 不等于整个 App 内存减少 98%。原型始终通过私有构建注入，生产 UndoLog 未改。

## 4. 冷历史载荷与同步成本

本项仅做一个新进程的成本探针，未实现生产冷历史或新的存储架构。对历史中 300 棵已删除的 121 节点子树调用现有 Bundler，JSON 返回诊断主进程后压缩、校验字节并写入私有临时目录；再在 renderer 解析和反序列化，检查 300 个根 UUID 及每棵 121 节点。

| 指标 | 单轮实测 |
| --- | ---: |
| 子树 bundle JSON | 23.30 MiB |
| gzip 后载荷 | 3.14 MiB |
| 整批打包及返回至诊断主进程 | 1,118.78 ms |
| 上述过程内的 bundle 生成 | 1,063.20 ms |
| 上述过程内的 JSON.stringify | 29.40 ms |
| 主进程 UTF-8 Buffer 转换 | 4.57 ms |
| 主进程同步 gzip / gunzip | 121.66 / 16.81 ms |
| JSON.parse | 73.60 ms |
| 300 棵子树反序列化及节点检查 | 294.50 ms |
| 临时文件 writeFileSync | 0.56 ms |

编码并返回的墙钟时间包含内部打包、序列化及 IPC，不能把这些嵌套耗时相加，也不能将差额全认定为 IPC 复制时间。临时写入是页缓存写入，没有 fsync，不能当作可靠持久化提交时间。gzip 的同步调用会占用诊断主进程；没有在生产主进程添加它。

原撤销历史一直保留。强制 GC 后，renderer 在额外持有 JSON 字符串时比原状态增加约 23.36 MiB，同时持有反序列化结果时增加约 96.06 MiB；释放探针临时根后，仅高出原状态约 0.07 MiB。诊断主进程观察到 JS heap 增加约 23.30 MiB、external 分配增加约 76.17 MiB；主进程没有做强制 GC，这不是其必要内存下界或常驻量。arrayBuffers 包含在 external 内，不能再重复相加。以上持有态也不是整个 App 的峰值 RSS。

该载荷不包括完整 ModelChange、视图、选择、实例身份、引用回放、协作冲突和持久化索引。反序列化后的对象身份需要与现有模型/历史重新关联；本次 UUID/节点数及压缩字节检查不能证明整个撤销引擎正确。**不能把约 396 MiB 的 renderer 堆与 3.14 MiB 的压缩载荷直接比较，宣称相应内存节省。**

正式冷历史的内存收益、首次冷撤销延迟、持续保存、恢复失败处理和账号隔离仍未知；worker/进程的初始化、通信和额外内存也未做 A/B。因此不引入生产落盘、线程池或新缓存预算，冷历史不转正。

## 初次候选轮次的执行记录

- 正式 A/B 共 24 个新 Electron 进程：缓存内存轮 6、缓存 CPU/延迟轮 6、共享轮 6、压缩轮 6。正式计量与构建/类型检查分开，前后交错串行；样本和每轮指标完整保存在 JSON。
- 补充一个 600 undo + 600 redo 的完整历史功能轮；其计时不纳入 A/B。一个有效三快照及 MemLab 路径诊断；一个冷载荷成本探针。失败及未完成的功能轮保留为失败，不计入通过数。
- 原型单测 38/38、类型检查最终通过；私有共享和压缩边界测试分别 5/5、6/6。撤回后原有四文件 35/35 通过，`pnpm --dir platform/wab typecheck` 通过。
- 四个新增/修改的诊断脚本 `node --check` 通过，`git diff --check` 通过。
- 初次候选轮次结束时，七个生产文件恢复至轮次开始的副本。后续正式缓存修复及共同功能修复见新报告；没有新增生产诊断依赖，也没有提交或发布。

脚本异常均未当作收益证据：首次直接替换 Comlink API 触发 DataCloneError，改为离线 HTTP 确认；新增缓存计数一度被误放入模型相等判断，已与业务状态分离；私有 Vitest 配置合并了根 projects，误启动更大测试集后已停止，后续明确限定 `--project option`，该轮不算数据库或全套测试通过；私有测试导入曾失败，改用已核实的 ESM 路径。生产断言和扩展失败没有被关闭、吞掉或降低验收标准。

MemLab 的非 TTY `--help` 调用另外报了 CLI 文本排版 RangeError，没有计入有效检查；实际 find-leaks 命令完成并留下结果。排除轮的重复大快照已清理，失败报告和有效三快照仍保留。

没有测出正式 App 的 CPU/RSS/GPU/首次加载收益，没有验收真实后端保存/发布、认证、自动升级或完整业务组件库。嵌套删除/恢复的关键验收及样式缓存重新对照已在后续完成；其他两项微观压缩暂不推广。

复用 [Electron 诊断工具说明](../../../desktop/tests/performance/README.md)。有效快照、MemLab 输出、原型补丁/源码、私有构建入口、每轮驱动和日志位置均记录在 JSON 的 localArtifacts。它们不进入生产资源；原始 profile、堆快照、压缩载荷不提交。正式 A/B 可用对应 RUN_ID、新 profile 和 before/style、option-before/share、drag-before/compact 构建复现。
