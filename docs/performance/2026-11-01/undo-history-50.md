# 项目撤销历史：固定最近 50 步

日期：2026-11-01。按用户最新要求，生产源码固定为每个项目会话最近 **50 个完整撤销步骤**，内部最多 51 条记录（含一个仅用于恢复视图的起点）。沿用既有样式缓存清理与历史滚动机制，不增加配置或另一套实现。

达到上限后，第 51 次编辑移除最旧一步，保留第 2～51 步，不会整栈清空。移除的是旧历史对对象的引用；只有不再被其他对象引用的内容才会被 GC 回收，不保证在截断瞬间立即释放内存。边界记录保留视图，清空其已无法撤销的变更引用。

当前模型、待保存事件、交互缓冲和已有持久版本均不因截断而删除。自动保存不清空最近 50 步；撤销后继续编辑只丢弃重做分支；一次已有分组交互仍是一步。较早状态只能恢复到实际存在的保存版本，不承诺每一步都有版本。

诊断工具的期望上限默认同步为 50。版本恢复测试按被测上限遍历，125 次编辑后，50 步窗口的最旧状态为 `Later74`；随后仍可通过实际客户端 `revertTo` 路径恢复更早的 `SavedCheckpoint`。

本轮验证：[脱敏结果](undo-history-50-validation.json)。3 文件 19 项单测、类型检查、当前源码的隔离生产构建均通过。原生 Electron 执行 600 条模型命令后，保留 51 条内部记录，待保存事件仍为 600；保存后事件为 0、历史仍为 51。全部 50 次撤销及 50 次重做、三个复杂上下文的滚动截断、冷恢复、UI/MCP 删除、双画板实际样式、保存重开及超出窗口的版本恢复均通过，无 Studio 或浏览器 console 错误。

原始报告中的 `history-released` 是全部保留步骤验证之后由脚本显式清空历史的诊断控制，不是达到 50 步后的产品行为。

[此前 100 步的 A/B](bounded-undo-history.md)和[原始数据](bounded-undo-history.json)保留为历史测量；其中 141.10 MiB、62.07% 等数字不作为 50 步策略的已测收益。本次调整只验收新的边界与相关功能，不另做三进程/侧的性能 A/B。
