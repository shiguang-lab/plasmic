# 普通打开项目画布：真实项目对照

本轮基线已包含[上轮的永久等待修复和首次求值调度](../2026-11-10/canvas-startup.md)。两份真实业务项目中，从 Dashboard 点击到 Studio 发出首屏揭示通知的中位数均缩短约 122 ms（8.1%），全部初始画板也更早完成。对照使用私有离线快照和 Desktop 的真实渲染器、启动和画布链路；不测量线上认证、网络或服务端耗时。

## 成本来源与改动

- **在用户看不到的 Host 中重复挂载加载界面。** 顶层已负责可见的加载工具栏和输入框，覆盖期间 Host 的各层启动占位仍会挂载工具栏、画布控件和布局。以前只关闭 Logo 动画。现在覆盖期间不挂载 Host 的加载占位，错误仍能请求揭示并显示重试；揭示后由 Host 负责自己的加载状态。组合改动后，点击到开始导入 Studio 模块的中位数在两个项目分别由 501 → 422 ms 和 489 → 415 ms。
- **模型依赖反复转成对象和字符串。** 启动流程已并行预取依赖，但顶层仍解析 JSON、重新序列化整个响应，再由 Host 解析一次。两份项目各引用五份依赖，原始依赖体积分别为 4.76 MB 和 4.62 MB。预取现通过原缓存和权限路径读取字节，Comlink 转移每个缓冲区一次，Host 解析一次。Host 的模型等待阶段由 45.9 → 20.1 ms 和 33.5 → 16.1 ms。普通刷新、缩略图和历史读取仍走原路径。
- **仍要完成的工作。** 大项目的采样显示首画板求值和 React 渲染、模型解包，以及 Host 和画板各自执行组件库，都占用启动 CPU。基线模型解包中位数约 103 ms，首画板渲染阶段约 197 ms。阶段可能重叠，也包括等待时间，不能累加成总耗时。没有为提高指标延后画板或放宽首屏就绪条件。

单独提前读取设置、等待组件同步后再挂载、轻量化入口导入以及跳过一次重复路由通知，均未显示端到端净收益，未采用。只替换字节传输在单项阶段稳定变快，单独的普通打开对照受系统负载影响，不能从该阶段推导总体收益。

## 原生回放结果

用同一份冻结源码分别构建基线和候选。使用 `desktop/tests/performance/real-project-open.cjs`（`PERF_OPEN_SESSIONS=1 PERF_OPENS=8 PERF_NO_DEBUG=1 PERF_OPEN_NATIVE=empty`）。每个版本用独立 Electron 进程和临时配置，通过真实 Dashboard 卡片进入，每次返回时销毁编辑器。每对轮换 A→B 与 B→A；同一时刻只有计时的一侧窗口显示。每个项目有 8 对，前 2 对作为预热，剩余 6 对全部计入；大项目有一对观察到系统索引活动，仍计入。每个版本的全部 7 次暖打开均通过真实 IPC 保存视口恢复检查。

| --- | ---: | ---: | ---: |
| A：10,746 个模型对象，2 个初始画板 | 1517 → 1394 | 1533 → 1399 | 2140 → 2025 |
| B：1,420 个模型对象，1 个初始画板 | 1512 → 1389 | 1824 → 1691 | 1433 → 1303 |

首屏揭示通知和全部初始画板渲染均为 12/12 对更快；外部轮询为 11/12 对更快。首屏揭示通知在计入的样本中最慢值分别从 1577 → 1397 ms、1526 → 1425 ms。每侧只有 6 个样本，不把该值外推为线上长尾。揭示通知由 Host 在目标画板和视口就绪后发出；外部轮询包含探测延迟，两者都不是合成器的实际呈现时间。单画板项目允许在保存视口恢复完成前就完成画板渲染。大项目两侧各记录同一条 Babel 大文件提示，未删除样本。
