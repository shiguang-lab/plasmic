# 画布首屏加载评估：页面模型与组件库模型按需加载

2026-11-20 · Plasmic Desktop 0.9.11 · 源码基线 `b28638689`

已发布模板打开画布时会用到两份数据：页面模型 `rev.data` 描述页面、画板和组件实例，组件库模型 `depPkgs[].model` 提供这些实例引用的组件和参数定义。**完整库模型缓存已完成本地实测**，作为后续实验的共同基线。两个待评估方向都先用已发布的只读模板验证。

| 待评估方向 | 首次打开时加载什么 | 已有证据 | 要回答的问题 |
| --- | --- | --- | --- |
| 页面模型按需加载 | 完整目录、画板位置和首屏可见页面，沿用完整库模型缓存 | 已对 Material UI 的 33 页发布快照做离线裁剪 | 首画板能提前多久显示，首次切页或缩放到总览要多等多久？ |
| 组件库模型按需加载 | 保留完整页面正文，尝试优先加载首屏需要的库定义 | 已确认解包顺序和外部引用，所需库对象的大小尚待测量 | 能减少多少冷缓存下载和热缓存解包，首次查看属性或切换画板是否变慢？ |

## 共同基线：完整页面与完整库模型缓存

### 线上采样：原模板接口的耗时与响应组成

2026-11-20 09:37，在同一台 Mac 上用已登录的 Desktop 交替暖开五轮。已发布模板为 Material UI 2.0.0，普通项目为同项目主分支修订 137。下表是**接口请求**的中位数。TTFB 从 HTTP/2 发出请求头计到收到响应头，正文接收计到最后一个数据帧。后端耗时来自同次请求的应用日志，与 TTFB 有重叠。

| 打开方式 | 原始响应 | gzip 正文 | 后端 | TTFB | 正文接收 | Desktop 请求总时长 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 已发布模板 | 4,484,409 B | 744,754 B | 236 ms | 322 ms | 789 ms | 1,109 ms |
| 普通可编辑项目 | 2,344,232 B | 369,093 B | 237 ms | 439 ms | 495 ms | 905 ms |

模板响应里，`rev.data` 字段占 2,271,915 B，内联的 `material-ui@1.1.0` 库模型占 2,211,171 B。普通项目已按资源 ID 读取库模型，五次暖开均命中磁盘缓存，缓存条目的 ID、SHA-256 和字节数与服务端一致。画板使用的组件库 JS 有单独的加载和注册流程。[依赖模型资源](../../../platform/wab/src/wab/server/routes/dependency-model-resources.ts) · [缓存命中与回源](../../../platform/shared/resource-cache/src/index.cjs) · [画板组件库选择](../2026-11-09/hostless-loading.md)

### 隔离对照：已发布模板复用完整库模型缓存

改后的 `GET /api/v1/template-center/:templateId/studio` 返回完整页面正文，以服务端按包版本实体和内容摘要确定的 `modelResourceId` 引用库模型。同账号打开普通项目时预热的模型可以直接复用。仅有模板查看权的读者冷开私有依赖时，资源接口按当前发布快照校验包版本实体及模型摘要。PostgreSQL 回归已覆盖私有依赖冷读、旧摘要和模板下架。[模板接口](../../../platform/wab/src/wab/server/routes/template-center.ts) · [服务端资源选择与读取](../../../platform/wab/src/wab/server/routes/dependency-model-resources.ts)

在隔离 PostgreSQL 中运行改前、改后接口，使用同一发布快照、Desktop 生产模式构建和 1400 × 860 窗口。每次启动新的 Electron 进程，从打开模板计到 Studio 报告 `canvas-revealed`，并核对「信贷-首页」画板、视口就绪及 33 页目录。四种组合各 8 次，交替执行。[32 次逐轮数据](published-template-model-cache.json)

| 模型磁盘缓存 | 首包 gzip，改前 → 改后 | 首包 + 回源库模型 gzip，改前 → 改后 | 打开画布，改前 → 改后 |
| --- | ---: | ---: | ---: |
| 冷 | 736,549 → 358,700 B | 736,549 → 736,514 B | 2,141 → 2,276 ms（慢 135 ms，6.3%） |
| 热 | 736,549 → 358,700 B | 736,549 → 358,700 B | 2,147 → 1,694 ms（快 454 ms，21.1%） |

首包原始 JSON 从 4,484,408 B 降到 2,273,285 B（−49.3%）。冷开 8 次均在首包后单独下载 377,814 B 的 gzip 库模型，额外一次往返使画布打开中位数增加 135 ms。热开 8 次均命中磁盘，库模型网络下载为 0 B，画布打开中位数减少 454 ms。装回依赖后，新旧响应逐字段一致。差值和百分比取自未取整的中位数。

组件库 JS 在各组均已预热，其他启动接口在本机回放。模型接口经过本机 HTTP 和 gzip level 4，每次网络请求额外等待 85 ms，下载上限 944,000 B/s，取值参考线上采样。后续原型应保留这组条件，以便区分缓存复用、数据裁剪和网络波动的影响。

## 方向一：页面模型按需加载

先返回完整页面目录、画板位置和首屏可见页面所需的本地对象。首次可见多张画板时批量取数，进入其他页面或缩放到总览时再补齐。此方向继续使用完整组件库模型。

### 离线估算

从同一发布快照出发，保留全局设置、主题、图片、全局上下文及非页面组件，按目标页面及画板的引用递归保留本地对象。目录保留全部页面名称、UUID、路由、分组说明、画板位置与尺寸、网格成员和依赖标识。

| 保留范围 | 本地模型对象 | 目录和模型一起 gzip 后 |
| --- | ---: | ---: |
| 只返回目录 | — | 3,440 B |
| 恢复现场的「信贷-首页」 | 536 | 25,471 B |
| 深链进入「手机验证码登录」 | 497 | 24,101 B |
| 整个「信贷」分组，9 页 | 2,572 | 94,470 B |
| 整个「健身」分组，24 页 | 7,414 | 242,459 B |
| 全部 33 页，含相同目录 | 9,863 | 326,015 B |

表中用紧凑 JSON 和 Node gzip level 5，仅统计目录和页面模型。逐页裁剪后各为 14,480–34,326 B，中位数 21,615 B。只取首页比取全部 33 页少约 301 KB。样本中各页的本地引用和外部引用目标均有效，重新选取全部页面得到的 bundle 与原版逐字段相等。有跨页引用的项目可能需要同时加载更多对象。这些是字节估算，首屏与切页耗时仍需原型实测。

### 原型与验证重点

1. **发布与定位。** 从同一发布快照生成目录和页面对象，保留 UUID、bundle 内对象 ID 和依赖身份。用版本、模型格式和内容摘要区分制品，全部可读后再切换发布指针。按深链、保存的画板或默认视口确定首屏，一次返回目录和已知的首屏内容。检查 Desktop 恢复模板时的项目预检是否重复下载正文。[模板发布事务](../../../platform/wab/src/wab/server/routes/template-center.ts) · [Desktop 启动预检](../../../desktop/src/workspace.cjs)
2. **切页与总览。** 按快照和缺少的页面批量补取，共享对象按原地址去重。同一页面在多个分组中复用正文，每张画板保留自己的位置、尺寸和变体。检查补取、并发切页和失败重试后，已显示画板、选中目标和缩放位置是否稳定。若单页粒度导致频繁补取，增加按可见分组加载的对照。[目标与视口就绪](../../../platform/wab/src/wab/client/studio-ctx/studio-loading.md)
3. **引用与全项目操作。** Studio 初始化会解包 Site、重建父引用并扫描表达式。验证首批对象引用完整，追加页面能保留共享对象身份。对 Preview 跳页、动态路由、MCP 按 UUID 读取、搜索和导出，按操作范围补齐数据。[Site 解包](../../../platform/wab/src/wab/shared/core/tagged-unbundle.ts) · [Studio 初始化](../../../platform/wab/src/wab/client/init-ctx.tsx)

## 方向二：组件库模型按需加载

先保留完整页面正文，评估首屏是否可以只取部分库定义。组件库 JS 提供组件实现。页面里的组件实例、参数和插槽可以引用库模型中的对象，当前 Studio 会先取得并解包全部依赖，再解包模板、解析外部引用。首屏需要哪些库对象、哪些信息能延后，尚无裁剪数据。[模型读取](../../../platform/wab/src/wab/shared/SharedApi.ts) · [依赖解包顺序](../../../platform/wab/src/wab/shared/core/tagged-unbundle.ts) · [外部引用解析](../../../platform/wab/src/wab/shared/bundler.ts)

### 原型与验证重点

1. **量出两组对象。** 在同一快照上，分别追踪完整模板解包所需的库对象，以及首屏可见画板渲染所需的库对象。沿组件、参数、插槽及其间接引用核对，测量两组各自的 gzip 字节和解包耗时。若完整页面中的其他引用仍要求加载整库，记录具体引用，以此判断库模型能否独立裁剪。
2. **验证编辑信息能否延后。** 对属性面板使用的数据，先核实来自持久化库模型还是运行时注册。仅对确认首屏无需读取的库数据试验延后加载。依次检查画板显示、选择组件、首次查看属性和切换画板，核对组件实例、属性值及插槽内容。
3. **保留缓存复用。** 裁剪内容需有自己的资源标识。分别用空缓存和由普通项目预热的完整库缓存打开同一模板，检查冷开节省的下载是否被额外请求抵消，以及热开是否重新下载已有定义。

## 统一对照与决策

先在同一发布快照、客户端构建、起始画板、视口和网络条件下，将两个方向分别与 B 比较。两者单独可行时再测试组合，比较组合相对于 C、D 各自的额外收益。

| 组别 | 页面模型 | 组件库模型 | 状态与比较对象 |
| --- | --- | --- | --- |
| A | 完整 | 首包内联完整模型 | 原始基线，已与 B 对照 |
| B | 完整 | 完整模型按资源 ID 缓存 | 已实测，两个方向的共同基线 |
| C | 目录与首屏所需页面 | 同 B | 待验证，与 B 比较页面裁剪 |
| D | 同 B | 优先加载首屏所需库定义 | 待验证，与 B 比较库模型裁剪 |
| C + D | 同 C | 同 D | 条件性组合，与 C、D 分别比较 |

**采样口径。** 在同一台 Mac 上轮换各组顺序，区分进程冷启动、同进程重开、库模型磁盘冷暖和页面会话缓存。固定组件库 JS 的缓存状态。覆盖首页、深链、恢复离屏画板、9 页与 24 页总览、首次切页、返回已访问页、快速连续切页和首次查看属性。加入小项目和跨页引用样本，在 Desktop 与 Web 核对。报告失败、超时及有效样本数；比较 P95 时每个关键场景每组至少取 40 个有效样本。

**指标与正确性。** 分开记录首包与到首屏的累计下载字节、回源次数、后端处理、TTFB、正文下载、解包、目标画板显示和可交互时间。交互阶段记录首次切页、总览全部可见画板就绪、首次选中组件至属性面板可用的时间，以及多页累计流量和峰值内存。同步核对同一视口截图、节点 UUID、组件 props、插槽和交互。新制品还需检查发布耗时、发布切换、模板下架及私有依赖授权。

**取舍。** 页面方向沿用建议门槛：大模板暖开首画板可交互 P50 相对 B 至少减少 15% 且至少 150 ms，首次切页和总览 P95 增量各不超过 200 ms，小项目与冷开无可重复的首屏回退。库模型方向先判断完整页面能否用较少库对象正确解包，再根据冷开下载、热开解包、已有缓存复用和首次查看属性的实测代价决定是否推进。

普通可编辑项目另行评估。局部模型会影响增量保存回退、草稿、撤销、跨页引用和远端修订合并。可先试验只读首屏就绪后补齐同一修订，再开放编辑；进入局部编辑阶段前，用保存、重开及双客户端并发验证未加载页面的数据完整性。[保存路径](../../../platform/wab/src/wab/client/studio-ctx/StudioCtx.tsx) · [本地草稿](../../../platform/wab/src/wab/client/studio-ctx/desktop-drafts.ts)
