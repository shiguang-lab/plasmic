# 画布几何查询：JS 读缓存与 WASM 对照

本轮结论：**不引入 WASM。单次查询内的 JS 测量缓存能改善 GP 页面的框选反馈，但没有证据证明节省内存。** 后续应优先处理共享祖先的派生边界与遍历开销。所有候选仅存在于隔离诊断构建，本轮没有修改产品实现或安装 App。

完整脱敏指标见 [JSON](geometry-query-experiment.json)，复现入口见 [实验说明](../../../desktop/tests/performance/geometry/README.md)。

后续查询内缓存的正式接入及重新验收见[接入报告](geometry-cache-integration.md)；下文保留实验构建的测量边界。

## 测量范围

- Apple M4、Mac16,1、24 GiB、macOS 26.6.2，Electron 44.5.1。使用当前源码的冻结副本与生产模式 Studio 构建，匹配的已有组件运行时。
- 两份已有真实项目的离线回放：GP 单画板（画板内约 1,107 个 DOM 元素）；Admin Templates 十画板总览中一个画板（约 600 个 DOM 元素）。所有请求由私有 fixture 接管，不访问真实业务服务，不写线上项目。
- 每个场景、每种实现分别启动三个新进程。顺序为 A/B/C、B/C/A、C/A/B；每进程预热 8 次、计时查询 32 次、原生 Electron 框选 12 次。共 18 个计时进程、576 次计时查询、216 次框选。
- 详细阶段计时、CPU profiler、timeline、内存各自独立运行。正式计时保留三组共有的轻量查询计数器，没有 profiler 或逐次读操作计时。发现其它诊断 benchmark 时等待；已接受轮次未检出重叠。
- 交互指标是**可信 pointerup 捕获到 awaitEval 和两次 requestAnimationFrame 完成**的时间，包含本次几何查询与选择反馈；不包含事件派发前排队，不是 OS 输入延迟或 compositor 呈现时间，也不是连续平移缩放 FPS。

三个实现使用同一个诊断构建，renderer hash 为 `5d8affccd499b73c42a7551af98e17fd4d9b6efb9b1c915b845d685f168cbec7`。冻结的 4,825 个 Studio 源文件指纹及三个被注入文件的前后 SHA-256 保存在 JSON。产品中的三个原文件再次核对，仍等于注入前的 SHA-256。

## 对照实现

| 实现 | 行为 |
| --- | --- |
| baseline | 保持现有节点遍历、DOM 测量、裁剪、矩形判断和父子选择规则；经过共有诊断包装 |
| cached-js | 在一次同步查询中共享 getBoundingClientRect 结果及裁剪所需的 12 个 computed-style 属性值 |
| cached-wasm | 相同读缓存；把最终矩形判断作为一批 Float64 数据交给 Rust WASM，包含打包、调用及结果应用成本 |

缓存仅在查询内存在，返回前释放 Map 和节点引用。没有跨手势快照、后台 Worker、新持久化数据结构或全局 DOM prototype 替换。真实组件、锁定、可选择范围、裁剪、父子去重与选择提交仍走现有实现。

这不是完整几何缓存：`paddingBox()` 中的 offset/client 指标和裁剪祖先遍历尚未缓存。WASM 只承担最终矩形相交/包含判断，不承担 DOM 读取或浏览器布局。

## 交互与查询结果

下表为三个独立进程各自中位数的中位数，单位 ms。

| 场景 | 实现 | 几何查询 | 框选反馈 |
| --- | --- | ---: | ---: |
| GP 业务页 | baseline | 225.25 | 305.45 |
| GP 业务页 | cached-js | 123.05 | 190.90 |
| GP 业务页 | cached-wasm | 125.05 | 194.05 |
| 十画板总览控制场景 | baseline | 0.60 | 60.35 |
| 十画板总览控制场景 | cached-js | 0.60 | 60.95 |
| 十画板总览控制场景 | cached-wasm | 0.60 | 61.90 |

GP 的 JS 缓存使查询减少约 **45.4%**，框选反馈减少约 **37.5%**。三轮反馈中位数分别为：基线 305.3 / 305.5 / 315.7，JS 185.5 / 190.9 / 192.2；每轮 p95 也低于相应基线。它通过本轮预设的交互收益门槛，但约 191ms 仍不是即时反馈。

WASM 相对缓存 JS 没有稳定改善。GP 三轮反馈为 194.1 / 267.2 / 186.5，其中第二轮波动较大；不能把一次较好或较差的结果解释为稳定因果收益。其查询中位数也没有优于 JS。

总览控制场景虽然有 600 个 DOM 元素，该编辑范围查询仅处理 **5 个矩形**，几何计算不是主要成本。原生框选落点的选择结果为空，GP 落点则始终选择 7 个节点；两类场景不能混为同一种业务操作。总览中的尾延迟波动不能归因给亚毫秒级矩形判断，也不能作为复杂业务节点编辑提速的证据。

每进程只有 12 次原生操作，进程内 p95 接近最大值；本轮不推断总体分布的精确尾延迟。逐轮中位数、p95 与选择结果摘要均保留在 JSON。

## 瓶颈归因

GP 每次查询处理 1,803 个矩形。查询内复用将实际边界读取从 **22,793 次降到 373 次**，computed-style 获取从 **100,486 次降到 451 次**；请求次数没有通过少查节点来减少。

独立阶段采样中，基线查询中位数约 277ms，裁剪路径约 223ms；JS 缓存分别约 136ms 和 92ms。裁剪时间包含内部样式、边界读取，不能把嵌套指标相加。最终矩形判定约 0.1–0.2ms 量级；WASM 打包约 0.1ms，内核常低于约 0.1ms 的计时分辨率，**不是零成本**。

源映射 CPU 采样进一步定位到 `visible-bounds.ts` 的 `paddingBox`、`clipSources`。基线 paddingBox 自耗时约 4.0s，缓存 JS 仍约 4.1s（整个相同 profile 工作负载，非单次查询）。这与它仍反复访问 offsetWidth、clientWidth、clientLeft 等指标的代码路径一致：缓存 getBoundingClientRect 没有消除全部派生边界测量。

timeline 中 GP 整轮 Layout 累计约 57–58ms，远小于数秒级 JS/裁剪工作。不能把十万次样式访问都解释成强制 reflow。明确的下一处 JS 优化候选是**查询内共享祖先 padding box / 裁剪结果，减少重复祖先遍历**，并复验定位包含块、fixed/absolute、内部滚动等规则；本轮没有继续修改候选或将该推测写成收益。

## 内存

每场景每组两次新进程，按 A/B/C 与 C/B/A 执行；每进程做 240 次查询，按 80 次记录阶段样本。先记录自然占用和静置结果，最后才做诊断 GC。计时轮没有强制 GC。

下表为两次独立进程的范围，单位 MiB。RSS 是本 App 的 renderer working-set/RSS 合计，100ms 采样的峰值，不是精确瞬时峰值、物理 footprint 或整套 App 的实际物理内存。

| 场景 | 实现 | 自然 renderer RSS 峰值 | 最终诊断 GC 后 V8 used heap |
| --- | --- | ---: | ---: |
| GP | baseline | 1503–1627 | 135.57–135.95 |
| GP | cached-js | 1612–1626 | 134.99–135.48 |
| GP | cached-wasm | 1658–1667 | 135.42–135.71 |
| 十画板控制场景 | baseline | 1012–1019 | 248.37–248.37 |
| 十画板控制场景 | cached-js | 1006–1007 | 248.20–248.50 |
| 十画板控制场景 | cached-wasm | 1005–1009 | 248.25–248.32 |

没有观察到查询缓存持续保留模型或 DOM 的堆增长，回收后的差异很小；不能据此证明所有场景无泄漏。GP 的 JS 峰值与基线波动范围重叠，没有稳定内存节省；WASM 的 GP 峰值在本轮略高，也没有内存收益证据。

WASM 文件为 5,247 bytes，线性内存逻辑容量为 1,114,112 bytes（1.0625 MiB）。这不是全部驻留物理内存，不与 RSS、used heap 或 backing-storage 指标直接相加。正式计时进程的编译/实例化等待约 0.2–0.4ms，不含文件读取或网络下载。单独内存轮有更高等待值，原值保留在 JSON。

## 正确性与处置

- 三组分别运行现有框选/裁剪测试及内核、缓存生命周期测试，各 **28 项通过，共 84 项**。内核每组还对 96,000 个有限、分数、零尺寸及负尺寸输入组合与实际 Box 规则逐项比较。
- 两份真实模型完成 **23 类功能场景**，包含缩放、平移、隐藏、变换、裁剪尺寸变化、GP 内部滚动，以及真实模型修改和撤销/重做，执行 Site invariants 检查。
- 两份项目各 9 个正式计时进程的原生选择完整标识摘要一致，查询选择数序列一致；原生事件均可信、只执行一次几何查询，选择提交数量一致且模型计数未变。反馈探针断言包含本次查询耗时。
- 隔离生产模式构建、Rust WASM 编译、五个 Node 脚本语法检查通过。没有新增产品依赖，没有部署或更新安装包。

**决定：WASM 不进入产品。JS 查询内缓存有明确的重几何场景交互收益，作为后续落地方向保留；不能以降低内存或实现 60/120 FPS 为理由宣传。** 产品接入前仍需验证没有诊断包装时的收益、峰值内存与完整交互回归；后续优化优先沿现有 DOM 几何路径推进。

原始 fixture、profile、trace、CPU profile、截图与构建保存在 `/tmp/plasmic-geometry-26fk__p2`，未提交业务模型或凭据。早期静态源地址、路径别名/入口预跑、一个停止的旧功能轮均不计入成绩。首次 profile 有阶段计数与 timeline，但未取得独立 CPU profile；CPU 归因使用显式启用 Profiler 后重跑的 GP 第 2 轮。所有正式计时和内存轮均无 renderer error。
