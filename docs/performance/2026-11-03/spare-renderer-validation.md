# Electron 45 备用渲染进程 A/B 验证

结论：预热能带来几十毫秒的启动收益，但当前不建议默认启用。GP 全画板就绪中位数仅改善约 25ms（1.1%），十画板全部就绪仅改善约 8ms（0.2%）；返回列表 5 秒后的进程工作集总和增加约 48MiB，确认被下一次编辑器使用的备用进程自身约为 64MiB。产品配置未启用预热，也未修改生产 main/preload 的语言传递方式。

## 预热资格和比较范围

当前 Studio 用 `additionalArguments` 传系统语言。原生资格探针使用生产 `StudioWindow`、隔离的持久化 session、固定本地 HTML 和五次编辑器创建/销毁：

| 配置 | 关闭预热 | 开启预热 |
| --- | ---: | ---: |
| 带当前语言启动参数 | 0/5 次复用既有进程 | 0/5 次复用既有进程 |
| 无额外启动参数 | 0/5 次复用既有进程 | 5/5 次复用既有进程 |

探针不预先创建默认 session；持久化 session 本身可以使用常驻预热池。既有进程必须在创建编辑器前已经出现在 OS 进程指标中，并在随后承载编辑器。创建新 PID 不算预热命中。这个资格限制与 [Electron 的实现说明](https://github.com/electron/electron/pull/53116) 一致。

真实十画板项目另外以生产参数各运行六次开关对照，两侧均为 0/6 次复用，耗时接近。因此仅添加 Chromium 开关无法为当前配置提供预热收益。

下述正式 A/B 使用兼容参数模式，隔离开关本身的效果：两侧都不传额外参数，使用同一个诊断 preload、生产 `StudioWindow` 和同一份冻结前端。没有实现生产语言初始化的替代方案，这不是可直接发布的产品候选。它衡量的是解决参数兼容问题之后能获得的收益。

## 反复打开耗时

macOS arm64，Electron 45.2.1。固定 GP 单画板和复杂十画板真实项目的离线载荷及精确依赖；前端资源指纹、夹具 SHA256 和逐轮数据见 [脱敏测量](./spare-renderer-measurements.json)。排除线上 API/IAM 延迟和生产草稿桥接，不写线上项目。

每个样本按关 / 开 / 开 / 关（ABBA）运行四个独立进程，每进程打开八次，前两次预热，后六次计时，即每种策略每项目 12 个计时样本。正式轮串行运行，不混跑构建、测试、trace 或强制 GC；操作系统文件缓存不受控。开启组的 32/32 次项目打开均使用已存在的进程，关闭组为 0/32。返回列表通过实际品牌链接触发。

| 指标，中位数 | 关闭 | 开启 | 改善 |
| --- | ---: | ---: | ---: |
| GP 首画布揭示 | 2165.6ms | 2140.8ms | 24.8ms / 1.15% |
| GP 全画板就绪 | 2185.2ms | 2160.6ms | 24.6ms / 1.13% |
| 十画板首画布揭示 | 2012.1ms | 1980.5ms | 31.6ms / 1.57% |
| 十画板全部就绪 | 4411.1ms | 4403.1ms | 8.0ms / 0.18% |

首画布和全画板使用 Studio 自身的 performance mark，不是合成器呈现或操作系统输入延迟；外部轮询时间另保留在 JSON 中。两个项目均有小幅收益，但这不代表模型解析、组件加载或布局计算加速，也不据此声明统计显著性。

## 返回列表后的内存

内存与计时分轮。十画板项目同样按 ABBA 运行四个进程，每进程六次打开/返回；每次返回后 500ms、1 秒、5 秒采样，不连接 debugger、不强制 GC。前两次预热，后四次统计，每策略每时间点八个样本。

| 返回后的进程工作集总和，中位数 | 关闭 | 开启 | 增加 |
| --- | ---: | ---: | ---: |
| 500ms | 912.9MiB | 968.6MiB | 55.6MiB |
| 1 秒 | 754.1MiB | 810.0MiB | 55.9MiB |
| 5 秒 | 742.3MiB | 790.5MiB | 48.3MiB |

所有 24 次循环的旧编辑器顶层 PID 均退出，其子 frame 的 OS PID 也没有在返回采样中残留。开启组为 12/12 次复用，关闭组为 0/12；没有用保留旧编辑器来换取打开速度。

在开启组的六个可与下一次打开对应的暖采样中，5 秒时的空闲进程 PID 均成为下一次编辑器 PID，其工作集中位数为 **64.34MiB**；关闭组没有这类匹配。`unownedRenderers` 仅指未归属顶层 WebContents 的候选进程，可能包括子 frame，不能直接把候选进程全部认作备用进程。

这些数值是 App 进程 working-set 之和，包含夹具后端所在主进程、GPU 等，并会重复计算共享页；不是系统新增物理内存的精确值。总差额不要求等于备用进程自身工作集。

## 功能与决策

- 开启组的 GP 功能回放通过编辑、撤销重做、实际 DOM 样式、画板位置、Preview 分页、完整客户端保存及重开。
- 开启组的十画板功能回放通过编辑、撤销重做、实际 DOM 样式、位置、冷画板恢复及保存重开。保存由隔离 fixture 确认。
- 正式计时、内存和功能轮的 renderer error 均为零。Dashboard 缩略图离线 fixture 的既有错误仍存在：计时各组每次九个、内存各组每次七个；两侧一致，不作为缩略图业务验收通过。
- 内存仅采用 `final-memory-*` 四组；资格探索、调试和中断轮不计分。最终内存轮的诊断脚本和产品 owner/资源处理源码指纹在采样前后保持一致。

综合收益与常驻内存，以及尚需完成的语言参数迁移，保持产品默认配置。诊断开关只位于 `desktop/tests/performance`，不进入发布包。

原始模型、日志、截图和隔离 profile 保存在本机 `/tmp/plasmic-spare-20261103/`；仓库 JSON 只记录脱敏指标和指纹。复现入口及环境变量见 [诊断说明](../../../desktop/tests/performance/README.md)。
