# 框选几何缓存接入与验收

已将查询内测量缓存接入正式框选路径。正式实现没有诊断全局变量、WASM、异步查询或新包依赖。完整指标见 [JSON](geometry-cache-integration.json)，前期三组实验见[实验报告](geometry-query-experiment.md)。本轮未安装或发布 App。

## 实现与生命周期

`getSelectableLayers()` 每次创建一个 `GeometrySnapshot`，共享元素边界和裁剪相关的 12 个样式属性值。样式为普通值副本，不缓存 live CSSStyleDeclaration。画板边界和缩放在查询开始读取一次，用于统一坐标转换。

快照由函数局部变量持有，同步查询返回后不保留；选择提交仍在查询完成后通过原有 `vc.change()` 执行。没有跨滚动、编辑、撤销、组件重新渲染或下一次手势复用的状态。锁定、隐藏、非选择节点、组件边界、父子去重与 Shift 追加规则保持原有路径。

共享裁剪函数接收显式快照；悬浮框、边缘揭示等未传入快照的调用保留原有测量行为。没有缓存 paddingBox 的 offset/client 指标或重写包含块判断，也没有改变滚动容器、组件 props、编辑状态及保存格式。

## 验证

- 三个专项测试文件共 **31 项通过**，包括已有框选与裁剪测试，以及共享祖先复用、样式副本、下一次查询重新测量、画板移动和 fixed/absolute 包含块规则。
- `pnpm --dir platform/wab typecheck --incremental false` 完整类型检查通过；隔离生产模式 Studio 构建通过。
- GP 和十画板真实 fixture 分别通过 **12 / 11 类几何功能场景**，与原算法逐项比较完整选择标识，覆盖缩放、平移、隐藏、变换、尺寸/裁剪变化、内部滚动、模型编辑及 undo/redo。
- 另通过 **11 项原生功能检查**：画板切换、重命名撤销/重做、真实 DOM 样式恢复、画板位置恢复、GP Preview 业务分页。两份模型均完整保存到隔离内存服务并重新打开，保存前后完整 bundle 和 revision 一致。没有写入真实后端。
- 两种实现、两个项目、各三个新进程，共 **144 次原生框选、384 次计时查询**，完整选择标识摘要及查询选择数序列一致，模型计数未变。GP 的基线/候选截图已检查，选择的 7 个图层、选框和业务布局一致。

原算法从明确的 Git revision 读取，并校验与前轮实验相同的 SHA-256。两组使用同一个构建，仅私有副本的函数边界计时；正式代码没有计数器或计时逻辑。构建 hash：`3dc333890bdbd4a82827648e760947fac1523a79bed1aaeb42a1588c377cbee3`。

## 正式代码的 A/B 结果

Apple M4、24 GiB、Electron 44.5.1。单位 ms，为三个独立进程中位数的中位数。每进程预热 8 次、计时查询 32 次、原生框选 12 次；两组以交替顺序串行运行，检测到其它诊断 benchmark 时等待。

| 场景 | 实现 | 查询 | 框选反馈 |
| --- | --- | ---: | ---: |
| GP | 原算法 | 222.50 | 301.55 |
| GP | 正式缓存实现 | 120.95 | 183.75 |
| 十画板总览控制场景 | 原算法 | 0.60 | 59.80 |
| 十画板总览控制场景 | 正式缓存实现 | 0.50 | 59.85 |

GP 查询减少约 **45.6%**，反馈减少约 **39.1%**。三轮反馈 p95：原算法 354.3 / 334.0 / 336.8，缓存 210.2 / 216.0 / 204.1。总览的本次编辑范围只有少量可选矩形，未见明显提速或持续回退；不能用画板/DOM 数量推断查询成本。

反馈是可信 pointerup 捕获至求值完成和两次 rAF，不包含事件派发前排队、OS 输入或屏幕呈现时间，也不是平移缩放 FPS。所有结果来自离线真实模型回放，不是线上 SLA。

早期总览轮只等待活动画板，最初一两次操作出现数百毫秒尾峰。该批数据保留在 `early-overview-timing/`，不混入本表。总览已在显式等待 `all-frames-rendered` 后重新完成六个新进程；本表对应 JSON 均记录 `allInitialFramesReady=true`。GP 为单画板，其原生操作前已有 40 次查询/预热，不涉及其它初始画板加载。不能把排除启动干扰后的尾峰下降归给缓存代码。

## 内存

GP 两组各两次新进程，按原版/缓存及缓存/原版顺序执行，每进程 240 次查询。自然占用先记录，最后才执行诊断 GC；计时轮不强制 GC。

| 实现 | 自然 renderer RSS 峰值，两次 / MiB | 最终 GC 后 V8 used heap，两次 / MiB |
| --- | ---: | ---: |
| 原算法 | 1518.5 / 1737.9 | 136.73 / 136.04 |
| 正式缓存实现 | 1478.0 / 1681.8 | 135.27 / 135.74 |

没有观察到缓存持续保留 DOM 或模型的堆增长。两次缓存峰值略低，但进程间波动大于差额，不认定稳定内存节省。RSS 为 App renderer working-set 合计和 100ms 采样，不是实际物理 footprint 或精确瞬时峰值。诊断 GC 后占用也不代表正常产品会即时释放到这个数值。

## WASM 候选范围

本次矩形内核无额外收益，不代表项目没有适合的 WASM 用途。

| 当前模块 | 已核实的实现 | 判断 |
| --- | --- | --- |
| `.pen` 脚本执行 | QuickJS WASM，限制内存、栈和执行时间，不暴露宿主 DOM/文件/网络回调 | 已在使用，主要价值是隔离执行与引擎复用，未声称提速 |
| `desktop/src/raster-vector.cjs` | 同步 PNG 解码及 ImageTracer 像素描摹 | 候选；可先测 PNG 往返转换、描摹及线程阻塞，再比较 Worker JS 与 WASM 内核 |
| `desktop/src/vector.cjs` | Paper.js 路径布尔运算 | 复杂路径候选；需同时验证轮廓、孔洞、面积、边界和输出质量 |
| `.fig` 导入 | Worker 内 fflate / fzstd 解压及 Kiwi 解码 | 候选；需先分段测量解压、解码、节点转换和最终插入，不能只比解压函数 |

以上性能候选尚未做 WASM 对照，不报告收益。图像预览已有 sharp，应把现有实现作为基线。对象图打包与 DOM 读取需要不同的边界治理，不能简单整体搬入 WASM。若继续研究，优先选择输入/输出能批量传递的位图描摹或复杂路径任务。

复现使用[生产接入验证入口](../../../desktop/tests/performance/geometry/README.md#product-integration-validation)。私有构建、原始日志、截图和 fixture replay 结果在 `/tmp/plasmic-geometry-product-hw6vbxjw`；仓库 JSON 仅保留脱敏统计、功能结果与源码指纹。
