# 代码验收规范

## 开始实现前

按已确定的需求和设计版本核对[原型清单](../workflows/codegen.md#3-核对原型清单并建立实现契约)，明确各项的触发与可观测结果，以及适用的路由、视口、数据、权限和未知项。

## 设计到代码的一致性

沿用实现前的原型清单逐项验收。按[组件契约](project-code.md#组件契约与复用)核对关键结构、组件职责和内容归属在实际渲染位置的落实，包括普通容器。对照真实入口中对应的页签、区块和状态，回填结构、适用的运行行为与视觉的实际结果和证据。按[实现后审查](review.md)补回原型查漏发现的范围内缺项。修复后重新验证受影响项及共享消费者。

按[逐场景截图验收](visual-acceptance.md)为每个范围内的变体、隐藏状态、条件入口和面板保存设计与实现成对截图、具体差异分析、修正及复验记录，并执行 `verify_codegen_visual.py check`。场景清单同时核对完整保存模型和原始来源；缺场景、缺任一端截图或缺修正复验不能通过视觉验收。门禁通过后仍须审查画面及真实状态，不能将证据结构通过当作视觉判断通过。

## 检查顺序

按目标 `package.json` 的实际命令执行相关类型检查、必要测试与构建，不假定脚本名称。区分既有错误与此次变更，报告实际结果，不删断言、降类型或忽略失败。结果作为实现后审查的证据，不替代审查。

测试聚焦行为和易回归边界：数据转换、合法 `0`/`false`、请求竞态、表单校验、提交锁、保存/刷新失败和权限等；不以源码存在某个字符串证明行为正确。小型静态布局不必建立镜像测试。检查通过后只因新变更或未解问题再次扩大验证。

从真实入口检查路由/Provider/宿主，不另建预览应用。按[Service 验收](services.md#验收与证据)分别报告网络/本地模拟和真实接口/权限联调。缺浏览器、认证或依赖时保留限制，继续独立检查。

## 按涉及场景验收

| 范围 | 可观测的通过条件 |
| --- | --- |
| 结构与复用 | 源设计的组件职责、内容归属与状态/事件关系落实到实际渲染区域；转换有依据，无遗漏或无依据的重写 |
| 页面接入 | 目标 route 可进入；Provider、宿主、图标、主题、资产接入正确 |
| 查询/分页 | 表单与实际参数一致；查询回正确页；total 正确；一次动作不重复请求 |
| 数据闭环 | 按 Service 规范核对契约、模拟链路、读写/状态/权限及失败恢复；单测不替代页面验收 |
| 状态 | 区分失败与成功空结果；失败结束 loading、保留适用数据和输入、恢复操作，不逐请求状态新增 UI |
| 编辑会话 | 开 A → 关闭 → 开 B，无陈旧值/错误/响应；动画完整；未保存策略一致 |
| 表单 | 边界按实际业务规则；无效时不请求；隐藏/折叠字段正确；错误可定位 |
| 提交 | 连续点击/Enter 不重复写；确认与 payload 相同；失败保留输入；锁最终释放 |
| 反馈 | 按[反馈职责](interactions.md#反馈职责)检查单次 toast、无额外失败 UI、专门结果的需求与业务依据；刷新失败不误报保存失败或重发写请求 |
| 权限 | 入口过滤在折叠前；只读无写路径；禁止根据 role/name 假定授权 |
| 视觉 | 对齐设计与实现的视口、有效内容宽度、数据和状态，比较层级/间距/密度/长文本，无重复 shell/padding |
| 可用性 | 宽表横滚与关键操作可达；要求的窄视口、RTL、长翻译、焦点与键盘正常 |

对清单中的每个适用检查分别记录通过、不符或未验证。浏览器、认证或数据不可用时，在对应项标明未验证及原因，并继续可执行的结构检查。截图仅证明所示状态的视觉。整页一致性通过要求范围内所有适用项都有通过证据。

## 交付证据

报告源项目/页面 UUID、revision（缺失注明）、CLI/资源版本与 releaseId；文件/路由、依赖与转换依据、数据/权限假设及模拟范围。分别给出结构、工程检查、运行行为和视觉的覆盖、证据与未验证项，互不替代；附审查方式、修复复核结果及未解决影响。已发现问题关闭不代表完整验收通过。

说明放任务交付中，不注入业务界面。交付目标项目代码，不自动发布设计、包或应用。
