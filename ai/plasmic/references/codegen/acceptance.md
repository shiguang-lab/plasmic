# 代码验收规范

## 开始实现前

记录输入/触发与可观测结果，明确源页面、目标路由和视口、实际使用的组件、数据/权限契约及未知项。验收依据需求和读取的模型；不能以“代码已生成”作为可运行结论。

## 检查顺序

读取目标 `package.json` 的实际命令，执行受影响的类型检查、必要测试与构建。不要假定每个工程都有 `type-check` 或复制参考工程的专用测试脚本。若已有错误阻塞，区分既有错误和此次变更，报告实际结果，不删断言、降类型或忽略失败。

测试聚焦行为和易回归边界：数据转换、合法 `0`/`false`、请求竞态、表单校验、提交锁、保存/刷新失败和权限等；不以源码存在某个字符串证明行为正确。小型静态布局不必建立镜像测试。检查通过后只因新变更或未解问题再次扩大验证。

通过真实项目入口运行，检查路由/Provider/宿主集成，不为验收新建绕过应用上下文的第二套预览应用。Mock 验证与真实接口/权限联调分别报告。无浏览器、缺认证或缺组件包时，完成其余可执行检查并标注具体限制。

## 按涉及场景验收

| 范围 | 可观测的通过条件 |
| --- | --- |
| 页面/组件 | 目标 route 可进入；imports、Slot、图标、主题、资产与实际实现一致 |
| 查询/分页 | 表单与实际参数一致；查询回正确页；total 正确；一次动作不重复请求 |
| 状态 | loading、空、失败、无权限、只读能区分；局部错误不丢失适用数据 |
| 编辑会话 | 开 A → 关闭 → 开 B，无陈旧值/错误/响应；动画完整；未保存策略一致 |
| 表单 | 边界按实际业务规则；无效时不请求；隐藏/折叠字段正确；错误可定位 |
| 提交 | 连续点击/Enter 不重复写；确认与 payload 相同；失败保留输入；锁最终释放 |
| 保存/刷新 | 成功一次反馈；刷新失败不会伪装保存失败或重试写操作 |
| 权限 | 入口过滤在折叠前；只读无写路径；禁止根据 role/name 假定授权 |
| 视觉 | 与页面设计在同视口比较；层级/间距/密度/长文本一致，无重复 shell/padding |
| 可用性 | 宽表横滚与关键操作可达；要求的窄视口、RTL、长翻译、焦点与键盘正常 |

覆盖真实存在的条件分支和状态，不为不存在的功能添加实现。静态截图可证明当前视觉，不能证明点击、校验、保存或 responsive 运行逻辑。

## 交付证据

说明源项目/页面 UUID、可取得的设计 revision、CLI/资源版本与 releaseId；生成或修改的文件/路由、实际依赖版本和使用的组件；数据、状态、权限假设与模拟范围；实际执行的命令和结果、视觉/交互验证、未解决依赖。

说明放任务交付中，不向业务界面注入版本横幅、Agent 实现说明或模拟开发控件。产物是目标架构中的项目代码；生成结束不自动发布设计、npm 包或应用。
