# 代码验收规范

## 开始实现前

依据需求和源模型记录触发与可观测结果、页面/路由/视口、组件职责、数据/权限及未知项；不从生成代码反推检查范围。

## 设计到代码的一致性

按[实现后审查](review.md)分方向委派，覆盖组件映射及适用的行为、工程与证据判断；不可委派则当前会话逐方向执行。记录合并/回退原因，修复后由受影响方向复核。无需逐节点填表或新增机械门禁，未知项不标记通过。

## 检查顺序

按目标 `package.json` 的实际命令执行相关类型检查、必要测试与构建，不假定脚本名称。区分既有错误与此次变更，报告实际结果，不删断言、降类型或忽略失败。结果作为实现后审查的证据，不替代审查。

测试聚焦行为和易回归边界：数据转换、合法 `0`/`false`、请求竞态、表单校验、提交锁、保存/刷新失败和权限等；不以源码存在某个字符串证明行为正确。小型静态布局不必建立镜像测试。检查通过后只因新变更或未解问题再次扩大验证。

从真实入口检查路由/Provider/宿主，不另建预览应用。按[Service 验收](services.md#验收与证据)分别报告网络/本地模拟和真实接口/权限联调。缺浏览器、认证或依赖时保留限制，继续独立检查。

## 按涉及场景验收

| 范围 | 可观测的通过条件 |
| --- | --- |
| 结构与复用 | 源设计的组件职责、内容归属与状态/事件关系落实到实际渲染区域；转换有依据，无遗漏或无依据的重写 |
| 页面接入 | 目标 route 可进入；Provider、宿主、图标、主题、资产接入正确 |
| 查询/分页 | 表单与实际参数一致；查询回正确页；total 正确；一次动作不重复请求 |
| 数据闭环 | 按 Service 规范核对契约、模拟链路、读写/状态/权限及失败恢复；单测不替代页面验收 |
| 状态 | 区分失败与成功空结果；失败结束 loading、保留适用数据和输入、恢复操作，不逐请求状态新增 UI |
| 编辑会话 | 开 A → 关闭 → 开 B，无陈旧值/错误/响应；动画完整；未保存策略一致 |
| 表单 | 边界按实际业务规则；无效时不请求；隐藏/折叠字段正确；错误可定位 |
| 提交 | 连续点击/Enter 不重复写；确认与 payload 相同；失败保留输入；锁最终释放 |
| 反馈 | 按[反馈职责](interactions.md#反馈职责)检查单次 toast、无额外失败 UI、专门结果的需求与业务依据；刷新失败不误报保存失败或重发写请求 |
| 权限 | 入口过滤在折叠前；只读无写路径；禁止根据 role/name 假定授权 |
| 视觉 | 与页面设计在同视口比较；层级/间距/密度/长文本一致，无重复 shell/padding |
| 可用性 | 宽表横滚与关键操作可达；要求的窄视口、RTL、长翻译、焦点与键盘正常 |

覆盖真实存在的条件分支和状态，不为不存在的功能添加实现。静态截图可证明当前视觉，不能证明点击、校验、保存或 responsive 运行逻辑。

## 交付证据

说明源项目/页面 UUID、可取得的 revision、CLI/资源版本与 releaseId；文件/路由、依赖版本、组件及转换依据；数据/权限假设和模拟范围。分别报告结构与复用、类型/测试/构建、运行行为、视觉的证据及未验证项，任一类通过不替代其他类；附审查方式、修复复核结果、未解决依赖及影响。

说明放任务交付中，不向业务界面注入版本横幅、Agent 实现说明或模拟开发控件。产物是目标架构中的项目代码；生成结束不自动发布设计、npm 包或应用。
