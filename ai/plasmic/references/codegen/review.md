# 实现后审查

实现与可执行检查完成后，按设计一致性、行为正确性、工程质量三个方向审查原始需求、设计契约和最终代码。组件映射属于设计一致性的必查专项；按实际改动启用相关方向，局部更新覆盖改动和共享消费者，不扩展为全仓重构。

## 审查方式

默认为每个启用方向分别委派独立 subagent，各自从原始来源审查产物。仅在范围小且判断高度依赖同一上下文时合并，并记录覆盖方向与理由；不把所有方向默认交给一个审查者，也不按节点、文件或单个检查项机械拆分。并发槽位不足时按方向串行委派，不因此合并职责。

核实宿主实际委派工具、子 Agent 访问能力与结果返回能力，不按客户端或模型名称推断。独立审查使用不继承实现历史的新上下文；复用同一会话切换角色或继承历史的 fork 不算多个独立审查者。

不支持委派、用户禁止、缺少隔离/必要访问或无法取得有效结果时，在当前会话逐方向分别审查，保留相同范围并记录各方向回退原因，不跳过或声称独立通过。可按访问能力分配静态与运行检查；缺浏览器不免除源码审查，也不使运行/视觉检查通过。不为委派安装工具、改权限或另起外部 Agent。

## 交接与职责

提供原始需求/设计路径与版本、两端组件契约、适用规范与资源版本、目标仓库规则、改动范围和最终文件（含新增文件）、路由及已有验证日志。保留实现契约中的转换理由供核实，但不把实现者的推理或“已通过”结论作为审查依据。审查者须读取原始来源与实际产物，也检查实现计划遗漏的要求。

每项委派明确方向、范围、所需来源与交叉项负责人。组件事件签名/槽位转换由设计方向核对，事件如何驱动业务状态与请求由行为方向追踪。发现超出本组范围的问题仍返回证据和建议归属，由主 Agent 分派，不能因职责边界漏掉问题。

委派仅限审查：审查者亲自核对源码、调用方和可用证据，可运行适用检查并记录报告，不改业务代码、设计或验收预期，不再次委派。主 Agent 负责判断问题、修复与交付。双方遵守相同的源码访问边界；工具成功、组件导入或实现者自述均不能替代证据。

审查期间保持被审查文件稳定，以提交、diff/文件快照或内容哈希标识实际范围；无需另建工作树。各组可并行只读源码；共享浏览器或 Desktop 同时仅一个控制者，交接后再操作。相关审查者未归还控制或状态不明时，不修改其被审查文件或争用会话。上下文隔离不等于文件或浏览器隔离。

## 审查范围

| 方向 | 同一审查者负责的相关判断 |
| --- | --- |
| 设计一致性 | 源页面、依赖及隐藏/条件分支中的组件职责、槽位、布局、默认值和状态/事件契约是否落实到实际渲染区域？包装内部及目标公开契约是否支持转换？是否擅自增加请求失败 UI？专门结果是否有需求/设计及业务依据，而非仅由 `error` 触发？有可用视觉证据时，对照同视口设计核对层级、密度、反馈和操作可达性；无证据则保持未验证。 |
| 行为正确性 | 真实用户流程及失败/边界分支是否成立？数据、状态、校验、提交、权限与恢复是否正确，事件参数是否驱动预期状态和请求？按[交互规范](interactions.md)追踪业务效果及[反馈职责](interactions.md#反馈职责)：提示时机、次数、关闭后可见性和失败恢复是否正确？ |
| 工程质量 | 是否遵循[项目规范](project-code.md)，正确接入宿主、路由、Provider、公共能力及依赖？职责和依赖方向是否清晰，有无重复实现、无关抽象或失效代码？请求层与页面是否重复承担提示，是否另建错误展示框架？工程检查是否覆盖改动及共享消费者？ |

每组都按[验收规范](acceptance.md)核对自身范围内证据的真实性、版本与覆盖，不用实现者自述或其他组通过替代判断。源码不能证明视觉/运行通过。主 Agent 汇总各方向的发现和未验证项，不另设默认的全量重复审查。

组件映射按[契约与复用](project-code.md#组件契约与复用)判断，允许合理组合、宿主接管、不同 API 和原生内容；不要求 DOM 一一对应。实际渲染位置与绑定才是依据，同名组件、import、相似 CSS 或其他区域使用了组件都不充分。

自动检查用于可机械验证的事实，Agent 审查负责来源解释、转换合理性、职责划分和证据充分性。不用组件名清单、正则或新固定报告 schema 代替这些判断；审查也不替代已有的类型检查、必要测试与运行验证。

## 发现、修复与复核

在现有任务记录中按方向写明审查方式、审查者、检查范围/版本、合并或回退原因和未执行项。问题包含源要求、代码位置、预期与实际差异、影响和证据；区分确认缺陷、合理转换与待确认项，不把个人偏好作为必须修改的要求。无发现时也说明覆盖范围及证据限制，不只返回“通过”。

主 Agent 汇总去重、明确问题归属；结论冲突时回到来源与代码核实，不按多数票或最宽松意见裁决。核实后修复，或记录拒绝误报的依据，不能因失败而换审查方式或丢弃结果。修复后重跑受影响检查，交回受影响方向复核新代码及相关调用方/流程；跨方向改动覆盖相关组，无需无差别重审全部。不可委派则在当前会话逐方向复核并说明，旧结论不能证明修改后通过。

结束前确认已发现的必需修复均解决，或明确未解决问题、影响和阻塞条件；缺失证据保持未验证。反复修复仍不能收敛时记录事实和待澄清点，不无限重试或制造通过结论。交付沿用[验收证据](acceptance.md#交付证据)，附实际审查方式与结论。
