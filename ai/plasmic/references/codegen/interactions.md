# 数据与交互规范

## 状态所有权

| 行为 | 所有者 |
| --- | --- |
| 列表数据、已提交筛选、分页、当前 Tab/目录 | 页面或独立列表区域 |
| 正在编辑的对象与模式 | 发起操作的父级 |
| 表单、详情、私有选项、校验、保存及关闭策略 | 编辑 Drawer/Modal |
| 单行操作、确认与提交锁 | 行操作组件 |
| 真正共享的目录/选项 | 最近共同父级，一次获取后复用 |
| 保存后的列表刷新 | 列表所有者，通过完成事件协调 |

props 表达业务输入与结果，例如 `item`、`mode`、`onSaved`、`onClose`，不暴露父级 setter 或逐项传入表单/请求/转换函数。表单不进入全局 store；全局状态只用于实际跨区域消费的上下文。React render 保持纯粹，写请求由明确用户动作触发；沿用目标 Hook 和请求封装，不强制安装 ahooks/Zustand。

## 查询与请求

区分搜索草稿与已提交条件。查询/重置同步实际参数并通常回到第一页；Enter 和查询按钮走同一入口。分页确认服务端/客户端所有权，服务端 total 不使用当前页长度替代，不二次切片服务端结果。用稳定业务 ID 作 `rowKey`。

请求路径为组件/Hook → service → 项目请求层。HTTP/认证错误、业务响应解包、业务错误提示各由既有责任层处理一次。service 返回类型化数据；页面管理可恢复状态，不重复 toast、不再次解包、不单独注入 token 或作用域。调用参数和返回值以目标 request 实现为准，不把其他项目的封装当作 Axios，也不编造 API、响应 envelope 或权限点。

弹层打开且标识有效后才请求私有详情。过滤/实体/作用域变化、关闭卸载后，旧响应不得覆盖当前会话；使用已有取消机制或请求序号，只在真实 service 支持时传 AbortSignal。缓存 key 包含相关实体、查询和作用域。若宿主已以作用域 key 重挂载路由，不在每页增加重复刷新 Effect。

远程选项用已有组件，搜索去抖和过期保护服从需求；保留当前选中值及文案，选项暂未加载不等于绑定失效。分页参数、防抖时长、选项反查方式依照实际组件/接口，不复制参考项目的常量或 API。

## 表单与校验

Form 是标准字段的单一主要数据源，使用类型化 `Form.Item name`；不逐字段再建 useState 双向同步。读取实际 value/change 绑定，Checkbox 等按真实契约设置。异步详情不靠 `initialValues` 自动更新，在当前会话明确初始化，后续选项变化不覆盖已编辑字段。

为实质表单字段明确：含义/API 值、可空性、初值、创建/编辑/查看下的可编辑性、归一化、校验来源、错误位置与依赖变化。不擅自加必填、正则、长度、自动 trim、大写或字段唯一性规则。日期确认时区/格式，JSON 同时校验语法与业务结构，解析失败不以空对象提交。

条件字段明确保留/清除/排除 payload 策略；不再有效的隐藏字段不阻塞提交，折叠但有效的字段仍校验且能展开定位。动态列表的稳定 ID/NamePath 维持值、错误与顺序对应；不因联动选项变更保留非法值或清除仍合法值。

提交前校验完整有效表单，错误显示在字段附近，并先展开隐藏分区再定位首个错误。校验失败不请求、不清空、不关闭；异步校验必须对应当前值/会话，网络失败不伪装“已存在”。后端明确字段错误对应关系才能定位，不解析自然语言猜字段。编辑不可变字段以禁用控件保留当前编辑语义；纯详情可用文本。

## 弹层与提交

弹层选择一种生命周期：常驻受控 `open`，或按编辑会话挂载、内部关闭后在退出动画完成时通知父级卸载。关闭动画期间保留标题/数据，不能点击取消立刻清空选中项；A → B 不残留 A 的值、错误或旧响应。使用当前版本公开生命周期 API，不假设 `destroyOnHidden` 清除所有外部 Form/Hook 状态。

X、取消、Esc、遮罩执行一致的关闭策略。脏状态比较当前有效保存值与会话基线，修改后还原能判为无变化；只按产品要求确认放弃。嵌套 Diff/确认弹层有独立开关和清理时机。

保存流程：收集值 → 校验/契约归一化 → 形成 payload 快照 → 按需求确认 → 共享提交锁 → 结果 → 关闭/刷新。归一化影响合法性时校验实际提交值。确认展示与 payload 相同；返回编辑后快照失效。普通保存不默认增加确认或 Diff。

同步设置逻辑提交锁并在 finally 释放，loading 只负责展示；点击、Enter、onOk 共享防重入口。提交期间冻结影响 payload 的输入，阻止不安全关闭。失败保留输入和确认上下文，不能自动重试非幂等写请求或静默覆盖版本冲突。

保存成功与刷新失败分开：`onSaved` 通知拥有者刷新，`onClose` 表示可卸载时机；刷新失败提供重试刷新，不显示保存失败并重发写请求。成功反馈只发生一次，提示 holder 不随关闭立即消失。

## 操作与状态反馈

区分初次加载、查询空结果、请求失败、缺前置选择、无权限和提交中，优先局部状态。失败可重试且保留适用的内容，不伪装空列表。

复用 ActionGroup 时先过滤权限再折叠，保留 danger/disabled 和稳定 key。已有后台约定下，单项行内删除/启停等轻量确认优先就近 Popconfirm；复杂发布 Diff 才用大弹窗。危险确认有明确对象/影响和 danger 按钮，不编造“不可恢复”；具体确认必要性与文案由需求/目标约定决定。
