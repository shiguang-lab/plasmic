# 页面读取与实现依据

## 读取真实模型

通过 Desktop MCP 的实际 `read` schema 读取，不预设参数和返回字段：

| 范围 | 需要取得的信息 |
| --- | --- |
| 页面 | UUID、名称、路由、根布局、引用组件、视口/响应式变体 |
| 节点 | 实际组件身份、Props、Slot 内容及顺序、文本、条件显示、重复表达式 |
| 数据与状态 | 类型、初值、派生值、绑定、状态所属范围、样例数据 |
| 交互 | 事件签名、目标状态/动作、参数、打开/关闭/提交/跳转流程 |
| 视觉与资产 | Token、主题、样式/断点、图标、图片/SVG 来源 |

从页面根递归读取引用的自定义组件与 Slot，包括非活动 Tab、关闭的 Drawer/Modal、隐藏分支和重复模板。对于 opaque 第三方组件，读取其注册信息和实际实现；渲染 DOM 不替代组件的业务语义。

`snapshot_layout` 返回渲染观测，不是模型节点 ID；模型 UUID 来自 `read`/`queryElements`。`get_screenshot` 静态图不执行交互。只读生成不通过改 open/activeKey、初值或保存设计来获取隐藏内容；无法观测的状态明确标注验证限制。

## 根据当前实现决定代码

每个使用到的设计组件都需要确认两端事实：Plasmic 的真实注册 metadata 与 wrapper/源码，以及目标项目可用的组件导出、版本、类型和实现。逐项确认 props、默认值、Slot、事件参数、受控/非受控状态，之后决定目标 JSX 和业务逻辑。注册名不等于 npm 导出名，设计 Slot 名也不保证是同名 React prop。

不使用 Pencil、其他编辑器或旧项目的预设组件转换表。设计端和目标端 API 不同，按实际实现完成必要转换；没有证据时记录缺口，不猜字段或生成看似等价的组件。原型模拟数据不证明后端 API 存在，编辑状态不定义真实权限。

搜索区、表格、行操作优先使用目标已有公共业务组件，但先核对目标 API。Plasmic Overseas wrapper 与目标 `@react/ui` 或本地组件不保证相同；所需能力不存在时使用公开 antd API 实现实际需求。运行 callback、格式化与数据请求依据业务需求编写，截图不能提供这些契约。

使用真实图标组件，避免 Unicode 符号冒充图标。日期等非 JSON 值按目标控件和 API 的真实类型处理；不要把展示字符串直接当保存值。布局、主题、条件与重复按已读取的信息实现，不引入通用模型解释器。

## 运行边界

保留业务语义，去除编辑占位、选择/reveal 状态、registry、模型 UUID 查询与临时 canvas overrides。无需因采用 Plasmic 设计而引入 Loader、SDK 或同步配置。英文 PascalCase 设计节点名可辅助命名，不要求每个节点生成一个组件。

解析图片/SVG 的真实来源、尺寸和使用权，按目标工程资源规则接入。需要认证的 NAS URL 或 data URL 不保证生产可用；不可访问时报告依赖，不替换为无关素材。保留业务语言和要求的响应式行为；未确定业务流程列为契约缺口。
