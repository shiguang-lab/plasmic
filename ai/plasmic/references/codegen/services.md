# Service 与模拟数据

涉及远程数据或业务提交时，在实现前读取本规范。静态内容不强制增加 service。目标是用同一份业务契约完成页面、service 和可验收的模拟流程；真实后端未就绪不等于页面可以没有数据或只有空操作。

## 发现接口资料与确定契约

先检查当前需求及附件、设计说明、关联 Wiki/任务/API 链接、目标仓库文档、接口定义/生成类型、已有 service 与调用方。接口可能散落在 PRD、技术方案、字段表、示例报文或评论中，不以文件名是否含 API 判断。沿当前需求的相关链接读取，不遍历无关知识库；使用可用连接器，记录无法访问的资料，不能将“无权读取”说成“没有文档”。

按实际数据动作建立覆盖：查询/详情、选项、创建/编辑及适用的提交、审核等状态动作。合并各来源中可验证的 method/path、参数位置、DTO/可空性、响应与错误、分页、状态迁移及权限；每项保留来源位置/版本和缺口。页面字段不等于接口字段，样例不证明必填、枚举全集或校验限制；已有调用也不证明覆盖本次新增动作。冲突不静默选一份或拼接成不存在的接口。

| 资料状态 | 执行方式 |
| --- | --- |
| 已有完整契约 | 按契约实现 service 和模拟，不因后端已提供接口文档而省略模拟 |
| 部分缺失、来源冲突或无法读取 | 保留已确认部分，集中询问缺失接口/字段/规则的资料或冲突裁定；仅阻塞依赖该结论的部分 |
| 搜索后没有契约，且用户未说明是否有资料 | 一次性说明已查范围与缺失动作，询问能否提供相关文档/链接，或是否确认没有资料并按需求推导；等待时继续不依赖答案的实现，不把未回复当作确认 |
| 用户已说明没有资料，或已授权按需求推导 | 不重复询问；按下述临时契约生成类型、service、模拟数据与流程 |

局部缺口不使已确认契约失效。仅对缺失项询问；用户确认无资料或已有推导授权后再补齐临时契约。来源冲突须先裁定，不能以推导覆盖。为独立开发准备的演示初值不构成未决业务规则的验收依据。

临时契约优先采用已确认的需求、设计字段/交互和目标工程约定，再推导完成流程所需的最少实体、稳定 ID、查询/详情、保存 payload、响应、状态/动作和错误。合理补齐未定义的字段类型、初值和校验，明确哪些来自资料、哪些是 AI 推导；不擅自改写已明确的业务规则，不额外扩展业务。需要审核等角色分支时建立可切换的模拟权限场景，不把推导的权限点称为后端授权契约。

在现有设计/任务说明中记录临时 endpoint、字段、状态迁移与模拟权限，标明待后端确认；它们可支撑本地验收，不能声称是已存在的后端 API。临时端点只连本地模拟；关闭模拟后不得向真实环境发送推导的请求或自动回退。真实契约取得后在同一 service 边界更新类型/映射及模拟，移除失效定义，不保留两套业务实现。

## 选择项目实际支持的模拟方式

读取目标项目的 mock 文档、依赖、启动脚本、环境配置、注册入口、请求层与相邻模块。核实实际开关名、取值解析、启动方式、拦截位置、URL/baseURL/代理前缀和响应解包；依赖或 mock 目录存在不代表运行时已启用。文档、注释与代码不一致时，定位并修正影响本任务的配置及说明，按实际加载结果验证。不要规定通用环境变量名，也不照抄其他项目的开关。

| 项目能力 | 实现方式 |
| --- | --- |
| 已有网络 mock（开发服务器、请求拦截或等价机制） | 必须沿用并补齐 handlers/数据/场景，让页面 → Hook/service → 原项目请求层 → mock → 原响应处理链路运行；handler 匹配实际 method、路径和参数，返回请求层预期的原始响应 |
| 没有可用的网络 mock 能力 | 提供简单的数据文件及最小有状态的本地模拟实现，沿用已有本地模拟约定；没有约定时，在 service 边界以明确的开发开关选择本地实现。UI 始终调用类型化 service，由其返回与正常调用方契约一致的 Promise 数据/错误；不为此安装完整 mock 平台 |

已有网络 mock 启动失败属于待修复/受阻，不能悄悄降级为本地返回值并报通过。网络 mock 场景禁止 service 导入 fixture 直接返回、在组件中塞假数据或为验收替换 service。没有网络 mock 时允许的本地模拟仍经 service 边界，但不会经过 HTTP/认证/拦截器，必须明确这个验收限制。

模拟状态、数据文件和场景只从开发模拟入口加载，不进入生产行为；沿用现有环境机制，无机制时使用目标构建工具支持的开发条件和单一显式开关。不能因请求失败自动改用假数据，不能默认在生产开启模拟；本地实现不散布到各组件。已有真实契约时，关闭模拟恢复正常 service 请求；尚无真实契约时明确缺口，不把模拟关闭后的失败包装成真实联调成功。

## 生成能够闭环的数据与 service

service 的调用参数、解包和错误语义服从项目请求层；类型化 DTO/Form/payload 的边界按[项目规范](project-code.md#类型与数据模型)，取消和反馈责任按[交互规范](interactions.md#查询与请求)。本地模拟返回 service 调用方的数据形态，网络 mock 返回请求层消费的响应形态，不混淆两种层级。

本地模拟不会触发请求层的统一错误提示，须在现有 Hook/调用方反馈边界补齐一次；service 和数据文件不调用 UI。切回真实请求时不保留重复的本地错误提示，不能因复用 request 的错误类型而假定提示已经执行。

先从需求列出完整业务路径，再实现每个路径所需的数据动作。数据文件是初始数据，不是每次请求返回同一快照：创建产生稳定 ID，保存更新实体，详情/列表/重新进入页面读取同一状态；筛选、分页及 total 按契约变化。提交、审核、驳回等只实现需求中存在的合法迁移，后续可见动作与权限、状态保持一致。读写共享一个模拟数据源，不用无条件成功掩盖未实现的动作。

按当前流程准备可复现的正常、空结果、失败和适用的权限/状态分支。失败在写入前生效，不改变数据，恢复后能继续；有明确部分成功契约时依契约处理。覆盖保存失败、保存成功后刷新失败等不同结果，不能只放“运营”角色而让需求中的审核路径无法进入。使用开发配置、已有工具或测试入口选场景和重置数据，不把模拟开关/验收按钮放进业务界面，不依赖随机失败。

数据文件加内存状态通常足够；记录初始化、重置与持久化范围。路由切换/重新查询不能意外丢失已保存数据；浏览器刷新是否重置按验收要求明确，只有要求跨刷新保留时才用项目已有存储或最小本地持久化。不建通用数据库、模拟权限平台或第二套业务规则引擎。

## 验收与证据

从正式路由、真实宿主/Provider 启动，按需求走完整流程和适用失败分支，观察请求/调用参数、返回结果、列表/详情的读后写一致性、状态/权限变化及提示次数。不能用静态截图、fixture 单测、handler 单测或“点击有提示”代替页面操作。记录可重复的启动方式、实际开关、数据初始化/重置、场景、路由、步骤与观察结果，避免记录凭据。

网络 mock 需用浏览器网络记录、handler 命中记录或项目等价诊断证明目标请求实际经过请求层并命中模拟；还需验证关闭模拟及生产配置不会加载模拟。纯本地模拟需追踪页面 → service → 本地数据的调用与状态结果，并明确 HTTP、认证、响应拦截未覆盖；同样检查开发隔离，不能把本地调用记录当网络证据。

分别报告前端模拟流程（网络 mock / 本地模拟）、真实 API 联调和真实权限验证。注明契约是已确认、部分推导还是全量临时；缺少浏览器、认证或宿主依赖时保留未验证项及阻塞，继续可执行检查，不以 service 测试替代页面验收。完整性、工程检查及视觉证据沿用[代码验收规范](acceptance.md)。
