# Detail-header composition

## Generation rules

Applies to [Ant Design v6](../index.md) Card/Button/Tooltip and [Ant Design Icons](../../antd_icons/index.md). Read [Overseas](../../overseas/index.md) when the page uses its AppShell. Match the actual participants through [library selection](../../index.md).

### Detail page header

Use this recipe only for a current user-requested entity heading area after the Header necessity assessment in [admin content entry](../../../design/layout.md#admin-content-entry). Record that exception's named region and source in the task inventory; otherwise skip this recipe and apply that section's content/action ownership and breadcrumb-first return-navigation decisions. Omitting the Header does not move its return Button into a standalone row or footer.

For an explicitly requested header, use an icon-only return Button immediately before the entity title in the same heading row, with type/status and page actions at the right. Do not allocate a separate return row or repeat the shell breadcrumb. Pattern reference: [Ant Design PageHeader examples](https://4x.ant.design/components/page-header/). This is a composition rule, not a registered PageHeader component: use the actual Button/Tooltip/icon contracts and registered Flex/Space for layout.

Use a 20px/600 title with 28px line height, a 16px ArrowLeftOutlined icon and an 8px icon-button/title gap as the default admin hierarchy. Put the independently registered `@ant-design/icons` instance in the Button icon Slot, with no visible text child; do not substitute Unicode arrows or copied SVG paths. Keep a real button hit area of at least 32×32px, hover/focus feedback and a keyboard-accessible action. Wrap it with a registered Tooltip naming the verified destination in the business page language, such as “返回列表”, and set an accessible name through a supported prop/HTML attribute. Read those live contracts before insertion; do not assume a prop exists. The destination label stays available through Tooltip and assistive technology even though it is not permanently displayed.

Let the title grow and wrap with min-width:0; keep the return icon aligned with the first title line, and prevent type/status from shrinking or overlapping it. Secondary metadata starts below the heading row. Derive its column arrangement and left alignment from the current requirement and user-approved design; keep those task-specific choices in the source inventory. The official PageHeader content starts at the content area's left edge ([official styles](https://github.com/ant-design/ant-design/blob/4.24.16/components/page-header/style/index.less)). When the user chooses title-aligned fields, leave the return control in a separate left gutter, derive the metadata inset from the actual return control width plus the heading gap, and verify the rendered field/title edges. Do not describe this inset as the official default or change the row/column arrangement to resolve an alignment issue. Default metadata uses 14px/22px text, 24px column and 8px row gaps, with 12px separation from the heading. Test representative long names in the complete page. Prefer wrapping; if the approved design truncates the title, expose the complete value through an actual overflow Tooltip.

Bind return to the intended parent/list route using registered Link/Button navigation, not an unconditional browser-history action that can exit the product on direct entry. Preserve the list's applied filters, scope/tab, page/page size and scroll position when returning from a record, where these states exist. Derive the route/state handoff from the actual flow and supported contracts; do not add mock query parameters or a second persisted state schema. Direct entry must still have a working parent destination. Explicit unsaved-change requirements for editable details take precedence over immediate navigation.

### Detail header review

For every generated or changed detail header, read back a single heading-row wrapper containing the return Button and entity title, and confirm the icon is in the Button's real icon Slot with no visible return text. Check both the editor canvas and live preview at the target viewport: short titles stay on the same row as the return icon, type/status remain readable at the right, the first metadata field follows the approved left alignment, and there is no extra return-only row or duplicated breadcrumb. Measure the text edges rather than only the metadata wrapper, whose padding may contain the inset. Inspect long-title wrapping and icon alignment; model validity alone does not pass visual acceptance.

In live preview, hover and keyboard-focus the return Button to verify the destination Tooltip, keyboard activation and accessible name. Confirm that hovering does not navigate. Enter a record from a list with non-default filters/scope/pagination, return and verify the correct route and preserved list state; also test direct entry to the detail page. Do not mark unexecuted navigation/state cases passed. Check the status preset's meaning as well as its layout; initialization must not inherit the success color.

Save/reopen and recheck the heading structure, Tooltip, destination and relevant state handoff. Identify screenshots by breadcrumb/title and the target business node. Record model/layout, screenshot and interaction evidence separately; a matching screenshot width or a successful save does not establish header acceptance.
