# Regeneration and stability

Use this workflow for a fresh generation or when the user asks for stable results. Keep a source-derived plan outside the product UI: current requirement sections, design evidence, scope decisions, target viewport, library contracts/versions, page routes and an acceptance matrix. Each matrix item identifies a source, observable expected result, page/state, and required model/layout/screenshot or real interaction evidence. Resolve outdated design features against the current requirement and user decisions; record the decision once.

For a full regeneration, use a blank project or fresh routed pages, not copies of previously accepted page models. Preserve the previous result as a comparison until the replacement passes. Requirement-specific HTML builders and business demo data belong in the task workspace; do not embed a particular requirement, its UUIDs or expected screenshots into this general skill. Reuse supported component APIs and common design rules.

Before deciding routes, apply [requirement alignment](requirement-alignment.md). Freeze the reviewed page/menu expectation separately from the generator's created-ID plan. Check both clean runs independently against that expectation; compare_models.py only checks equality between runs and cannot establish requirement correctness. Page counts, menu labels, hierarchy and type variants must not be inferred from the generated plan.

## Generation gates

- Assign Card padding from the composition, not one shared preset: when Tabs owns top spacing and the last Table owns pagination bottom spacing, emit body padding `0 20px` and zero vertical padding/offsets in intervening wrappers. Plain information/form/metric cards may use `16px 20px`. Include this choice in intended Card props; verify_slots.py checks literal planned body padding. After save/reopen, separately measure top/bottom ownership including every wrapper and the pagination's own bottom gap; matching props alone do not pass geometry acceptance.
- Create routed Pages before calling setPageViewport; the operation updates existing previews and does not establish a default for future Pages. Confirm both native Page preview frames and overview artboards match the target preset. Discover the installed contracts before insertion. Read normalized routes before binding links; use one complete route tree for the shared shell. Track created IDs from MCP output instead of hardcoding old UUIDs.
- For overview/KPI regions, plan roles, typography, padding ownership, line budget and comparison placement using [overview metrics and information cards](admin-design.md#overview-metrics-and-information-cards). Establish observable geometry expectations independently of generated output. Measure each card's content/edges and inspect longest relevant content and empty/type variants; do not accept a row solely because all cards share a height.
- For detail pages, plan the [detail header composition and checks](admin-design.md#detail-page-header) before insertion: return icon and entity title share one heading row, no permanent return label or return-only row, destination Tooltip/accessibility, long-title layout and parent/list-state handoff. Include these in each clean run's acceptance matrix and save/reopen evidence; do not reuse an older two-row header as generation input.
- Build a page and its actual states/interactions together. Inspect its readback and complete screenshot before continuing. Check render-time expression errors in the actual page. The expression sandbox may omit browser globals such as URLSearchParams; encode query values with supported expressions and use registered href routing. Missing capabilities or dropped props/styles are failures; correct the source or component contract and regenerate the affected page.
- Validate component ownership: one AppShell; real SearchForm Items/controls; registered Cards for planned business surfaces with content inside children; Tables inside their Tab content slots; registered ActionGroup with a consistent limit; independently registered `@ant-design/icons` component instances in Button icon slots; no imported example triggers/descriptions/loading text. Use `python3 scripts/verify_slots.py <intended.html> <mcp-read.json>` to identify missing or wrong named components, Card content outside children and imported children in slots the generation did not supply. The command exits nonzero for these failures. Use --allow-defaults only for inspection before cleanup; it may tolerate sample children, never missing/wrong components or misplaced Card content. Review those candidates, remove unused examples through MCP and rerun without that flag for acceptance. Explicitly set status-only Badge count to `{{ undefined }}`; removing its example child does not clear a default numeric count. A valid model alone does not establish these invariants.
- Treat pagination counts, full-value access, state semantics and navigation handoffs as observable contracts. Draft changes must not apply filters until Search; reset/query/scope changes return to page one. Pending/initialized records must not inherit old members, counts or success feedback. Preserve legitimate zero/false. Test representative role/action combinations and gated SQL validation/preflight/save/launch behavior when those flows are in scope.
- Make `python3 scripts/verify_forms.py <expectations.json> <mcp-read.json> --overview <mcp-overview.json>` a mandatory subprocess in every task's generator, with the script path resolved from `resourceRoot`. Freeze the reviewed field inventory independently of generation output and bind only Page IDs from the created-ID plan. Before insertion, check all intended Page HTML using readback-shaped source fixtures and a complete source Page overview. Check full public MCP Page readbacks plus the whole-project overview after generation and save, and repeat after reload/reopen before delivery. Any nonzero exit stops generation/acceptance; do not catch it to continue, trim the overview to hide Pages, or rebuild the expected field inventory from generated nodes. Scan unlisted Forms/controls and manual field help/error structures as well as expected required rules, plain labels, native tooltip and value ownership. Standalone controls require reviewed per-Page names/reasons; exemptions cannot cover controls inside business Forms. Include the reviewed Modal width, full-row fields and short-field row groups in layout expectations; run the [Modal form layout](admin-design.md#modal-form-layout) structural check and opened-preview acceptance. Preserve gate reports separately from actual invalid-input, tooltip and submission tests in preview. Manual stars, error state and tooltip buttons must not survive a Form migration or remain in its generation source.

## Acceptance and rerun

Live preview defaults to Desktop and fills the available area below the preview toolbar; its viewport follows the App window rather than the page artboard. For a fixed-size visual comparison, select Custom and apply the target width and height. Record the actual iframe viewport and the displayed scale separately: Phone, Tablet and Custom retain their CSS viewport dimensions when their presentation shrinks to fit. A device preview does not authorize adding mobile layouts to a PC-only requirement.

When changing preview viewport behavior, verify Desktop at two App window sizes, Phone/Tablet in both orientations, and Custom through dimension inputs and drag handles. Check drag conversion while the preview is scaled, and confirm mode/dimensions persist through page navigation and refresh. Use layout snapshots for iframe dimensions and screenshots for placement, clipping and control state; identify page layout minimum widths separately from preview sizing failures.

Record separate results for model integrity, actual layout, screenshot review, real preview interactions and persistence. Capture a complete default page and relevant menus/overlays/tabs/long values; each visual review records page identity, viewport, inspected region, observed result and pass/fail. Explicitly identify the screenshot's target business node when multiple frames share dimensions. Do not mark an unexecuted case passed.

Save, restart/reopen the App, read the generated model and rerender the delivered pages. Compare the pre-close and reopened models exactly. Measure widths, bounds and scroll reachability from actual layout snapshots. Include pagination and required footer controls in viewport boundary checks. The editor can expose all SearchForm fields even when runtime collapsed=true, so check both editor and real preview: expanded filters and longer Tables must scroll together in the AppShell content region, without an internal Table body limit. Verify displayed time precision as well as the stored value; a native time control may hide seconds. Preserve sanitized MCP calls, inputs, skill/source versions and evidence in the task's report.

When a generation or acceptance failure reveals a reusable rule, update this skill's relevant reference and any executable check, update the generation source, then rerun generation from clean pages. Do not declare stability from a one-off UI patch. Remove invalidated evidence from the final pass list while retaining failure records in the transcript.

For a focused reusable-rule change, a clean affected-region generation is sufficient when it exercises the relevant component contracts and layout context. Build fresh nodes from source inputs in isolated temporary components/pages, not copies of the accepted model. State the tested scope explicitly: repeated KPI-region generation does not establish full-page or business-flow stability. Keep accepted pages intact and remove temporary components/canvases after capturing evidence. Include the changed rule's relevant state/content cases; do not substitute two identical short mocks for coverage.

When stability is explicitly required, perform another clean generation with the final same inputs and skill. Compare observable requirements, component/slot contracts, state/interaction behavior and measured geometry; generated UUIDs need not match. Run `python3 scripts/compare_models.py <first-mcp-read.json> <second-mcp-read.json> --report <report.json>` for page structure, props, state and interaction equality after normalizing generated element/state/interaction IDs. This compares model contracts only; runtime behavior, geometry and visual review still require independent evidence. Reopen both runs and inspect their screenshots. Keep only the accepted deliverable in its project; remove empty/test canvases and duplicate runs. Report the number of executed runs and any remaining limitations rather than promising universal determinism.

Permission checks must exercise the destination page's own role controls and execution buttons, in addition to list entry visibility. Switching a SQL page to read-only must disable validation, submission, saving and launching and cancel any simulated pending completion. Initialization must show no completed snapshot or historical selection records. In a preflight sample, “all SQL fields” describes the column set; verify sensitive-field masking separately rather than claiming every non-sensitive value is masked.

Do not infer a control prop from another control or from the underlying Ant Design API. Recheck the live registration for every newly introduced prop; for example, the current registered TextArea exposes disabled but not readOnly. Apply the supported contract and verify the resulting read-only UX.

For simulated asynchronous flows, allow enough observable time for the actual App to render and inspect the processing state, without blocking editor operations. Capture processing before completion, then verify terminal state and disabled actions. An already-completed screenshot does not prove the processing state. Keep the duration in the scenario plan, not as a universal component timeout.

Verify completion feedback after an overlay actually closes. The registered Modal invokes onOpenChange(false) before onOk. Use the feedback rules in admin-design.md: ordinary completion uses a short Message/toast rendered outside the closing overlay, without inserting a persistent page-top Alert. Capture the visible message, verify automatic dismissal and unchanged page geometry, and clear the business open state so the operation can be invoked again. Row confirmations must use Popconfirm; exercise cancellation and confirmation from both direct and More actions when present.

For account/role switches, repeat the complete role cycle at least three times in live preview. Check sidebar selection backgrounds and spacing, header controls, row action colors, dropdowns and anchored confirmations after conditional components unmount and remount. Compare screenshots before switching and after returning to the initial role. Also re-enter preview and check again. Missing styles are a runtime failure, not a permission state: shared component libraries must inherit the same theme and use one style cache per preview window. Fix runtime loading before accepting the prototype; do not hide the failure with a reload or component-specific CSS overrides.

Text integrity is an acceptance gate. Reject replacement characters not present in source input, and verify important literal labels against the original generated input. A successful JSON parse does not prove Unicode preservation. If text differs between input, editable readback and rendered screenshot, fix the MCP transport/import root cause and regenerate; do not patch individual damaged labels to claim stability.

For editable mock records, exercise copy → edit → delete and verify the resulting table data and total. Success feedback alone is insufficient. If a route handoff uses a synthetic record ID, distinguish that route record from a locally copied record with the same ID; changes must update the collection actually rendering that row.
