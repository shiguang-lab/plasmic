# Official Plasmic CLI tasks

Read only when the user explicitly requests official code generation/sync/watch or CLI project metadata. Design/template explanation and native React coding use Desktop model reads instead.

`@plasmicapp/cli` provides the `plasmic` command; `@plasmickit/cli` provides `plasmickit` for skill/resources. Check the installed official CLI's help/version and the target repository's existing `plasmic.json`, lockfile, auth host and generated-file ownership. Use [official CLI documentation](https://docs.plasmic.app/learn/cli/) and [codegen overview](https://docs.plasmic.app/learn/codegen-guide/) for its workflow, verifying flags with installed help before invocation.

`info` returns project metadata, not editable node/state/Slot contracts. `sync` and `export` write generated files; use the user's requested project/branch/version and a reviewable destination, then verify imports, assets and the actual target build. Plasmic-managed files can be regenerated by future syncs; custom application logic belongs in developer-owned code following that project's integration contract.

For self-hosted Studio verify the actual supported authentication host and access before requesting data; do not assume public-cloud credentials or endpoints apply. Keep credentials out of transcripts. Generated JSX is supplementary evidence of that export/version, not proof of the current unsaved editor model or complete business APIs. Do not run sync merely to explain a template, or blend official managed output into a native implementation without the requested integration contract.
