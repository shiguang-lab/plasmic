# Desktop Dynamic Island activity

The island starts compact. Existing Desktop tools are intercepted in the dispatcher: every invocation expands the card, including state queries. It stays open while any call is queued or running, then collapses after ten minutes without a new call following the last completion, including failure. Hover also expands and holds the card; pointer exit has a 350 ms grace period and does not renew the MCP lease. Internal state polling and mirroring never renew the lease. Page navigation, loading and reported task status do not control shape. No separate start/end tool is needed. Editing and native in-app Preview show the current canvas; other Studio routes show account identity, current organization/workspace and accessible organization/workspace/project totals, without any canvas placeholder. MCP operation subjects, queue state and errors remain visible alongside those totals. Background account reads never count as MCP calls; authentication changes clear old account data. The compact capsule retains actual operation/task name, status, queue count and activity/error indicators; its tooltip includes resource name, actual stage and error. Success briefly acknowledges completion; failures remain until a meaningful operation replaces them. No operation runs merely because the island is visible.

Use `report_task` to show the actual current task title, execution stage and genuine blockers. Required: stable taskId, current projectId, monotonically increasing sequence, title and status. Start with running; update stage as real work advances; report blocked with the actual error when work cannot continue. End with completed or failed. A new task must start with running. Task reports are ephemeral UI metadata, scoped to the current project/session; keep durable planning in the agent's local working directory.

Only supply stageIndex and stageCount together for an explicit known plan. Never infer stages, percentages or remaining work from tool counts, arbitrary time or an assumption that a failed call succeeded. Do not claim task completion until required verification succeeds. Applied editor changes do not prove persistence: save separately before reporting a saved design.

The readonly mirror follows the current canvas/Preview viewport without changing selection, zoom, pan or business state. Multi-page/freeform canvases frame the union of visible artboards with a 16 CSS-pixel margin, preserving real page backgrounds and relative positions with contain sizing; offscreen pages remain offscreen. Loading clears old pixels and shows a placeholder while preserving the current expansion lease. A failed same-view capture labels its retained image Previous frame; a project/page/session change clears old pixels. Right-click opens Show main window / Check for Updates… / Exit Dynamic Island mode / Quit application. Showing the main window switches to the standard window and hides the island while retaining the remembered closing preference. Startup and update restarts restore the last display mode. Closing the main window follows that preference. Exiting island mode restores a standard window and resets a remembered island closing preference to ask. Quit follows normal app shutdown. There is no floating window/mode icon. Capsule click and Context Menu/Shift+F10 open the same menu; dragging remains available.

Visual feedback follows real calls and rendered targets: reads scan, writes/interactions highlight. Model UUIDs and Preview refs locate visible nodes; view reads scan the current viewport. Missing/offscreen targets, failures and stale views clear highlights. Completion briefly acknowledges the result, then stops. report_task alone never starts visual scanning. The overlay follows image aspect ratio, preserves the design and honors reduced motion.

Idle capsules show the page/canvas name with save state or Preview, or the account name with accessible project count. Loading, signed-out and statistics errors have explicit labels. Card headers consistently identify the project/account and Canvas/Preview/Account mode. During activity, the title names the actual task or current target; only the status row describes the action and its result. Idle cards display the real project name, current canvas/Page name, project Page and editable-component counts, native Studio save state and current zoom/Preview dimensions. Counts exclude code/internal-frame components. Preview uses its runtime Page name rather than the retained editor selection. Loading clears summary values; During MCP activity, the card shows a task/target and one execution-status row; regular counts, save status and configuration metadata yield to that activity. Known stages, compact queue counts and real errors remain visible; error details replace progress bars. Metadata polling never marks a design saved or triggers model reads.

Updates share one download with the standard window. A ring/ready icon appears on the capsule or card header; clicking it or Check for Updates… opens a fixed-size confirmation pane inside the island. Background update activity never changes shape or reveals the main window. Later preserves the ready download. Install waits for outstanding MCP calls, temporarily rejects new calls, closes Preview and saves before restarting.

Account identity uses a localized signed-in status dot beside the account name; the footer contains the email rather than a repeated sign-in label. Idle account cards also show the currently resolved theme and UI language as read-only metadata; these follow the shared appearance/localization snapshots and yield to account loading and MCP tasks/errors. Account loading uses two aligned rectangular content placeholders with a continuous shimmer, plus a short identity placeholder when needed. Loading is announced accessibly; reduced-motion preferences disable the shimmer. MCP activity retains its task and error display while statistics load.

Idle signed-out account cards offer a localized Sign in button. The trusted island IPC reveals the main window and opens the existing unified-login page, hiding the island while retaining its closing preference. Account loading, authenticated data and MCP activity replace the idle sign-in action.
