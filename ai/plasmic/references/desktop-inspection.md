# Rendered design inspection

Read when observing geometry, screenshots or real Preview behavior. Use live tool schemas; view changes must not become saved business state.

## Geometry and static screenshots

For content completeness, request `get_screenshot` with `fullContent:true` in artboard mode. This expands nested horizontal/vertical scroll regions and clipping ancestors in an isolated static copy, leaving the live canvas and saved design unchanged. It defaults to original-size lossless pixels; `fullResolution:false` requests a compressed preview. `elementUuid` crops an expanded node. Read the returned `fullContent` region inventory, dimensions, `coverage:"rendered-dom"` and limitations: unmounted virtualized items and unloaded content are not covered. Use actual Preview scrolling to inspect those. Captures over 16383 pixels per side or 20 megapixels fail; select a smaller element. Keep a normal viewport capture for layout acceptance, since the full-content image shows an expanded layout. Workspace mode does not support fullContent.

`snapshot_layout` provides rendered geometry and image sources, not editable model IDs. Default output is a summary with paginated problems; use `view:"elements"`/`"images"` for detail. It checks horizontal overflow, image loading and controls escaping sticky Table-cell content bounds. `cellContent` records actual cell padding, control bounds and required width; an operation group can overflow its cell while remaining inside the viewport. For acceptance request `view:"full"` with each Page's `componentUuid`: it pins a background canvas without changing the active arena/selection, so preceding it with `navigate` is unnecessary. Rendering acceptance requires a fresh capture declaring `table-cell-control-overflow` in `checked`; old captures cannot establish this check. Obtain node UUIDs separately through `read`. A metadata timeout alone does not establish that page unloading caused a renderer hang; retain Desktop version, operation/stage timing and project identity before diagnosing or retrying.

`get_screenshot` returns a compressed WebP preview without editor chrome/placeholders; use `fullResolution:true` for original-size lossless pixels. Prefer `componentUuid` for a Page. When a particular artboard matters, take its exact `frameUuid` from the model: a Page's pageFrames entry and its shared-overview canvases.frames entry have different identities. Both componentUuid and frameUuid pin a background rendering without navigation, including offscreen artboards; supplying both requires the frame to belong to that component. An unqualified capture uses the currently rendered/focused artboard. Width/height set the temporary static rendering viewport; they are separate from output compression and do not resize the live Preview. Record source-frame dimensions, capture dimensions and any resizing. Workspace mode captures the visible editor, accepts no componentUuid/frameUuid and may support a crop rect. Identify the page using its title/breadcrumb and a unique business-body element from the readback, not width alone. Static screenshots do not execute interactions. Background geometry/screenshot reads show an inspection activity status in the App; it identifies acquisition, not acceptance. Open each returned image and reject visible omissions before generating the next Page. Record the required visible content and the actual observation, including failures.

## Native Preview

Before preview.open for prototype generation/edits, complete [saved-output acceptance in the execution plan](workflows/prototype.md#execution-plan-and-completion-evidence) using the current [verification report](verification.md#collect-and-verify). Follow the [review rounds](workflows/prototype.md#final-preview-review): collect the whole planned round, then close before batch repairs, at most 10 rounds. Crash/unavailable runtime may end a round early; ordinary failed cases do not. Read-only inspection may examine existing Preview without generation or saving.

Use top-level `preview` for runtime acceptance: `{action:"open",componentUuid:"PAGE_UUID",width:1440,height:1024}`. It uses authenticated in-app Preview without saving or adding a device column. Width/height select a temporary Custom **runtime test viewport**; design columns retain Desktop. `state` reports actual committed iframe readiness, Page identity and `canGoBack`/`canGoForward`. Query these flags before `back`/`forward`; both actions traverse only the current Preview session’s business page history and are no-ops at its boundaries. `refresh` remounts only the runtime iframe, preserving the current route, viewport and navigation history. Device/variant changes do not add page history. Navigation actions return the updated flags. Closing clears the session history. Runtime operations use this entry point so actions/evidence are collected; execute/batch cannot route Preview. An external Preview popup must be closed first.

`preview {action:"snapshot"}` returns bounded, paginated DOM roles/names/values and text. When either collection has more output, `continuation` supplies the next `preview` call with both offsets and the same limits; follow it while locating the target before claiming it is absent. The individual `nextOffset` and `text.nextOffset` identify which collection remains. Pagination follows the current DOM, not a frozen snapshot: after an interaction/navigation restart at offset 0. These refs identify runtime DOM, never editable model UUIDs. They expire after navigation or replacement. Use click/fill/press/scroll with current refs. Native select uses select; an Antd selector uses click → snapshot → click option. Interactions trigger actual DOM/input events and never change saved props to imitate a result. Use source-derived actions and assertions from the local plan; assert evaluates the supplied text/count/value/visibility checks (default wait 2 seconds, maximum timeoutMs 10000). Failed assertions remain failures, not completed cases.

`preview {action:"screenshot"}` captures the visible runtime iframe, returns compressed WebP, and records CSS viewport separately from presentation pixel size. It rejects clipped viewports; reveal the full Preview in the App. Use it for required overlay/processing states before terminal results. `get_screenshot` with componentUuid is the static canvas image, not a replacement for runtime behavior. Close through `preview {action:"close"}` before edits. Hidden Tabs/overlays require actual observations; do not persist open/active-key overrides to inspect them.

`preview.open` retains the original editing canvas/artboard, zoom and pan before the mode transition. `preview.close` exits native Preview or interactive canvas mode, restores that retained view and waits for the editor canvas; it does not require a functioning Preview iframe. It returns `view` plus actual project/session/Page/frame/mode in `context`, without saving or changing business state. Repeated close is safe. `navigate` locates an editor arena; it is not an exit-Preview command. Retain unfinished runtime cases in the local plan and rerun them after recovery.

`preview.state` returns `ready:false` when outside native Preview. Model readiness and the retained editor selection do not prove runtime readiness. For context errors follow the [execution-context recovery contract](desktop-context.md); do not silently switch modes through a model read/write or use save/reopen as a routine mode-recovery shortcut.

Runtime frame discovery, DOM evaluation, input dispatch and capture share a 30-second deadline per action, enforced outside the iframe. A timeout fails that action and releases the serialized queue; it does not certify whether an already-dispatched input took effect. Retain the error and collected cases, close Preview, and inspect current context before repairs. Do not keep issuing screenshots/state retries into a broken runtime.

Preview tool failures return `{msg, detail}`. Diagnostic fields in this paragraph belong to `detail`. Preview errors retain the original exception in `cause` (message/name/stack when supplied). `preview` diagnostics identify action/ref, phase/source, editor context, runtime frame, target/hit-test geometry and attempted/acknowledged native inputs. `operationExecuted:false` means requested input was not dispatched; `true` means its sequence completed, not that business processing succeeded; `null` means input may have run or only part completed. Inspect the outcome before replaying a possibly executed mutation. Target preparation can scroll/focus before input dispatch.

`PREVIEW_TARGET_STALE`, `PREVIEW_TARGET_HIDDEN`, `PREVIEW_TARGET_DISABLED`, `PREVIEW_TARGET_BLOCKED` and `PREVIEW_ACTION_NOT_APPLICABLE` report `runtimeAvailable:true`, `canContinueRound:true` and snapshot recovery. Record the failed case, refresh refs/inspect the target and continue other cases in the same usable round. A target error alone does not justify closing Preview. Unknown failures report null availability and state recovery; inspect actual readiness before deciding. `PREVIEW_UNAVAILABLE`/`PREVIEW_TIMEOUT` report unavailable runtime and close recovery; retain findings/pending cases and end the round. Context mismatches retain their explicit recovery. `canContinueRound` never changes a failed case into a pass.

## Pen and external references

For Pen references, ordinary `design_reference.screenshot` uses public `TakeScreenshot`; inspect `sourceFrameSize` and pixel `scale`, since Pen may return a thumbnail. `fullResolution:true` uses public `Export` at scale 1 into a temporary directory, reads the source pixels and removes the exported file. It never modifies the Pen design or enlarges a thumbnail. The result records its capture method, actual image dimensions and scale; insufficient export resolution fails explicitly. Use full resolution when judging text, spacing and fine layout.

External reference tools require a ready, editable Studio project open in edit mode. Start `reference_browser` with `{action:"load_page",url:"https://external-reference.example/page"}`; it validates the source and editor context before showing the panel. `capture_browser` captures an external source, and `import_reference` explicitly imports a loaded external reference into a separate artboard. These tools isolate Studio authentication. `close` always hides the reference panel. Runtime acceptance belongs to `preview`: if it fails, keep the current Page incomplete and report the exact error. Reference tools and model-state changes cannot replace the missing runtime check.

## Other inspection entry points

Desktop's **Open preview in browser** saves the design before opening the external preview. Read-only tasks use the in-app Preview or an already open authorized preview; do not trigger that browser action to inspect unsaved work. If only the saving entry point is available, retain model/static evidence and report the missing runtime check. Prototype tasks may use it after the authorized save.

For offscreen rendered content use `execute` → `scrollElementIntoView` with component/element UUIDs from `read`; frame and repeated instance targeting follow the live schema. Navigate first and wait for rendering. Inspect returned visible/bounds plus a workspace screenshot; static snapshot rendering is separate. Hidden/unrendered targets fail; ancestor clipping can still make visible=false. Restore temporary editor mode/view changes after inspection.

## Evidence interpretation

Visual evidence records page identity, viewport, inspected region, concrete observations and pass/fail. Keep model, geometry, pixels, exercised behavior and persistence as separate results. A successful save or screenshot capture does not pass the other checks.

Static captures default to the selected source frame dimensions. Below-fold reachability and responsive interactions require actual Preview tests, independently of static capture sizing.
