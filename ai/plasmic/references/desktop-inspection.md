# Rendered design inspection

Read when observing geometry, screenshots or real Preview behavior. Use live tool schemas; view changes must not become saved business state.

`snapshot_layout` provides rendered geometry and image sources, not editable model IDs. Default output is a summary with paginated problems; use `view:"elements"`/`"images"` for detail. It checks horizontal overflow and image loading. For acceptance request `view:"full"` with each Page's `componentUuid`: it pins a background canvas without changing the active arena/selection, so preceding it with `navigate` is unnecessary. Obtain node UUIDs separately through `read`. A metadata timeout alone does not establish that page unloading caused a renderer hang; retain Desktop version, operation/stage timing and project identity before diagnosing or retrying.

`get_screenshot` returns a compressed WebP preview without editor chrome/placeholders; use `fullResolution:true` for original-size lossless pixels. Prefer an explicit `frameUuid` for ambiguous canvases. Width resizes the selected static snapshot, not a live responsive viewport; record source viewport and resizing. Workspace mode captures the visible editor and may support a crop rect; discover permitted target combinations. Identify the page using its title/breadcrumb and a unique business-body element from the readback, not width alone. Static screenshots do not execute interactions. Background geometry/screenshot reads show an inspection activity status in the App; it identifies acquisition, not acceptance. Open each returned image and reject visible omissions before generating the next Page. Record the required visible content and the actual observation, including failures.

Use the top-level `preview` tool for runtime acceptance: `{action:"open",componentUuid:"PAGE_UUID",width:1440,height:1024}`. It uses the authenticated in-app Preview without saving or adding a device column. Width/height together select a temporary Custom **runtime test viewport**; Page design columns retain native Desktop. `state` reports actual iframe readiness and runtime context separately from retained editing selection. The internal execute preview operation only controls native routing; runtime tests use the top-level tool so actions/evidence are collected. An external Preview popup must be closed first.

`preview {action:"snapshot"}` returns bounded, paginated DOM roles/names/values and text; follow nextOffset and text.nextOffset as needed. These refs identify runtime DOM, never editable model UUIDs. They expire after navigation or replacement. Use click/fill/press/scroll with current refs. Native select uses select; an Antd selector uses click → snapshot → click option. Interactions trigger actual DOM/input events and never change saved props to imitate a result. In a controlled task, begin_case enforces its pinned action values/order/target role or name; assert evaluates the exact planned text/count/value/visibility checks (default wait 2 seconds, maximum timeoutMs 10000). Failed assertions remain failures, not completed cases.

`preview {action:"screenshot"}` captures the visible runtime iframe, returns compressed WebP, and records CSS viewport separately from presentation pixel size. It rejects clipped viewports; reveal the full Preview in the App. Use it for required overlay/processing states before terminal results. `get_screenshot` with componentUuid is the static canvas image, not a replacement for runtime behavior. Close through `preview {action:"close"}` before edits. Hidden Tabs/overlays require actual observations; do not persist open/active-key overrides to inspect them.

The `reference_browser` and `capture_browser` tools isolate Studio authentication and reject Studio Preview URLs. `import_reference` is an explicit external-reference import into a separate artboard and has no runtime acceptance role. A reference browser loading error/403 does not establish native Preview availability. Missing runtime capabilities block the affected acceptance; do not guess alternate URLs or substitute import/capture for exercised behavior.

Desktop's **Open preview in browser** saves the design before opening the external preview. Read-only tasks use the in-app Preview or an already open authorized preview; do not trigger that browser action to inspect unsaved work. If only the saving entry point is available, retain model/static evidence and report the missing runtime check. Prototype tasks may use it after the authorized save.

For offscreen rendered content use `execute` → `scrollElementIntoView` with component/element UUIDs from `read`; frame and repeated instance targeting follow the live schema. Navigate first and wait for rendering. Inspect returned visible/bounds plus a workspace screenshot; static snapshot rendering is separate. Hidden/unrendered targets fail; ancestor clipping can still make visible=false. Restore temporary editor mode/view changes after inspection.

Visual evidence records page identity, viewport, inspected region, concrete observations and pass/fail. Keep model, geometry, pixels, exercised behavior and persistence as separate results. A successful save or screenshot capture does not pass the other checks.

Background screenshots default to the selected source frame width and height, preserving viewport CSS. An explicit width/height changes the layout viewport; output compression and element cropping are separate. A screenshot captures the selected viewport, not proof of reachable below-fold content. Test actual scrolling in Preview.
