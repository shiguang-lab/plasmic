# Plasmic 页面到项目代码

按目标工程规范将可编辑 Plasmic 页面生成 React/TypeScript。`plasmickit` 更新规范，Agent 读取、实现并验证；不调用 `export_code`，不引入官方 CLI、同步配置或托管渲染。

## 必读规范

`context resolve --mode codegen` 返回以下必读规范。按需读取数据/交互规则。

- [页面读取与实现依据](../model-reading.md)：读取真实模型与当前实现，确认目标 API。
- [项目代码规范](../codegen/project-code.md)：目录职责、组件拆分、类型、样式、宿主集成。
- 涉及查询、请求、表单、弹层、提交或权限时，读取[数据与交互规范](../codegen/interactions.md)。静态布局不需要加载这些规则或添加对应能力。
- [代码验收规范](../codegen/acceptance.md)：行为、视觉、构建与交付证据。

## 1. 确认页面和目标项目

读取需求、仓库规则、依赖与锁文件、入口、路由、Provider、公共组件、请求和权限封装。区分现有应用与独立项目的菜单/登录/顶栏责任；沿用实际依赖和命令，不机械复制原型外壳。

若用户明确要求新建独立项目且未指定技术栈，默认 React + TypeScript + Ant Design 6 + Vite，使用当前可安装且互相兼容的稳定版本并提交锁文件。普通页面生成不升级现有工程的组件库。不预建微前端、权限平台、请求框架或通用页面引擎。

## 2. 读取真实设计

通过 Desktop MCP 选择用户指定项目，读取 `get_app_state` 和实际操作 schema，执行 `identify`、`read`。按照[页面读取规范](../model-reading.md)读取目标 Page、依赖组件、Props/Slots、数据、状态、事件、条件与重复、主题和资产。记录实际项目/页面 UUID、路由、可用 revision 与资源 releaseId；接口不提供 revision 时明确标记。

截图和布局核对视觉，模型与组件实现定义结构和行为。读取非活动 Tab、关闭弹层及隐藏分支；只读生成不改初值或自动保存。涉及原型修改时，先按 prototype 工作流完成、保存并验证，再读最终设计。

## 3. 建立实现契约

在工作区记录实现与验收契约：组件/文件、字段类型与 API 参数、动作状态与成功/失败行为、主题/资产接入、样例/真实接口/fixture 边界。简单页面合并说明，不建空目录。

先按[组件库索引](../libraries/index.md)确认设计端与目标端各自的库/API 版本，再从目标已安装类型和源码核对 props、Slots 和事件。设计注册名不等于 npm 导出名。缺失组件或不明业务契约应明确；继续实现不依赖它们的部分，不能用虚构接口或看似相同的组件掩盖问题。模拟列表不证明存在对应后端服务，原型状态也不定义真实权限。

## 已有代码的局部更新

局部更新只读取受影响页面/子树、状态、查询及组件依赖，核对实现与需求差异。只改职责所属文件，保留无关逻辑和接入方式，不重生成整页或按设计节点重组工程。源设计变化后重读受影响输入；验收覆盖改动及共享消费者，无需重跑无关页面。

## 4. 生成并接入真实项目

按规范实现类型、必要 service、页面/私有组件、样式与词条，并接入真实路由。将原型声明式状态和交互翻译成类型化 React 状态、Form 与事件处理函数；写 JSX 和实际业务逻辑，不把 Studio 模型 JSON、表达式解释器或注册元数据作为产品运行依赖。

保留信息层级、布局、文案、数据、动作与可见状态；复用公共组件和公开 API，按契约处理 wrapper 差异。未定字段/API/权限须记录，不声称完成联调。fixture 按项目 Mock 机制隔离；静态演示可用本地类型化数据并说明性质。

## 5. 验证并交付

运行项目类型检查、测试和构建；在真实入口核对页面、交互及[视觉验收](../codegen/acceptance.md)。修复 API 和状态流程，不删校验、弱化类型或复制截图。

交付说明源页面/资源版本、文件、路由、依赖、模拟数据边界、检查及未验证项。生成不自动发布或部署。
