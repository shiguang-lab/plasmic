# Plasmic 页面到项目代码

目标是从可编辑的 Plasmic 页面读取结构与行为，按目标项目的工程规范生成可维护的 React/TypeScript 代码。`plasmickit` 负责更新和提供规范，Agent 负责读取、分析、实现与验证。此流程不调用 `export_code`，不引入官方 Plasmic CLI、代码同步配置或托管渲染模块。

## 必读规范

`context resolve --mode codegen` 返回以下四份规范与本工作流；全部读取后开始实现。

- [页面读取与实现依据](../codegen/page-reading.md)：读取真实模型与当前实现，确认目标 API。
- [项目代码规范](../codegen/project-code.md)：目录职责、组件拆分、类型、样式、宿主集成。
- [数据与交互规范](../codegen/interactions.md)：查询、请求、表单、弹层、提交与权限。
- [代码验收规范](../codegen/acceptance.md)：行为、视觉、构建与交付证据。

## 1. 确认页面和目标项目

读取需求、目标仓库规则、`package.json`、锁文件、真实入口、路由、Provider、公共组件、请求和权限封装。确认是在现有应用新增业务页面，还是新建独立项目；宿主子应用的菜单/登录/顶栏责任与独立应用不同。沿用目标实际依赖和命令，不机械复制原型画布的应用外壳。

若用户明确要求新建独立项目且未指定技术栈，默认 React + TypeScript + Ant Design 6 + Vite，使用当前可安装且互相兼容的稳定版本并提交锁文件。普通页面生成不升级现有工程的组件库。不预建微前端、权限平台、请求框架或通用页面引擎。

## 2. 读取真实设计

通过 Desktop MCP 选择用户指定项目，读取 `get_app_state` 和实际操作 schema，执行 `identify`、`read`。按照[页面读取规范](../codegen/page-reading.md)读取目标 Page、依赖组件、Props/Slots、数据、状态、事件、条件与重复、主题和资产。记录实际项目/页面 UUID、路由、可用 revision 与资源 releaseId；接口不提供 revision 时明确标记。

截图和布局用于核对视觉，结构与行为以模型和组件实现为依据。非活动 Tab、关闭的弹层及隐藏条件分支也需要读取；只读生成不修改设计初始状态或自动保存。需求同时包含原型修改时，先按 prototype 工作流完成、保存并验证，再读取最终设计。

## 3. 建立实现契约

在任务工作区留下简明实现与验收说明：各页面区域的实际组件/文件、字段值类型与 API 参数、动作的状态变化及成功/失败行为、主题与资产的接入方式、样例数据与真实接口或开发 fixture 的边界。简单页面可合并在一份说明中，不创建空规格目录。

从目标已安装类型和组件源码核对关键 props、slots 和事件签名。设计注册名不等于 npm 导出名。缺失组件或不明业务契约应明确；继续实现不依赖它们的部分，不能用虚构接口或看似相同的组件掩盖问题。模拟列表不证明存在对应后端服务，原型状态也不定义真实权限。

## 4. 生成并接入真实项目

按规范实现类型、必要 service、页面/私有组件、样式与词条，并接入真实路由。将原型声明式状态和交互翻译成类型化 React 状态、Form 与事件处理函数；写 JSX 和实际业务逻辑，不把 Studio 模型 JSON、表达式解释器或注册元数据作为产品运行依赖。

逐区块保留信息层级、布局、文案、数据表达、动作及可见状态。复用目标公共组件和公开库 API，按真实契约处理包装组件的差异。字段/API/权限未确定时显式记录边界，不声称已完成真实联调。开发 fixture 依照目标项目的 Mock 机制隔离；目标为静态演示时可使用明确的本地类型化数据，交付说明其性质。

## 5. 验证并交付

运行目标项目现有的相关类型检查、测试和构建，在真实入口核对页面与涉及的交互状态，再按[验收规范](../codegen/acceptance.md)比较视觉。修复实际组件 API 和状态流程中的错误，不通过删校验、弱化类型或复制截图修饰问题。

交付说明源页面/资源版本、生成文件和路由、依赖、真实与模拟数据边界、实际执行的检查、未验证项。代码生成不自动发布设计或部署应用。
