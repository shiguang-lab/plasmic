# Plasmic 页面到项目代码

用于 Plasmic 设计对应应用代码的生成、修改、修复及一致性验收；只读审查执行相关读取和验证，不修改产物。遵循目标工程规范，不调用 `export_code` 或引入同步配置、托管渲染。

## 必读规范

`context resolve --mode codegen` 返回必读规范；数据/交互规则按需读取。

- [页面读取与实现依据](../model-reading.md)：读取真实模型与当前实现，确认目标 API。
- [项目代码规范](../codegen/project-code.md)：组件契约与复用、目录职责、类型、样式、宿主集成。
- 涉及数据或提交时，先读[Service 与模拟数据](../codegen/services.md)；查询、表单、弹层或权限另读[交互规范](../codegen/interactions.md)。静态布局不添加这些能力。
- [代码验收规范](../codegen/acceptance.md)：设计到代码的一致性、行为、视觉、构建与交付证据。

## 1. 确认页面和目标项目

读取需求、仓库规则、依赖与锁文件、入口、路由、Provider、公共组件、请求和权限封装。区分现有应用与独立项目的菜单/登录/顶栏责任；沿用实际依赖和命令，不机械复制原型外壳。

若用户明确要求新建独立项目且未指定技术栈，默认 React + TypeScript + Ant Design 6 + Vite，使用当前可安装且互相兼容的稳定版本并提交锁文件。普通页面生成不升级现有工程的组件库。不预建微前端、权限平台、请求框架或通用页面引擎。

## 2. 读取真实设计

通过 Desktop MCP 定位指定项目，读取 `get_app_state` 和操作 schema，执行 `identify`、`read`。按[页面读取规范](../model-reading.md)取得完整模型与依赖契约。记录项目/页面 UUID、路由、可用 revision 和资源 releaseId；缺 revision 明确标记。

模型与组件契约定义结构/行为，截图和布局核对视觉。覆盖非活动及隐藏分支；只读不改初值或自动保存。涉及原型修改，先按 prototype 工作流完成、保存并验证，再读最终设计。

## 3. 建立实现契约

在任务说明中确定需求与设计版本、实现及验收范围。来源冲突说明采用依据；影响业务语义且无法裁定时澄清，继续独立工作。记录组件/文件、API、行为、反馈责任与模拟边界。

按[组件库索引](../libraries/index.md)及[组件契约与复用](../codegen/project-code.md#组件契约与复用)核对两端真实 API。业务接口先发现资料，再依 Service 规范确认缺口或推导临时契约；未知组件 API 不自行推导。

从源模型确定应保留的语义；仅对非直接转换记录源区域、目标落点、契约依据、理由和未解决差异，无需逐节点填表。

## 已有代码的局部更新

局部更新只读取受影响页面/子树、状态、查询及组件依赖，核对实现与需求差异。只改职责所属文件，保留无关逻辑和接入方式，不重生成整页或按设计节点重组工程。源设计变化后重读受影响输入；验收覆盖改动及共享消费者，无需重跑无关页面。

## 4. 生成并接入真实项目

按规范实现类型、必要 service、页面/私有组件、样式与词条，并接入真实路由。将原型声明式状态和交互翻译成类型化 React 状态、Form 与事件处理函数；写 JSX 和实际业务逻辑，不把 Studio 模型 JSON、表达式解释器或注册元数据作为产品运行依赖。

每完成一个业务区域，按[一致性核对](../codegen/acceptance.md#设计到代码的一致性)检查语义落点及可运行的行为、视觉。数据流程同时实现 service 和模拟，沿用已有网络 mock，否则提供本地模拟；按 Service 规范验证闭环并区分真实联调。

## 5. 执行验证

按[代码验收规范](../codegen/acceptance.md)完成工程检查、真实入口行为与视觉验收，记录证据及限制。

## 6. 实现后审查与交付

按[实现后审查](../codegen/review.md)为适用方向分别委派独立 subagent；不可委派时当前会话逐方向审查。主 Agent 汇总核实并修复，交回受影响方向复核；按验收规范报告各方向、证据与未解决项。生成不自动发布或部署。
