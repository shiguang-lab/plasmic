# Product prototype workflow

Studio: https://studio.plasmic.shiguanglab.com. Use the logged-in desktop MCP and the user's project. Read `get_app_state`, then `execute` → `identify`; require `canEdit`. Do not use private Studio globals, database bundles, browser evaluation, or raw REST to generate/update a design. If MCP lacks a required capability, implement and test it before continuing through MCP.

Read [../admin-design.md](../admin-design.md) for admin prototypes. Derive business behavior from the original requirement and product design; previous generated prototypes are reference evidence, not authoritative requirements. Access `.pen` through its MCP. Record scope, conflicts, mock data, and source paths in a sidecar plan outside the UI. Respect explicitly requested viewport and platforms.

For ActionGroup navigation, use item `href` so the registered Plasmic Link performs routing. Reserve `onAction` for local actions; do not replace page navigation with `window.location`.

When routing depends on successful form validation, use the native `navigation` interaction on Form `onFinish` and derive its destination from the validated `values`. The submit button calls Form `submit()`; it must not also have an unconditional `href`. Discover the current interaction schema before creating the action, and upgrade the editor if the native action is unavailable.

Install **Ant Design Icons** through **Component Store → Icons** before inserting library icons. Confirm the imported library in `read`, then inspect the specific icon contracts. The top-level Icons entry is for project SVG assets and must keep its upstream behavior. Do not inject the icon library into every host/project. Button icons must be independently registered `@ant-design/icons` components (such as `plasmic-antd-icon-PlusOutlined` and `plasmic-antd-icon-DownOutlined`), using the Button icon Slot and iconPlacement for a leading/trailing icon. Read the specific icon component contract; use its own component identity and official import, without a generic Icon/name wrapper. Do not create project SVG assets or copy SVG paths for icons; inherit color through currentColor. For triggers with two icons, put the leading action icon in icon and a separate dropdown indicator beside the text. Never put Unicode icon substitutes such as ＋, ⌄, ‹ or › in button labels. Verify actual delivered nodes and dropdown behavior.

## Align with the requirement before building

For requirement-driven generation or a page/navigation audit, read [requirement alignment](../requirement-alignment.md). Establish the current scope, source-derived page inventory, exact menu hierarchy and behavior acceptance matrix before creating routes. Distinguish independent pages from type/role/state variants, Tabs, overlays and overview frames. A shared page in the requirement remains one routed Page unless an explicit user decision authorizes a split. Keep requirement-specific decisions in the task workspace, not this general skill.

Acceptance expectations must come from that reviewed source inventory, not the generator's routes or output. Run the linked structural check against public MCP overview and full page readbacks before visual/interaction acceptance and again after reopen. A mismatch blocks acceptance; do not rewrite the expected inventory to match generated output. Matching two generated runs proves repeatability only after both independently pass requirement acceptance.

## Build through MCP

- Name editable nodes in English PascalCase. Prefer the actual registered component display name for unique page-level structural components (especially `AppShell`); use meaningful business names/scopes for controls and repeated components. Follow [editor node naming](../admin-design.md#editor-node-naming) for names, component identity, copies and readback checks. Set names during generation rather than accepting arbitrary identifiers or fixing only the selected node afterward.
- `get_app_state` supplies exact editor operation schemas. `execute` calls validated operations; `execute_batch` is atomic but does not resolve IDs created by earlier steps. Discover IDs with `read`; inspect exact props, choices, slots, and imported project IDs before using a component. Never copy Antd5 props or Pen library IDs.
- For list search/filter regions, use Overseas `plasmic-overseas-search-form` with editable `plasmic-overseas-search-form-item` nodes in its children Slot. Read/install/upgrade the published Overseas library before insertion. Set colSpan=6 for four-column admin layouts; put exactly one real Antd6 control in each Item's children Slot. Configure name/label/span/initialValue/clearValue/validation on Item and options/placeholder/date mode on the control. Extra actions use extraActions, custom labels/help use labelContent/help. Query/reset events receive values and must update applied filters and reset pagination; values tracks drafts. Insert, move, delete and modify these nodes through MCP. Never construct another native query grid or opaque fields/element JSON. See ../admin-design.md.
- For standalone admin pages, first `read` the installed Overseas library and confirm `plasmic-overseas-app-shell` exists. Install Overseas with `installLibrary` using its published project ID when it is missing. If a newer library has been published, use `upgradeLibrary` with its imported project ID, then `read` the updated contracts and `save`. Insert one AppShell instance per page with product/user/language/App Source/menu props and the complete menu/route tree (including hidden detail routes) and put business content in its `children` (Page body) slot. Never rebuild the shell as native layout per page. Preserve business element UUIDs and interactions when migrating existing pages via `moveElement`; remove obsolete shell markup after moving content and overlays.
- Use `createComponent`, `insertHtml`, `changeElement` and component copies for editable structure. Use Antd6 registrations for controls, cards, tables, tabs, feedback and forms; native HTML for semantic layout/text. Business surfaces such as a list with toolbar/Tabs/Table, grouped form information, detail panels and metric cards use `plasmic-antd6-card` with editable content in its children Slot. Do not imitate Card with a styled native section/div. Read the Card contract and follow [card ownership](../admin-design.md#card-ownership), including edge-specific spacing: Tabs-first / Table-last list Cards use body padding `0 20px` when those components already own top/bottom spacing, not the plain information Card's `16px 20px`. Ordinary layout wrappers remain native. Build reusable shared structure when pages actually repeat it. Use flex/grid and natural flow, not a screenshot or absolutely positioned imitation.
- For all generated headings, follow [heading typography](../admin-design.md#heading-typography): use the owning component’s real title Slot where available, preserve its theme, and check inherited typography on custom semantic headings. Inspect actual glyph spacing and title-to-content separation across the pages; do not infer visual acceptance from font-size props alone.
- For editable forms and form Modals, follow [forms and state](../admin-design.md#forms-and-state): use real Form/Item validation, required indicators and label tooltip; keep the default Modal footer/text for a confirm/cancel pair. Inventory all project Pages and fields, including Pages without business Forms and reviewed standalone controls. Wire `verify_forms.py` with a complete overview into the task's generation/acceptance entry point, before insertion, after generation/save and after reopen; a failed gate stops the task. Follow [Modal form layout](../admin-design.md#modal-form-layout) for width, short-field pairs and full-row long fields; include row grouping/spans in the inventory and check opened-Modal geometry in real preview. Inspect native field errors, label help and processing behavior, not only the success path.
- For overview/KPI regions, follow [overview metrics and information cards](../admin-design.md#overview-metrics-and-information-cards): separate secondary metric labels from section headings, preserve requirement-derived data context, and avoid stretching sparse summaries to unrelated card stacks. Plan field roles and typography before insertion; use the compact composition defaults when appropriate. Pass the per-card density/edge measurements and relevant long/empty/type-state checks in real preview after reopen; equal heights alone do not pass.
- For admin detail pages, follow [detail page header](../admin-design.md#detail-page-header): generate an icon-only return Button and entity title in one heading row, destination Tooltip/accessibility, metadata below, and the real parent/list navigation handoff. Apply this during generation, then run the linked detail-header acceptance checks.
- `data-props` is JSON, not JSX. Direct children of `plasmic-component` can be `<slot name="...">`. Styles on code components control layout; use supported props for appearance. Dynamic values use `{{ expression }}` through `changeElement`. Read render-prop parameter names before binding table cells.
- Choice props with dynamic options may be exported as “Dynamic options”; use an expression for the initial choice, and derive supported values from the live registry/source. Query-data props require an expression object. Read the normalized page path after creation before linking pages. Dropdown JSON uses `key` for action routing.
- Inspect default slot content before acceptance. Remove unused Modal triggers, Alert descriptions, Spin loading content, and Badge example children through MCP. Status-only Badge requires an undefined count; zero is still an explicit count. Editor empty-slot placeholders can switch Badge into notification layout even when the runtime status is correct. Compare the live preview; capture it through MCP for final status/overlay evidence. Never leave component examples in the product flow.
- Add real local `createState` / `createInteraction` behavior for the required flow. Keep draft filters separate from applied filters. Label simulated processing in the plan; do not imply that business APIs are connected.
- For PC requirements, create routed Pages and at most one named overview Arena containing references to those Pages. Do not create a separate Arena per page or leave capability-test pages/canvases in the deliverable. Read `devicePresets` and use Studio’s `Desktop` preset by default; an explicit user viewport overrides this default. Use `setPageViewport` for one Desktop column across Page previews, and matching `createArtboard` / `updateArtboard` dimensions in the overview. PC-only work must not add mobile/tablet frames, breakpoints or responsive overrides. Clean obsolete test canvases with `deleteCanvas`; preserve page UUIDs and interactions. For a fixed viewport, bound the root height and let the AppShell content region own vertical scrolling. Tables grow naturally; do not set an internal Table body height unless explicitly required. See ../admin-design.md for scroll-owner acceptance.

## Acceptance

Check delivered node names against actual component identities, content and interactions using [editor node naming](../admin-design.md#editor-node-naming). Inspect the editor tree/selection label and persisted readback after save/reopen; model validity alone does not establish meaningful naming.

For regeneration or requested stability testing, read [../reproducibility.md](../reproducibility.md). Establish source and acceptance inputs before building, generate fresh editable pages, and rerun generation after updating rules that caused a failure. Previous accepted model exports are comparison evidence, not generation input.

For visual acceptance, record the screenshot's page identity and viewport, inspected regions, concrete observations and pass/fail conclusions. A list of captured files is not a visual analysis. Review changed detail headers using [admin-design.md](../admin-design.md#detail-header-review); keep model checks and screenshot review as separate evidence.

For any Table change, apply the column-width and content checks in [admin-design.md](../admin-design.md#table-column-widths), including actual overflow Tooltip interaction, editable template bindings, measured operation width and save/reopen column evidence.

For generated or changed query regions, apply [SearchForm acceptance](../admin-design.md#searchform-acceptance) to each Page/Tab instance: effective grid, label/punctuation fit, control space and business-toolbar alignment, with separate visual and interaction outcomes. A checked default Tab or working query/reset cannot pass unvisited filter regions.

For operation feedback and confirmations, apply [feedback and row confirmation](../admin-design.md#feedback-and-row-confirmation): short Message for ordinary completion, anchored Popconfirm for simple row confirmation, and real cancel/confirm/dismissal and geometry checks.

For component wrapper/default changes, apply [component behavior contracts](../admin-design.md#component-behavior-contracts), including explicit overrides, state bindings, validation/save failures and event timing. Use the same installed Ant Design version in the behavior tests; verify affected flows in the local App too.

For same-sized artboards in one overview, pass `artboardElementUuid` (a unique business-body element from `read`) to `get_screenshot` to select the intended whole page; width alone can match a different page. Wait for that element to appear in `snapshot_layout` after navigation. Review every screen with `get_screenshot` and `snapshot_layout`, including meaningful tabs, overlays, filters, permission gates and long values. Exercise real preview interactions, not only definitions. `validate` checks model integrity, not visual quality. Fix issues via MCP and recheck changed screens.

For offscreen editable content, use `execute` → `scrollElementIntoView` with componentUuid/elementUuid from `read`; frameUuid selects an artboard and instanceIndex selects a repeated rendering. Navigate first and wait for rendering. Check returned visible/bounds and a workspace screenshot; static artboard screenshots use a separate rendering. Positioning preserves selection, editor mode and model properties. Hidden/unrendered targets fail; visible=false means ancestor clipping still prevents visibility. Restore any editor mode temporarily changed during acceptance.

Call `save`, record revision, reopen the project, then `read` to confirm persisted elements, props, states and interactions. Inspect screenshots again after reopen. Keep a sanitized MCP transcript and an evidence report linking sources, screenshots, actual checks, and unresolved limits. Never report acceptance from a successful save alone. Do not publish a release without user authorization.
