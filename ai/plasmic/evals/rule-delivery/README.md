# Rule delivery and verification probes

Use [cases.json](cases.json) with isolated baseline/candidate skill and resource snapshots. These are offline decision probes: all model, width and permission facts are synthetic. Do not modify an editor or treat a proposed action as executed. Give each agent only its snapshot, the returned must-read list and the cases; exclude this rubric and previous results.

Grade decisions against these expectations:

| Case | Required decision |
| --- | --- |
| new-page | Prepare current rules and decisions before composition; the snapshot version's full-width column rule with rendered density verification; use native title Slot. |
| local-spacing | Apply only the affected layout change, reuse scoped evidence and avoid full-Page planning. |
| matching-bad-plan | Reject design acceptance from consistency/validate/save; correct the known full-width column choice and native heading ownership. |
| legitimate-untitled | Preserve half-width two columns, Card-owned heading and legitimate help; keep runtime evidence pending. |
| matching-invalid-values | Reject zero column, oversized span and boolean span even when the plan matches. |
| one-long-value | Longest-value measurement does not justify a single-column group of mostly short facts; use Item span. |
| incomplete-reading | Run delivered reader commands, resolve decisions and complete selection preflight/Design review before writes; plan-only is insufficient. |

Also compare both verifier versions against identical synthetic invalid and valid inputs. Keep Agent decisions separate from actual verifier behavior. Retain source/output hashes, grading and unavailable metrics. A single paired batch shares case context within each variant and does not establish general reliability or a live Desktop acceptance result.
