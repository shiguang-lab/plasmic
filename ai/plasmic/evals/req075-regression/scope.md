# REQ075 optimized-version acceptance scope

Source: REQ_海外客群管理平台.md v1.36, sections 2.5, 3.1–3.6, 5.1–5.8, 6.1–6.5, 6.7–6.9 and 7.2–7.7. The source is in the user's REQ075 P0 requirement directory. P1/P2 dimension selection, AI, observation, portraits and export-audit UI remain outside this P0 prototype scope. Business APIs, scheduler, confplus and IAM are represented by the existing prototype simulation, not tested production integrations.

## Required outcomes

- Four routes only: groups, regular, onetime, detail. Sidebar exposes list and SQL selector for all three roles; creation/detail remain child flows. Repeated role changes preserve current role across navigation.
- List: independent draft/applied filters, market isolation, scenario/type/status/keyword, All/Mine, default 20 and 50/100 pagination, empty result, reset, long-value Tooltip, preserved return query/page/scroll. Three visible row actions maximum; overflow preserves authorized actions.
- Role/state matrix: all roles view; administrator/operations create, metadata edit and copy in every state; SQL editing only never-active initialized/selection-failed; delete only initialized; disable/export only administrator; read-only never executes. Cancel confirmations preserve records; accepted actions produce required simulated transitions. No version/verification UI.
- Both SQL flows: formatting; reject non-SELECT, DDL/DML/dangerous functions, non-dwt/cdm tables, missing uid/app_source and wrong/missing App predicate; one-time also rejects variables. Editing invalidates validation/preflight. Submit starts running → success/failure, no progress bar; success shows total plus Top100 masked full-field samples. Failure remains recoverable. Only successful preflight enables save/launch; launch returns to list with selecting state/record.
- Regular metadata: editable name/key/owner/scenario; retention defaults to 3 and supports 3/7/30/60/180/long-term; retention help explains irreversible partition cleanup and next-refresh effect; deadline includes seconds and immediate effect. One-time metadata modal supplies name/key/owner/scenario, locked type and entrance App; page does not repeat name input; expiry 14, maximum 365.
- Detail: default Overview; Basic, Overview, Members, Selection and Application tabs, plus regular-only Refresh; no P1 Observation. Basic information is two columns; regular storage table/retention/partition/deadline; one-time validity and no regular storage. Long identifiers remain readable, legitimate zero is preserved. Members are masked full pagination, not Top100; initialized/first selecting have no historical members. Read-only SQL closes/reopens. Records show required fields/filtering; drawer shows parameters/response/failure; application allows only ACTIVE and authorized roles, native required-field validation and busy protection.
- Overlays: native ownership, functional close/cancel, recoverable input, hidden initial state, no sole dismiss footer duplicating a usable X. Verify preflight running/success/failure and application busy/success/failure separately.
- Every page: 1440×1024 and 1440×720 actual Preview, header/sidebar stable, bottom content and actions reachable, no clipping/overlap or nested native scrolling. Hidden tabs/overlays checked at short height.
- Persist: explicit save receipt, reopen/new editor session, full models/bindings/initial overlay state unchanged; rerun all six structural gates, four shell-height checks and required interactions after reopen.
- Optimization: live scoped discovery preserves exact contracts; batch ordered receipts reconstruct complete models; single undo restores exact model; model evidence reuse refreshes layout and reruns every gate; changed session invalidates reuse.

## Evidence rules

Expected fields and behavior come from this source review. Existing pre-generation intent files may be reconciled to later explicit naming/Form/Descriptions migrations with a recorded semantic mapping; actual model output must not be copied wholesale into expected intent. Unsupported dynamic expressions keep their static checker diagnostic and require separate state-specific runtime evidence; an unresolved diagnostic is never silently converted to a pass. Every remaining failed or unexercised case must stay visible in the final report.
