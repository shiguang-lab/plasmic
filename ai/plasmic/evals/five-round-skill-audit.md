# Plasmic skill 五轮审查

日期：2026-10-26。范围：仓库中的 Skill 入口、规则路由、设计规范、计划辅助工具、验收脚本和 MCP 引导。修复均在本地源码中；未发布、安装或修改业务设计项目。

## 发现与修复

| 轮次 | 问题及影响 | 修复 |
| --- | --- | --- |
| 1：入口与规则路由 | 类别列缺少 Tag/纯文本选型规则；用户明确要求的详情头未进入必读规则；Antd 5 的表单语义角色被 Antd 6 身份限制误拦截；局部修改的流程范围不清楚。 | 补充条件路由，按实际库限定注册身份检查，明确完整后台套件与局部/其他库检查范围。 |
| 2：设计一致性 | 分组表单与全局单 Row 要求冲突；需求明确的 Tabs 共享 Table 与每个 Tab 必须拥有 Table 冲突；Card 动作标题示例与优先级规则矛盾。表单骨架还会把已声明的 NameCol 改为 NameCol2，并丢失标签名称和控件选项 Slot。 | 统一每组一 Row、同一 Form 提交；同步 Tabs、组合、模板与目录的共享 Table 条件；收紧 Card 示例。骨架保留声明的列、文案节点和控件子树，拒绝计划与字段清单的 span 漂移。 |
| 3：验收可信度 | 编辑器状态不变时，修改需求计划或规范仍可能复用旧审查；保存比较把 data-record-id 当生成 ID 忽略；两个空白详情页可仅凭否定文本断言通过记录解析检查。 | 审查绑定完整计划摘要和逐规范摘要；仅规范化标签中的独立 id 属性；不同记录必须具有不同正向业务文本证据，否定场景仍可作为补充。 |
| 4：客户端执行 | 原型流程强制 Unix 本地 RPC 预检，遗漏已有原生 MCP 状态输入路径；MCP 引导只检查共享 Skill 目录，可能忽略独立客户端目录的本地源。 | 引导原生 MCP 状态导出与 --state 校验，提前说明完整套件实时采集范围。read_skill 接受当前客户端的绝对 skillPath，显式路径或本地源损坏时失败，不转到发布源。 |
| 5：修复复核与回归 | 新递归骨架把计划中表示“不设置”的 null 写入控件、Row、Col。 | 统一剔除顶层未设置属性，保留有效 false、0；复核前四轮修复，没有发现其他可复现的较大问题。 |

## 证据边界

这些结果证明所审查的规则入口、脚本约束、客户端配置和分发行为通过了相应测试，不能证明所有模型都会正确理解并执行规范。本轮没有运行新的真实模型设计生成、视觉验收、Preview 或保存重开评测。

完整套件的实时采集仍要求本地 macOS/Linux Desktop RPC；Windows 或仅远程 MCP 的客户端可检查已有完整证据，但不得把证据回放称为本轮实时验收。独立子代理与压缩能力也不能假设所有客户端都具备。

后续真实模型评测继续采用 [evals 的执行与评分规则](README.md)，分别记录模型/客户端版本、实际规范读取、生成结果、运行行为与未验证项。
