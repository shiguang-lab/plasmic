# Codegen contract probes

Use [cases.json](cases.json) to evaluate component-contract preservation without prescribing a component library in the codegen rules. The packages and APIs are synthetic fixture contracts. These probes test decisions and proposed source changes after contract acquisition; they do not test MCP discovery, compilation, live behavior or visual fidelity.

The [contract-rule run](results.md) reports baseline/candidate evidence and validation limits. The [post-implementation review runs](review-results.md) cover independent review, fallback, a scoped repair/review cycle and separate direction assignments.

Run the same cases in fresh agent contexts with the baseline and candidate versions of `model-reading.md`, `workflows/codegen.md`, `codegen/project-code.md`, `codegen/interactions.md` and `codegen/acceptance.md`, plus `codegen/review.md` for versions that provide it. Give executors only those references and `cases.json`, not this rubric or prior conclusions. Restrict work to the supplied evidence and an isolated output directory; do not contact live applications, resolve a different published resource version or edit the business repository. Preserve one response per case, including proposed JSX and evidence limits. Compare actual outputs against the criteria below; an executor's own passing claim is not a grade.

| Case | Required result | Counterexample to reject |
| --- | --- | --- |
| source-capabilities | Repair the actual OrdersSurface inside OrdersPanel using Panel's heading/actions/contentStyle and children, retain the action binding, and use Stack's column/16 layout. Keep the unrelated help surface and native ticket content. Identify obsolete styles for removal only if no other consumers remain. Report source consistency separately from blocked runtime/visual checks. | Passing because Panel is imported or used for help; leaving the hand-built OrdersPanel; wrapping native ticket artwork in another surface; claiming 403 prevents source inspection. |
| verified-adaptation | Accept the verified AppFrame-to-host, pane-to-items and launcher-to-adjacent-action conversions. Follow AccountTabs through to TabSet and confirm the controlled selection/open/close bindings. No structural rewrite is required; report runtime/visual checks as unverified. | Installing the design library, adding another app shell, copying nonexistent launcher props, requiring identical JSX/names, or rejecting the ordinary help text. |
| unknown-target-contract | Preserve the known native content and identify the unknown target export/props/events as the blocker for the picker. Keep the source search/selection requirements explicit; do not claim that the target lacks the capability or that the feature is implemented. | Inventing target APIs, treating unread contracts as a verified gap, or replacing the picker with custom controls that drop search/pagination/selection behavior. |
| interaction-and-evidence | Follow event arguments through AccountTabs to state: selection writes the old key and dismiss sets open to true. Report both source-backed defects and distinguish unverified build claims from observed evidence. | Approving because components and prop names match, trusting the implementation report, or claiming runtime behavior was exercised. |

For post-implementation review probes, assign review only: inspect fixtures and report findings without changing inputs or proposing a new design. Use separate fresh-context reviewers for the applicable design-fidelity, behavior-correctness and engineering-quality directions. Keep source evidence shared and code stable; the parent owns deduplication, cross-direction assignments and conflicting findings. Record any justified scope merger; limited concurrency should use sequential reviewers, not silently merge directions. Separately test fallback under an explicit no-delegation task restriction, reviewing each direction in the current context and reporting the actual reason. Check that coverage and missing runtime/visual evidence survive both modes. These probes do not establish a repair/review loop until changed code is actually supplied and re-reviewed by the affected directions.

Record failures and justified deviations, not keyword counts. Review the exact rendered region, slot/content ownership and state/event flow in the proposed source. Equivalent implementations satisfying the supplied contracts are valid. A single successful probe run establishes bounded evidence only; it does not demonstrate a reliable improvement over the baseline or full codegen acceptance.
