# Published HTML hydration regression

`node scripts/build-studio.mjs` rebuilds the local loader-react SDK dependency graph and the HTML hydration bundle before Studio. Both the HTML generation server and browser hydrater link `packages/loader-react`. The hydration build records its actual source/configuration inputs and output hashes, verifies local Host/SDK source maps, removes obsolete ignored public copies, and rejects legacy Preview consumers. Studio copies the canonical scripts without re-minifying them; server, Studio and Desktop serve identical bytes.

The self-hosted published HTML carries its public loader API address separately from the internal SSR origin. Cached HTML without that attribute derives the service base, including a path prefix, from the classic hydration script. Existing hydrater instances and mounted roots are reused. The stable script URL redirects with a 60-second cache duration to the single versioned sibling script. A matching version gets the existing one-year resource cache duration; unknown versions return 404 and never silently serve latest. Missing or multiple versioned build outputs fail.

After preparing matching Desktop assets, run `pnpm test:published-hydration` from `platform/wab`. This tool is also mandatory in `pnpm test:preview-probe`, alongside all six existing tools. The tool checks input/output provenance and exact script-byte equality before starting loopback-only servers. Every engine and case must pass; no engine or fidelity assertion is optional.

The fixture uses the actual production `bundleModules`, `genLoaderHtmlBundle`, local SDK and compiled hydration script. Its synthetic page imports the real local AntdButton implementation. The cases cover Chromium, Firefox and WebKit; light/dark global variants; SSR-only output; embedded data, pinned remote data and cached HTML; shared Host data context and style tokens; SSR node identity; repeated hydration/state retention; form validation, submission/disabled states, overlay open/close, links, assets and resource caching. The page is a publishing contract fixture, not a substitute for the separate full REQ075 native Preview and design acceptance.

Put the fixed historical hydration script in the probe fixture directory (`PLASMIC_PROBE_FIXTURES`, default `/tmp/plasmic-cover-probe`) as `hydration-baseline.js`, with a `hydration-baseline.json` containing `sdk: "2.0.23"` and SHA-256 `53b75d8e09e2fc62db3dcf35d928068098cf92d52e4f0c98ff8be8a9c6a0a053`. Both the bytes and pinned hash are checked. This is the archived pre-migration registry SDK input, not an alternative production renderer. Only the historical visual-control packet includes the original React DOM client module required by the current Antd implementation. All current published cases omit that module and require the new SDK builtin; its independent jsdom counterexample also has neither a downloaded module nor Node require fallback, so the historical packet cannot mask the missing-builtin defect.

Each current case is compared with the historical runtime on the same page, theme and browser, using the original threshold: fewer than 1% of pixels may differ by more than 20 in any RGB channel. Raw metrics and uniquely named PNGs are saved before assertions. Browser console errors, missing assets and unexpected external requests fail acceptance. The full production SDK deployment closure must also be validated independently from the development node_modules tree.


Both server Dockerfiles use the repository root as their build context and CI lockfile enforcement. Their setup builds the local SDK/hydration before Sub consumes Host. The production image receives the deployed SDK dependency closure at the same path as the platform link, rather than a development node_modules symlink. Build with `docker build --target server -f deploy/Dockerfile .` or `docker build -f platform/wab/Dockerfile .`. A local intercepting proxy may require its already trusted CA as `--secret id=build-ca,src=/path/to/trusted-ca.pem`. This optional input is mounted only during dependency operations, is not copied into the release image, and never disables TLS verification. The existing optional `npmrc` secret supplies private registry configuration.

The deployment helper repairs pnpm's generated SDK self-reference before relocation and rejects every broken or external dependency link. Both Dockerfiles use persistent pnpm store and metadata caches while retaining frozen lockfiles, TLS and supply-chain verification. The isolated release check relocates this closure and renders with its own production dependencies after removing the producer.

Cover rasterization waits for a complete paint cycle after SVG decode, including foreignObject text masks. Browser acceptance retains the existing whole-image pixel threshold and additionally checks that the gradient heading retains its visible text pixels. SSR-only acceptance compares exact rendered text content, including context and retained business content, independently of React's HTML comment separators.
