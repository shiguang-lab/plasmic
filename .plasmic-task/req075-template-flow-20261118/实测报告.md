# 海外 O 端模板参考流程实测

2026-11-18 在本地 Plasmic Desktop 0.9.3 使用真实需求 REQ075「海外客群管理平台」§6.2 和 §6.3，验证列表归属切换及 SQL 编辑校验两个模块。业务项目「客群管理 · 模板流程实测」的 ID 为 `qEkBAnKZp5atGRf27r892m`。项目已保存至 revision 8。使用的是已安装 Desktop 的公开本地 RPC。

## 从业务画布往返模板

1. 在个人空间创建业务项目并打开，确认可编辑。
2. 使用 `open_template` 打开模板中心「海外 O 端」4.0.0，确认画布只读。从本次发布读取 17 个页面的名称、场景和结构描述，从中选出 5 个候选，导航到画板分别读取组件树和截图。
3. 列表选「筛选与分范围列表」的公共筛选区、范围标签和各自的表格。另一个候选「分范围表格」缺少公共筛选区。按需求换成客群字段、当前负责人和业务记录。SQL 模块比较了基础表单、分组表单和分步表单，均缺少 SQL 编辑、修改后结果失效以及逐项校验反馈。三个候选仍可参考通用表单外观。
4. 以起点的业务项目 ID 调用 `open_design`，核对 ID 与编辑权限。使用 Overseas 3.2.0 与 Ant Design 6 5.7.0 在业务项目创建客群列表和 SQL 圈选两个页面。保存后切走，再打开业务项目，新编辑会话读回同一 revision，重新打开 Preview 测试。业务项目登记的直接依赖只有两个组件库。

## 流程质量

- 页面描述足以缩小候选范围。近似页面须比较它实际拥有的区域，以及筛选和表格之间的位置关系。本例从 17 页缩到两个列表候选，再用截图和结构确定主参考。
- 空匹配路径可用。现有模板检查器对空匹配仅检查理由非空，裁定是否合理还依赖候选的模型和截图。记录最接近的候选以及缺少的交互，能复核判断，也允许其他区域继续使用合适的模板。
- 批量采集时出现一次按 componentUuid 截图调用未返回有效响应、模板窗口停止响应。重启本地 App，先导航到候选并使用当前 frameUuid 截图后恢复。已有接口可以走通；直接采集多页的稳定性仍值得单独复测，根因未定位。
- 首次列表预览出现空表。按 Table 契约将行数组包装为 data.data 后，在真实 Preview 验证交叉负责人样本。单看编辑成功、保存成功或页面外形都会漏掉这类绑定问题。
- 截图复核发现一个本地化问题：列表分页显示英文 `20 / page`，空结果也显示 `No data`。
- 本次是模块级流程评估。取得了候选截图、实时组件树、业务保存回读和交互断言，未运行完整产品原型的所有静态交付检查。一个真实需求只能证明两条路径在本例成立，无法据此估计其他需求的选型准确率。
